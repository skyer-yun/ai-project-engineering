# 需求收集与分析工作流（N1-N2）

## 概述

本工作流覆盖 N1（需求收集）到 N2（需求分析）阶段，将客户原始需求转化为结构化的需求分析报告。

## 工作流步骤

### Step 1：需求收集

**输入**：
- 客户原始需求材料（会议纪要、邮件、聊天记录、招标文件等）
- 客户背景信息（行业、规模、现有系统）
- 项目约束（预算范围、时间要求、技术限制）

**处理**：
1. 接收并整理客户原始材料
2. 提取关键需求条目
3. 识别业务目标和核心痛点
4. 标注信息不完整的需求项

**输出**：
- 初步需求清单（条目化）
- 信息缺失清单（需向客户确认的问题）

**人工参与**：
- 确认需求理解是否准确
- 补充缺失的客户背景信息
- 确认需求优先级初步排序

### Step 2：需求分析与结构化

**输入**：
- Step 1 输出的初步需求清单
- 补充确认的客户信息

**处理**：
1. 将需求按功能/非功能/约束分类
2. 识别需求间的依赖关系
3. 检测需求冲突和矛盾
4. 分析业务流程和数据流向
5. 评估技术可行性

**输出**：
- 结构化需求清单（含分类、优先级、依赖关系）
- 需求冲突清单（含建议解决方案）
- 技术可行性评估

### Step 3：竞品调研（可选）

**触发条件**：
- 用户明确要求竞品分析
- 涉及产品选型的场景
- 需要了解行业最佳实践

**处理**：
1. 确定竞品范围（用户指定或根据行业推荐）
2. 使用 web-access 搜索竞品信息
3. 按 5 维度对比矩阵进行分析
4. 生成 SWOT 分析

**输出**：
- 竞品分析报告（含对比矩阵 + SWOT）
- 差异化建议

**依赖**：
- web-access（核心，缺失则使用本地知识库）

### Step 4：需求分析报告生成

**输入**：
- Step 2 的结构化需求
- Step 3 的竞品分析（如有）

**处理**：
1. 按标准报告结构组织内容
2. 生成需求分析报告
3. 标注风险项和建议
4. 标记交接就绪状态

**输出**：
- 需求分析报告（.docx 或 .md）

### 报告结构

```
1. 项目背景
   1.1 客户概况
   1.2 项目目标
   1.3 业务现状
2. 需求概述
   2.1 功能需求清单
   2.2 非功能需求
   2.3 约束条件
3. 需求详细分析
   3.1 业务流程分析
   3.2 数据流向分析
   3.3 用户角色分析
   3.4 接口需求分析
4. 需求优先级
   4.1 优先级矩阵（紧急/重要）
   4.2 分期建议
5. 技术可行性评估
   5.1 技术方案概要
   5.2 风险识别
   5.3 建议与对策
6. 竞品分析（可选）
   6.1 竞品概览
   6.2 对比矩阵
   6.3 SWOT 分析
   6.4 差异化建议
7. 附录
   7.1 需求追溯矩阵
   7.2 术语表
```

## 产物清单

| 产物 | 格式 | 必选/可选 | 说明 |
|------|------|----------|------|
| 需求分析报告 | .docx / .md | 必选 | 完整的需求分析文档 |
| 竞品分析报告 | .docx / .md | 可选 | 5 维度对比 + SWOT |
| 需求追溯矩阵 | .xlsx / .md | 可选 | 需求→功能→测试追溯 |

## 交接标准

需求分析报告完成后，检查以下条件：

- [ ] 所有功能需求已条目化
- [ ] 需求无二义性（可被产品经理理解）
- [ ] 业务目标可量化
- [ ] 干系人已确认（或标注待确认）
- [ ] 技术风险已识别

满足后提示用户交接给 product-copilot 启动 PRD 编写。

## 回退与异常

| 异常 | 处理 |
|------|------|
| 客户信息严重不足 | 列出必填信息清单，请求补充后再继续 |
| 需求矛盾无法调和 | 标注矛盾点 + 给出 2-3 种解决方案 + 请求决策 |
| 竞品信息无法获取 | 跳过竞品分析，标注"待补充" |
| 行业不熟悉 | 加载 knowledge/industry-solutions/ + 联网搜索 |
