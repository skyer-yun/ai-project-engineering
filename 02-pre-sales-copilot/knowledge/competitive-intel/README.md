# 竞品情报分析框架

## 概述

本目录定义竞品分析的标准框架和方法论，供 requirement-workflow 的竞品分支使用。

## 5 维度对比矩阵

### 权重分配

| 维度 | 权重 | 说明 |
|------|------|------|
| 功能 | 30% | 功能覆盖度、功能深度、特色功能 |
| 技术 | 20% | 技术架构、技术先进性、扩展性 |
| 价格 | 25% | 产品定价、实施费用、运维成本 |
| 服务 | 15% | 实施能力、售后响应、培训支持 |
| 口碑 | 10% | 客户评价、市场份额、行业认可 |

### 功能维度（30%）

| 评估项 | 评分标准 |
|--------|----------|
| 核心功能覆盖度 | 需求覆盖率：100%=10分, 80%=8分, 60%=6分 |
| 功能深度 | 标准功能深度 vs 差异化功能 |
| 特色功能 | 独有功能加分 |
| 可配置性 | 功能可配置/可定制程度 |
| 移动端支持 | 移动端功能完整度 |

### 技术维度（20%）

| 评估项 | 评分标准 |
|--------|----------|
| 技术架构 | 微服务/单体、云原生支持 |
| 技术先进性 | 当前主流 vs 过时技术 |
| 扩展性 | API 开放度、插件机制 |
| 安全性 | 安全认证、数据加密 |
| 性能 | 并发能力、响应时间 |

### 价格维度（25%）

| 评估项 | 评分标准 |
|--------|----------|
| 产品授权费 | 按用户/按模块/买断 |
| 实施费用 | 标准实施 vs 定制开发 |
| 运维成本 | 年度维保、云资源费用 |
| 总拥有成本（TCO） | 3年/5年 TCO 对比 |
| 付款条件 | 付款节点、质保金 |

### 服务维度（15%）

| 评估项 | 评分标准 |
|--------|----------|
| 实施团队 | 团队规模、行业经验 |
| 响应速度 | SLA 响应时间 |
| 培训支持 | 培训方式、培训内容 |
| 本地化服务 | 本地团队 vs 远程支持 |
| 升级维护 | 版本更新频率、升级成本 |

### 口碑维度（10%）

| 评估项 | 评分标准 |
|--------|----------|
| 客户评价 | 同行业客户满意度 |
| 市场份额 | 行业排名、装机量 |
| 行业认可 | 获奖、认证、资质 |
| 生态体系 | 合作伙伴、开发者社区 |
| 发展潜力 | 公司规模、融资、趋势 |

## SWOT 分析模板

```
          | 优势 (Strengths)  | 劣势 (Weaknesses)
----------|-------------------|-------------------
内部因素  | - {优势1}         | - {劣势1}
          | - {优势2}         | - {劣势2}
          | - {优势3}         | - {劣势3}

          | 机会 (Opportunities) | 威胁 (Threats)
----------|----------------------|----------------
外部因素  | - {机会1}            | - {威胁1}
          | - {机会2}            | - {威胁2}
          | - {机会3}            | - {威胁3}
```

### 分析要点

- 优势：相对竞品的差异化能力
- 劣势：需要改进或规避的短板
- 机会：行业趋势、政策红利、客户需求变化
- 威胁：竞品动态、技术替代、政策风险

## 采集渠道

### 一手渠道

| 渠道 | 方式 | 可靠度 |
|------|------|--------|
| 竞品官网 | 功能介绍、产品手册、案例 | 中 |
| 竞品演示 | 申请产品演示、试用 | 高 |
| 行业展会 | 现场体验、获取资料 | 中 |
| 客户反馈 | 已使用竞品的客户评价 | 高 |

### 二手渠道

| 渠道 | 方式 | 可靠度 |
|------|------|--------|
| 行业报告 | 艾瑞/IDC/Gartner 报告 | 高 |
| 技术社区 | CSDN/知乎/掘金评测 | 中 |
| 招标信息 | 中国政府采购网/企查查 | 高 |
| 社交媒体 | 微信公众号/微博/抖音 | 低 |
| 专利数据库 | 专利检索分析 | 中 |

### 采集注意事项

1. 标注信息来源和采集时间
2. 交叉验证关键数据
3. 区分事实和观点
4. 定期更新（建议季度更新）
5. 敏感信息不外泄

## 竞品分析报告结构

```
1. 分析背景
   1.1 分析目的
   1.2 竞品选择说明
2. 竞品概览
   2.1 各竞品基本信息
   2.2 市场定位对比
3. 功能对比
   3.1 功能覆盖度矩阵
   3.2 核心功能详细对比
   3.3 特色功能分析
4. 技术对比
   4.1 技术架构对比
   4.2 技术栈对比
   4.3 扩展性对比
5. 价格对比
   5.1 定价模式对比
   5.2 TCO 分析
6. 服务对比
   6.1 实施能力对比
   6.2 售后服务对比
7. 综合评估
   7.1 5 维度评分表
   7.2 SWOT 分析
   7.3 竞争策略建议
8. 附录
   8.1 数据来源说明
   8.2 评分明细
```

## 使用方式

1. requirement-workflow 的竞品分支触发时加载本框架
2. 确定竞品范围后使用 web-access 搜索信息
3. 按 5 维度矩阵逐项评分
4. 生成 SWOT 分析
5. 输出竞品分析报告

## 扩展

- 新增竞品数据可直接在本目录创建 `data/{竞品名}.md`
- 定期更新评分数据
- 积累行业对标数据形成基准
