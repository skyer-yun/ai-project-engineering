> **定位**：本文件是「工件版本树」「演化规则」「工件类型注册表」的**唯一权威源**。
>
> **关联**：Checkpoint 协议见 [04-工具层/03-Checkpoint脚本/](../04-工具层/03-Checkpoint脚本/)；交接契约见 [04-阶段交接契约Schema.md](./04-阶段交接契约Schema.md)。

## 一、为什么需要"工件演化层"

工件是项目过程的具象产物（需求文档/设计文档/代码/测试报告等）。如果只做"交接"（PRD 给研发后无演化追踪），会导致：

- PRD 从 v1 到 v5 的迭代轨迹丢失，无法回溯
- 跨阶段交接后，工件状态在上下游不同步
- 改动原因被遗忘（评审反馈？客户变更？回溯修正？）

本体系要求每个工件维护一棵版本树（不只是线性版本号），让每次演化可追溯。

---

## 二、工件版本树结构

```
PRD-v1 (S 阶段初稿)
  ├── PRD-v1.1 (评审反馈调整)
  │     └── PRD-v1.2 (用户验证调整)
  │           └── PRD-v2.0 (B 阶段架构反馈大改，分支合并)
  └── PRD-v1-archived (废弃分支，保留可追溯)

每个版本节点记录：
  - 版本号（语义化：major.minor）
  - 创建时间 / 创建者（角色名 + 工具，工具中立）
  - 触发原因（评审/反馈/变更/回溯）
  - diff（与上一版的差异）
  - 交接契约引用（哪个阶段第几轮产出）
```

---

## 三、工件演化规则（minor / major / archive）

| 触发场景 | 演化动作 | 示例 |
|---------|---------|------|
| 评审反馈 | minor +1 | v1.0 → v1.1（评审调整） |
| 跨阶段调整（如 B 反推 PRD） | 走变更评审，major +1 | v1.x → v2.0 |
| 客户变更 | major +1 + 变更日志强制 | v1 → v2 |
| 回溯修正 | minor +1 + 标注回溯来源 | v2.0 → v2.1（来自 QG-S 回溯） |
| 废弃分支 | archive 标记，**不删除** | v1-archived |

**铁律**：
- minor 改细节、major 改方向、archive 不删
- 任何 major 必须有变更日志（diff + 原因）
- 任何回溯修正必须标注来源（哪个 QG / 哪个阶段）

## 五、diff 模板（版本间差异记录）

每次工件演化必须产出 diff 记录：

```yaml
artifact_diff:
  artifact: PRD
  from_version: v1.2
  to_version: v2.0
  trigger: cross_stage_adjustment   # 评审/反馈/变更/回溯/跨阶段调整
  trigger_source: B 阶段架构反馈
  changes:
    - section: "Part 7 功能点"
      type: major_change            # new / minor_change / major_change / removed
      summary: "认证模块从 session 改为 JWT"
      impact: ["S 架构", "S 详设", "B 编码"]
  handoff_ref:                      # 引用交接契约（详见 04-阶段交接契约Schema.md）
    from_stage: S
    to_stage: B
    iteration: 3
    triggered_by: Builder           # 角色名，工具中立
  review_required: true             # 是否需要评审
  signed_by: ["Spec-Writer", "Builder"]
```

## 六、工件演化与 Checkpoint 的关系

每次工件演化对应一次 Checkpoint（详见 [04-工具层/03-Checkpoint脚本/](../04-工具层/03-Checkpoint脚本/)）：

| 工件演化动作 | 对应 Checkpoint 类型 |
|------------|------------------|
| Git commit（代码） | git_commit |
| 文档版本号变更 | doc_version |
| 部署前快照 | deploy_snapshot |
| 测试基线变更 | test_baseline |
| 任意工件 diff | artifact_diff |

---

## 七、工件演化与交接契约的关系

每次演化在工件上记录交接契约引用（详见 [04-阶段交接契约Schema.md](./04-阶段交接契约Schema.md)）。下游读取工件时，先校验引用的契约：

| 检查项 | 通过条件 | 不通过处理 |
|--------|---------|-----------|
| 上游 Exit 是否达标 | exit_met = true | 拒绝接收 + 通知 Keeper |
| Eval 分数是否过硬 | 高于阈值 | 提示人工确认 |
| 循环次数是否异常 | ≤ 5 | 标记风险 + 调查根因 |
| Reflect 是否通过 | reflect_passed = true | 拒绝接收 |
