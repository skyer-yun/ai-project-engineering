# 质量门禁 QG-D 至 QG-Ship

> **定位**：本文件是「阶段出口质量门禁 checklist」的**唯一权威源**。DSBL 每阶段 Exit 前必须跑对应 QG，全绿才签交接契约。
>
> **关联**：阶段定义见 [01-DSBL五阶段定义.md](./01-DSBL五阶段定义.md)；硬指标阈值见 [06-产物质量硬指标库.md](./06-产物质量硬指标库.md)。

---

## 一、QG 总览

| 门禁 | 阶段 | 谁审 | 通过则 | 不通过则 |
|------|------|------|--------|---------|
| **QG-D** | D-Discover | 客户代表 + Spec-Writer + Keeper | 进 S | 回 D Loop / 升级 |
| **QG-S** | S-Spec | Spec-Writer + Builder + Reviewer | 进 B | 回 S Loop / 升级 |
| **QG-B** | B-Build | Builder + Reviewer | 进 Ship | 回 B Loop / 升级 |
| **QG-Ship** | S-Ship | Shipper + Reviewer + **客户** | 项目交付 → 进 L | 回 Ship Loop / 升级 |

**核心原则**：
- QG 是"门"不是"评分"——通过/不通过，二元判定。
- 任一项 🔴 则整门禁不通过，禁止进下一阶段。
- 🟡 是警戒项，需记录但不阻塞。

## 二、QG-D：需求→规范前置门禁

**触发时机**：D-Discover Exit 前。
**主审**：Spec-Writer（主）+ 客户代表（必签）+ Keeper。

### Checklist

| # | 检查项 | 类别 | 通过标准 |
|---|--------|------|---------|
| 1 | 需求 5 维完整性 | 🔴 | 业务/角色/场景/约束/优先级 全部明确，无 TBD |
| 2 | 干系人清单签署 | 🔴 | 所有关键干系人签字（含反对意见已记录） |
| 3 | 业务场景闭环 | 🔴 | 核心场景端到端走通（输入→处理→输出→验收） |
| 4 | 约束清单（合规/预算/时间/技术） | 🔴 | 4 类约束逐条标注 |
| 5 | 优先级矩阵 | 🟡 | MoSCoW 或 KANO 标注完成 |
| 6 | 风险登记 | 🟡 | 已识别风险进入风险登记册 |
| 7 | Loop 次数 ≤5 | 🔴 | D 阶段 Loop 不超过 5 次 |
| 8 | Reflect 签名齐全 | 🔴 | Spec-Writer + 客户代表 + Keeper 签字 |

- [需求分析报告](../02-产物层/D-Discover/需求分析报告模板.md) v1.0+

## 四、QG-B：编码→交付前置门禁

**触发时机**：B-Build Exit 前。
**主审**：Builder（主）+ Reviewer（必签）。

### Checklist

| # | 检查项 | 类别 | 通过标准 |
|---|--------|------|---------|
| 1 | 单测覆盖率 | 🔴 | 行覆盖 ≥80% / 分支覆盖 ≥70%（详见 [06-产物质量硬指标库.md](./06-产物质量硬指标库.md)） |
| 2 | Lint 严重问题 | 🔴 | 严重级 = 0 |
| 3 | 类型检查 | 🔴 | TypeScript/强类型语言零类型错误 |
| 4 | 代码审查通过 | 🔴 | Reviewer 在 PR 签字，无未解决 🔴 意见 |
| 5 | 联调集成通过 | 🔴 | 前后端/E2E 关键路径走通 |
| 6 | 接口契约一致性 | 🔴 | 实现与 S 阶段契约一致 |
| 7 | 性能基线 | 🟡 | 关键场景性能达约定基线 |
| 8 | 安全扫描 | 🟡 | 无 Critical/High 漏洞（或已确认接受） |
| 9 | 文档同步 | 🟡 | README / 接口文档 / 部署文档更新 |
| 10 | Loop 次数 ≤5 | 🔴 | B 阶段 Loop 不超过 5 次 |

## 六、QG 失败处理

| 失败类型 | 处理 |
|---------|------|
| 单项 🔴 不通过 | 回当前阶段 Loop，重做相关任务 |
| 多项 🔴 不通过 | 评估是否 Exit-Escalate（升级到 Keeper/客户决策） |
| 根本性失败（如需求错） | 跨阶段回溯，更新上游产物 + 重新签 QG + 风险登记 |
