## 正文

### 一、测试策略（交付）

#### 1.1 测试目标

- 功能正确性：100% 满足验收标准
- 性能达标：见 §3 性能测试
- 安全无严重漏洞：OWASP Top 10 = 0
- 兼容性：主流浏览器/设备通过

#### 1.2 测试类型矩阵

| 测试类型 | 范围 | 工具 | 责任 | 频率 |
|---------|------|------|------|------|
| 单元测试 | 函数/类 | Jest/Vitest | 开发 | 每次提交 |
| 集成测试 | 接口/模块 | Jest+Supertest | 开发 | 每日 |
| 功能测试 | 端到端 | Playwright | 测试 | 每周 |
| 接口测试 | API | Postman/Newman | 测试 | 每日 |
| 性能测试 | QPS/响应 | JMeter/k6 | 测试 | 发布前 |
| 安全测试 | 漏洞扫描 | SonarQube/Snyk/Burp | 测试 | 发布前 |
| 兼容性测试 | 浏览器/设备 | BrowserStack | 测试 | 发布前 |
| 回归测试 | 全量 | 自动化 | 测试 | 每轮 |

#### 1.3 测试用例设计（6 种方法）

> ⚠ 应用 ≥ 4 种设计方法（QG10 Eval 指标）。

| # | 方法 | 适用场景 | 示例 |
|---|------|---------|------|
| 1 | **等价类划分** | 输入有明确范围 | 手机号 11 位 / 非 11 位 |
| 2 | **边界值分析** | 边界易错 | 密码 6 位（min）/ 7 位 / 20 位（max） |
| 3 | **场景法** | 业务流程 | 用户下单→支付→发货→收货 |
| 4 | **判定表** | 多条件组合 | 不同会员等级 × 不同支付方式 |
| 5 | **正交实验** | 多因素优化 | 3 因素 × 3 水平用 L9 而非 27 次 |
| 6 | **状态迁移** | 有状态实体 | 订单：待支付→已支付→已发货 |

#### 1.4 用例覆盖率指标

| 维度 | 阈值 |
|------|------|
| PRD 功能点覆盖率 | 100% |
| 验收标准覆盖率 | 100% |
| 核心路径覆盖率 | 100% |
| 异常路径覆盖率 | ≥ 80% |

### 六、缺陷管理（交付）

#### 6.1 缺陷分级

| 等级 | 定义 | 处理时限 |
|------|------|---------|
| **P0 阻塞** | 核心功能不可用 / 数据丢失 / 安全漏洞 | 立即修复，阻塞发布 |
| **P1 严重** | 主要功能受影响 / 性能严重不达标 | 24h 内修复 |
| **P2 一般** | 次要功能问题 / 体验问题 | 一周内修复 |
| **P3 轻微** | 文字错误 / UI 微调 | 排期修复 |

#### 6.2 缺陷生命周期

```
新建 → 分配 → 修复中 → 已修复 → 验证中 → 已关闭
                                       ↓
                                  重新打开（验证失败）
```

### 八、Loop Eval 集成

> 每轮测试 Loop 自动跑 Eval，不达标触发 QG-交付 Eval 反馈点。

#### 8.1 交付阶段测试执行 Loop

```
Plan     → 列执行批次 + 缺陷分级标准
Act      → 自动跑回归 + 手动跑探索测试
Observe  → 通过率 + 缺陷数 + 性能指标（自动统计）
Reflect  → 缺陷分级评审 + dev 复现确认
Exit     → 通过率 ≥ 95% + 无 P0 + P1 清零
```

#### 8.2 交付阶段缺陷闭环 Loop

```
Plan     → 列未关闭缺陷 + 优先级 + 责任人
Act      → dev 修复 + testing 验证（双签）
Observe  → 回归测试通过 + 修复引入新缺陷检查
Reflect  → 缺陷 close 会签
Exit     → P0/P1 清零 + 回归通过（QG-交付）
```
