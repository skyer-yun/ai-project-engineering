### 4. 部署步骤

#### 4.1 **打 Checkpoint**（强制前置）

> ⚠ 生产环境部署前必须打完整快照（**QG 部署门禁**）。
>
> 使用工具：[04-工具层/03-Checkpoint脚本/snapshot.sh](../../04-工具层/03-Checkpoint脚本/snapshot.sh)

```bash
# 打部署前快照
./snapshot.sh --type deploy --node Ship --tag pre-deploy-$(date +%Y%m%d-%H%M)

# 输出示例
# ✓ Snapshot created: snapshots/pre-deploy-20260630-1430/
#   - DB dump: db-backup.sql (245MB)
#   - Config: config-backup.tar.gz (12KB)
#   - AI context: ai-context-backup.json (45KB)
#   - sha256: a1b2c3...
```

#### 4.2 数据库变更

```bash
# 应用迁移
flyway migrate -configFiles=prod.conf

# 验证
flyway info -configFiles=prod.conf
```

#### 4.3 服务部署

```bash
# 构建镜像
docker build -t registry.example.com/myapp:v1.0 .

# 推送镜像
docker push registry.example.com/myapp:v1.0

# K8s 滚动更新
kubectl set image deployment/myapp myapp=registry.example.com/myapp:v1.0
kubectl rollout status deployment/myapp
```

| 2 | 主页可访问 | 200 | {填写} | ☐ |
| 3 | 登录功能 | Pass | {填写} | ☐ |
| 4 | 监控指标上报 | Pass | {填写} | ☐ |

### 5. **回滚预案**（关键）

#### 5.1 回滚触发条件

- 冒烟测试失败
- 错误率 > 5%（持续 5 分钟）
- 业务投诉（关键功能不可用）

#### 5.2 回滚步骤

```bash
# 一键回滚到部署前 Checkpoint
./rollback.sh --to pre-deploy-20260630-1430

# 验证回滚成功
kubectl rollout status deployment/myapp
```

#### 5.3 回滚策略矩阵

| 场景 | 回滚方式 | 责任人 | 决策时限 |
|------|---------|--------|---------|
| 代码 bug | 镜像回退 + DB 兼容 | 运维 + 业务 | 5min |
| DB 变更失败 | DB 备份恢复 + 镜像回退 | DBA | 15min |
| 配置错误 | 配置回滚 + 重启 | 运维 | 5min |
| 第三方故障 | 切换备用 / 降级 | 架构师 | 评估 |

> ⚠ 回滚决策人：运维 + 业务签字（详见 [00-理论层/03-HITL模式与不可逆性矩阵.md](../../00-理论层/03-HITL模式与不可逆性矩阵.md) 交付阶段不可逆 L4）。

## Loop 微循环 字段（交付阶段部署 Loop）

```
Plan     → 列部署步骤 + 回滚预案 + 通知清单
Act      → auto-deployer 生成部署脚本 + 灰度执行
Observe  → 部署成功 + 监控指标 + 冒烟测试
Reflect  → 运维 review + 业务确认
Exit     → 部署成功 + 监控正常 + 业务签字
```

> ⚠ 交付阶段部署 HITL 模式 = **In**（生产环境不可逆 L4，详见 [00-理论层/03-HITL模式与不可逆性矩阵.md](../../00-理论层/03-HITL模式与不可逆性矩阵.md)）。
