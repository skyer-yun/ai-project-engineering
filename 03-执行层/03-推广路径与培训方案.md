# 推广路径与培训方案

> **定位**：本文件是「DSBL × 五角色 × 工具中立」体系的推广落地路径与培训方案的**唯一权威源**。
> **目标**：让 10-30 人团队在 4 周内从 0 到全员使用本体系。
> **关联**：配合 [角色 Playbook](./01-角色Playbook/) + [适配层](../05-适配层/) + [工具层](../04-工具层/) 落地。

---

## 文档信息

| 项目 | 内容 |
|------|------|
| 适用对象 | 10-30 人技术团队（Spec-Writer / Builder / Reviewer / Shipper / Keeper） |
| 推广周期 | 4 周 |
| 责任人 | Keeper（主导） + 技术负责人（协作） |

---

## 一、4 周推广路径

### Week 1：单角色试点（小步验证）

| 项 | 内容 |
|----|------|
| 目标 | 1-2 个角色先跑通，验证体系可用性 |
| 范围 | Spec-Writer + Builder（最高频、ROI 最大） |
| 动作 | ① 选 1 个真实项目（小型，2-4 周交付）<br>② Spec-Writer 用 D + S 前半 Playbook<br>③ Builder 用 S 后半 + B Playbook + Plan Mode<br>④ 选定 AI 工具（详见 [05-适配层/](../05-适配层/)）<br>⑤ 每日站会同步问题 |
| 产物 | 试点项目源码 + 试点问题清单 |
| 验收 | D→S→B 流转跑通 + QG-D/QG-S/QG-B 通过 |

**Week 1 结束做什么**：
- 收集试点痛点（适配不准 / 工具缺失 / 路径混乱）
- 调整 Playbook + 适配方案
- 决策是否进入 Week 2

### Week 2：双角色扩展（横向覆盖）

| 项 | 内容 |
|----|------|
| 目标 | 加入 Reviewer + Shipper，覆盖完整 DSBL 闭环 |
| 范围 | 4 角色（Spec-Writer + Builder + Reviewer + Shipper） |
| 动作 | ① 选 1 个中型项目（4-8 周交付）<br>② Reviewer 跨阶段介入审查<br>③ Shipper 接手 B 阶段提测代码<br>④ 跑 QG-D→QG-S→QG-B→QG-Ship 跨角色交接<br>⑤ 启用 [Loop 度量看板](../04-工具层/02-Loop度量看板/) |
| 产物 | 跨角色交接契约链 + KPI 第一周数据 |
| 验收 | 4 角色全部用 Playbook 开场 + QG-D~Ship 全通过 |

### Week 3：Keeper 接入 + 全程闭环

| 项 | 内容 |
|----|------|
| 目标 | 加入 Keeper，打通全程 DSBL + L 复盘 |
| 范围 | 全 5 角色 |
| 动作 | ① Week 2 项目继续走到 Ship 部署验收<br>② Keeper 接入做契约校验 + 上下文治理<br>③ 启用 [Checkpoint 脚本](../04-工具层/03-Checkpoint脚本/)（部署前快照）<br>④ 完成 L 阶段项目复盘 |
| 产物 | 部署 Checkpoint 记录 + 验收报告 + 复盘报告 |
| 验收 | DSBL 全程通过 + 客户签字 + 改进项录入体系 |

### Week 4：全员推广 + 制度化

| 项 | 内容 |
|----|------|
| 目标 | 推广到剩余人员 + 写入团队制度 |
| 范围 | 全员 |
| 动作 | ① 全员培训（详见 §二）<br>② Playbook + 适配层 入职手册<br>③ KPI 看板周报化<br>④ 设立体系 owner（持续维护） |
| 产物 | 团队规范文档 + 入职手册 + owner 任命 |
| 验收 | 全员能独立用 Playbook 开场 + 周报 KPI 达标 |

## 二、新人入职培训（3 天速成）

### Day 1：理论 + 工具熟悉

| 时段 | 内容 | 时长 |
|------|------|------|
| 上午 | 七层架构总览（读 [README](../README.md) + [00-理论层/01-DSBL阶段模型与Loop微循环原理.md](../00-理论层/01-DSBL阶段模型与Loop微循环原理.md)） | 2h |
| 上午 | DSBL 五阶段 + Loop 微循环 + QG-D~Ship（读 [01-标准层/](../01-标准层/)） | 2h |
| 下午 | 选定 AI 工具 + 配置 [05-适配层/](../05-适配层/) | 2h |
| 下午 | 工具层上手：[素养盘点](../04-工具层/01-团队工程素养盘点工具.html) + [Loop 看板](../04-工具层/02-Loop度量看板/) + [Checkpoint](../04-工具层/03-Checkpoint脚本/) | 2h |

### Day 2：本角色 Playbook + 适配层

| 时段 | 内容 | 时长 |
|------|------|------|
| 上午 | 读本角色 Playbook（[01-角色Playbook/](./01-角色Playbook/) 5 选 1） | 2h |
| 上午 | 读对应适配指南（[05-适配层/](../05-适配层/)） | 2h |
| 下午 | 跟 mentor 走 1 个完整 Loop（影子练习） | 4h |

### Day 3：独立实操 + 考核

| 时段 | 内容 | 时长 |
|------|------|------|
| 上午 | 独立完成 1 个小任务（按 Playbook 入场姿势） | 3h |
| 下午 | review 实操产物 + 考核 | 2h |
| 下午 | 答疑 + 入职反馈 | 2h |

**考核标准**：
- 能说出本角色覆盖的 DSBL 阶段 + HITL 模式
- 能用 Playbook 入场姿势开场
- 能读懂交接契约并正确生成
- 能找到对应 QG 检查项

## 三、4 大推广阻力与应对

### 阻力 1：「AI 不信任，怕出错」

| 项 | 应对 |
|----|------|
| 根因 | 历史上 AI 编造过 / 跑过 ≠ 通过的认知 |
| 应对 | ① 73% HITL 数据宣讲（Anthropic 2026-02 论文实证，AI 做重活，人做关键决策）<br>② Plan Mode + QG 强制审批可见效<br>③ 先在低风险场景跑（CRUD/文档/单测）<br>④ KPI 看板展示 ROI（用数据说话） |
| 兜底 | 关键阶段强制 HITL-In，AI 无权自主决策 |

### 阻力 2：「不知道怎么启动」

| 项 | 应对 |
|----|------|
| 根因 | Playbook 触发语记不住，工具不熟 |
| 应对 | ① 每角色 Playbook §八 入场姿势做成桌面速查卡<br>② AI 工具配置启动问候（自动列出可用工作流）<br>③ mentor 制度（新人前 2 周绑定 mentor） |
| 兜底 | Keeper 在周会做开场示范 |

### 阻力 3：「产物参差不齐」

| 项 | 应对 |
|----|------|
| 根因 | 模板没用 / 用了但章节缺失 |
| 应对 | ① [02-产物层/](../02-产物层/) 模板做成交互式检查清单<br>② QG-D~Ship checklist 强制门禁<br>③ [交接契约校验工具](../04-工具层/04-交接契约工具/) 拦产物 |
| 兜底 | Keeper + Reviewer 联动核查 |

### 阻力 4：「缺证据，看不到效果」

| 项 | 应对 |
|----|------|
| 根因 | KPI 没量化 / 没对标 / 没历史对比 |
| 应对 | ① [Loop 度量看板](../04-工具层/02-Loop度量看板/) 周更新<br>② 基线 vs 目标 vs 实际三列对比<br>③ 每月发「ROI 报告」（提效/降错/省时）<br>④ 季度评比「最佳 Loop 实践」 |
| 兜底 | 强制周报含 KPI 截图 |

## 四、推广里程碑与退出条件

### 阶段验收清单

| 阶段 | 时间 | 退出条件 |
|------|------|---------|
| W1 试点 | 第 1 周末 | 1 项目跑通 + 问题清单收敛 |
| W2 扩展 | 第 2 周末 | 4 角色覆盖 + QG-D~Ship 通过 |
| W3 闭环 | 第 3 周末 | 5 角色覆盖 + 复盘报告完成 + 客户签字 |
| W4 全员 | 第 4 周末 | 全员培训完成 + 制度文档发布 |

### KPI 达标线（W4 末）

| KPI | 目标 |
|-----|------|
| 全员 Playbook 使用率 | ≥ 90% |
| QG 一次通过率 | ≥ 70% |
| 跨角色交接契约完整率 | 100% |
| Loop 度量看板数据完整度 | ≥ 90% |
| 周报含 KPI 截图 | 100% |

## 五、维护与演进

### Owner 制度

- 任命 1 名体系 owner（通常由 Keeper 或技术负责人兼任）
- 职责：
  - 每月评审 Playbook + 适配层（跟进业界新共识）
  - 收集团队反馈，季度发布 minor 升级
  - 维护 [04-工具层/](../04-工具层/)（KPI 调优 + 脚本更新）
  - 维护 [06-参考实现/](../06-参考实现/)（参考样例同步）

### 版本演进规则

> 详见 [01-标准层/05-工件演化与版本规范.md](../01-标准层/05-工件演化与版本规范.md)。

| 变更类型 | 版本号 | 示例 |
|---------|--------|------|

| 新增章节 / 新工具 / 新适配 | minor +1 | 加新 AI 工具适配 |
| DSBL 阶段重定义 / 角色重组 | major +1 | 引入新角色 |
