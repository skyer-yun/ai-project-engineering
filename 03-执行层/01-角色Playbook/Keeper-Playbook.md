# Keeper 角色 Playbook

> **目标读者**：项目经理 / 知识管理专员 / PMO / 技术总监督
> **主责阶段**：全程监督 + L-Learn（主）
> **业界锚点**：Anthropic Context Engineering 四原则 / Eval-Driven Development
> **工具中立**：详见 [05-适配层/](../../05-适配层/)。

---

## 一、角色定位

Keeper 是「上下文/记忆/复盘」的守护者。承担原 PM 职责并扩展：
- 项目管理（WBS / 进度 / 风险 / 资源）
- 上下文治理（契约守护 / 工件演化 / 记忆管理）
- 复盘沉淀（L 阶段主责，反哺体系）

**为什么改名 Keeper**：
- "PM" 在 AI 时代语义偏窄（管人 + 管进度）
- AI 时代核心挑战是**上下文管理**——谁守护契约、谁管理工件演化、谁保证记忆不丢失
- Keeper（守门人）更准确反映这个角色的全程监督属性

## 四、DSBL 阶段覆盖 + HITL 模式

| 阶段 | HITL | 核心动作 |
|------|------|---------|
| **D**（监督） | In | 项目章程确认 + 干系人清单会签 |
| **S**（监督） | In | 契约守护 + QG-S 签字 |
| **B**（监督） | On | 进度跟踪 + 风险预警 + QG-B 见证 |
| **Ship**（监督） | In | 部署/验收 L4 见证 + QG-Ship 签字 |
| **L**（主责） | **In** | 复盘报告 + 改进项录入 + 项目归档 |

> **核心定位**：Keeper 是"裁判 + 档案管理员 + 教练"——裁判判契约是否过，档案管理员管工件演化，教练写复盘反哺体系。

## 五、Loop 5 字段（Keeper 版）

```yaml
loop:
  goal: "守护全程上下文 + 契约 + 工件演化，并从项目提炼可复用知识"
  context: |
    全程：交接契约链 + QG 历史 + Loop 度量数据 + 工件版本树
    项目：MEMORY.md + 项目章程 + 风险登记册
  tools:
    - 任意 AI 工具（Claude Code / Codex / Cursor 等）
    - 契约校验工具（[04-工具层/04-交接契约工具/](../../04-工具层/04-交接契约工具/)）
    - Checkpoint 脚本（[04-工具层/03-Checkpoint脚本/](../../04-工具层/03-Checkpoint脚本/)）
    - Loop 度量看板（[04-工具层/02-Loop度量看板/](../../04-工具层/02-Loop度量看板/)）
    - 项目管理工具（WBS / 甘特图 / 风险登记册）
  checkpoint: "每次契约签署 + QG 通过 + 阶段流转"
  exit:    "L 阶段复盘报告通过 + 改进项录入体系"
```

**L 阶段复盘 Loop**：

```
Plan     → 列复盘维度（目标/过程/质量/团队/AI 协作）
Act      → 整理数据 + 访谈 + 写复盘报告
Observe  → 数据对比（计划vs实际 / QG 通过率 / Loop 次数）（客观）
Reflect  → 团队共识 + 改进项（主观）
Exit     → 复盘报告评审通过 + 改进项录入体系
```

## 七、上下文治理（Keeper 核心职责）

按 [00-理论层/04-上下文工程四原则.md](../../00-理论层/04-上下文工程四原则.md) 落地：

### 7.1 Write 治理

- 确保每次阶段 Exit 都写交接契约
- 确保每次工件演化都进版本树
- 确保项目 MEMORY.md 及时更新

### 7.2 Select 治理

- 启动扫描：推断项目阶段 → 加载 Top-3 知识
- 跨阶段交接：只传契约 + 版本树，不全量传 context

### 7.3 Compress 治理

- 超 20 轮对话自动摘要
- 长工具结果截断 + 链接
- memory 单文件 ≤ 200 行

### 7.4 Isolate 治理

- 跨项目 preferences 严格分离
- 跨角色 context 独立
- 交接元数据精简

## 八、契约校验流程

每次阶段流转，Keeper 用 [validate-handoff.sh](../../04-工具层/04-交接契约工具/) 校验：

```
上游签交接契约
   ↓
Keeper 运行 validate-handoff.sh
   ↓
校验项：
  - gate_status = passed
  - exit_met = true（所有 loop_signs）
  - 关键 Eval 高于阈值
  - iterations ≤ 5
  - reflect_passed = true
  - approved_by 齐全
  - output_artifacts.path 存在
   ↓
校验通过 → 下游可启动
校验失败 → 退回上游 + 风险登记
```

## 九、典型协作流（全程视角）

```
D 启动 ── Keeper 监督章程签署
   ↓
QG-D ── Keeper 见证 + 归档契约 D→S
   ↓
S 流转 ── Keeper 监督 QG-S 通过 + 归档契约 S→B
   ↓
B 流转 ── Keeper 跟踪进度 + 风险预警 + QG-B 见证
   ↓
Ship 流转 ── Keeper 见证 L4 部署/验收签字 + 归档契约 Ship→L
   ↓
L 复盘 ── Keeper 主导复盘 + 写报告 + 改进项入库
   ↓
项目归档 ── Keeper 完成项目档案 7 类产物齐全
```

## 十一、反模式

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 跳过契约校验直接流转 | 上游污染下游 | 必须跑 validate-handoff |
| 项目结束不写复盘 | 经验丢失 | L 阶段强制复盘报告 |
| 工件不版本化 | 演化轨迹丢失 | 强制工件演化层 |
| 上下文混层 | 全项目污染 | 严格 4 层分离 |
| 复盘流于形式 | 体系不演化 | 改进项必须录入跟踪 |
