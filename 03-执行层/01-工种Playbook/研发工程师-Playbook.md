# 研发工程师 Playbook（含架构师）

> **目标读者**：研发工程师 / 架构师 / 全栈开发 / 后端/前端开发
> **主责阶段**：设计（S，后半：架构/详设）+ 开发（B，主）
> **方法论逻辑角色**：构建师（Builder）（设计后半主签）+ 审查师（Reviewer）（交叉审查）
> **业界锚点**：Anthropic *Building Effective Agents* / Spec-Driven Development / Google Engineering Practices
> **工具中立**：本 Playbook 不绑定具体 AI 工具。Claude Code / Codex / Cursor / 自带工具均可，详见 [05-适配层/](../../05-适配层/)。

---

## 一、工种定位

研发工程师是「规范→可工作软件」的落地者，主责交付实现侧：
- **架构设计**：C4 四视图、ADR（架构决策记录）、技术选型
- **详细设计**：接口定义、数据模型、时序图、状态机
- **编码开发**：单测、lint、类型检查、Code Review
- **联调集成**：接口契约一致性、集成测试

**架构师子角色**：在设计后半主导架构设计，签 QG-设计的 构建师（Builder） 角色。

**与产品经理的边界**：产品写 PRD（What/Why），研发写架构设计（How）。设计阶段并行，研发给产品反馈可行性。

**与测试工程师的边界**：研发写代码+单测，测试写测试策略+用例。开发阶段协同，研发给测试提供接口文档和联调报告。

## 四、五阶段覆盖 + HITL 模式

| 阶段 | 研发工程师角色 | HITL | 核心动作 |
|------|-------------|------|---------|
| 需求 | 协（可行性反馈） | On | 技术可行性评估、约束反馈 |
| **设计后半**（主） | **主**（架构/详设） | **In**（L3 评审） | 架构设计、详细设计、ADR |
| **开发**（主） | **主**（编码+单测+联调） | **In+Fallback**（L2） | 编码、单测、Review、联调 |
| 交付 | 协（缺陷修复） | In（L4 部署） | 缺陷修复、部署支持、回滚 |
| 复盘 | 参 | In | 技术债复盘输入 |

详见 [03-执行层/03-HITL规则表.md](../03-HITL规则表.md)。

## 五、Loop 5 字段（研发工程师版）

```yaml
loop:
  goal: "把 PRD/需求基线 → 可工作软件 → 通过测试验收"
  context: |
    上游：PRD v1.x / 架构设计 / 详细设计 / 验收标准
    约束：技术栈/性能/安全/兼容性/可维护性
  tools:
    - 任意 AI 工具（Claude Code / Codex / Cursor 等，详见 05-适配层）
    - IDE + Git + Checkpoint（每次状态变更打 snapshot）
    - 单测框架 + lint + 类型检查
  checkpoint: "每次 commit 打 git_commit / 部署前打 deploy_snapshot"
  exit: "QG-开发 通过（覆盖率/lint/类型/编译/Review/P0P1）→ 签交接契约 开发→交付"
```

**设计后半 Loop（PRD→架构/详设）**：

```
Plan     → Plan Mode：列架构 4 视图大纲 + ADR 清单
Act      → AI 生成架构设计 + 详细设计
Observe  → 4 视图完整度 + 非功能覆盖 + 接口完整度（客观）
Reflect  → 架构评审会 + 产品/售前确认（主观）
Exit     → 评审通过 → 配合 QG-设计
```

**开发 Loop（详设→可工作软件）**：

```
Plan     → 拆任务 + 估时 + 风险识别
Act      → AI 协助编码 + 单测生成
Observe  → 覆盖率/lint/类型/编译/Review 一次通过率（客观）
Reflect  → Code Review 会 + 跨角色反馈（主观）
Exit     → QG-开发 通过 → 签交接契约
```

## 七、典型协作流

### 7.1 设计 → 开发（自循环）

```
PRD v1.x → 研发做架构设计 → 架构评审通过
   ↓
研发写详细设计 + 接口定义 → 与产品确认验收标准
   ↓
共同签 QG-设计 → 交接给开发
   ↓
编码 + 单测 + Review + 联调 → QG-开发 → 交接给测试
```

### 7.2 与产品经理协作（设计阶段）

设计阶段前半产品主 PRD，后半研发主架构：
- 产品提供 PRD + 验收标准 + 原型
- 研发反馈可行性 + 技术约束
- 协同产物：PRD 评审纪要、需求变更记录

### 7.3 与测试工程师协作（开发阶段）

- 研发提供：源码 + 单测 + 接口文档 + 联调报告
- 测试反馈：缺陷清单 + 覆盖率盲区
- 协同产物：缺陷修复记录、回归测试通过证明

### 7.4 与交付工程师协作（交付阶段）

- 研发提供：部署清单 + 配置项 + 回滚脚本
- 交付反馈：部署问题、生产缺陷
- 协同产物：部署演练记录、回滚验证

## 九、反模式（禁止行为）

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 跳过架构设计直接写代码 | 系统不可维、技术债爆炸 | 设计后半必须过 QG-设计 |
| 单测覆盖率不达标就提测 | 缺陷逃脱率飙升 | 核心 ≥90% / 行 ≥80% / 分支 ≥70% |
| 不写接口文档 | 联调灾难、前后端打架 | OpenAPI 文档与代码同提交 |
| Code Review 走过场 | 质量失控 | Review 一次通过率 ≥70% / 返工率 ≤30% |
| 跳过 Plan Mode 直接生成 | 文档结构散乱 | 强制场景必须触发 Plan Mode |
