# 项目经理 Playbook

> **目标读者**：项目经理 / PMO / 项目协调人
> **主责阶段**：全程监督（五阶段均参与）+ 复盘（L，主责）
> **方法论逻辑角色**：统筹师（Keeper）（统筹师，全程唯一稳定角色）
> **业界锚点**：Anthropic *Measuring AI Agent Autonomy*（HITL 73% 实证）/ PMP / 敏捷项目管理
> **工具中立**：本 Playbook 不绑定具体 AI 工具。Claude Code / Codex / Cursor / 自带工具均可，详见 [05-适配层/](../../05-适配层/)。

---

## 一、工种定位

项目经理是「五阶段全流程」的统筹者，主责监督侧：
- **项目章程**：项目类型声明（瀑布/迭代 MVP/敏捷）、Sprint 切法、外环节奏
- **进度跟踪**：WBS、甘特图、关键路径、里程碑
- **风险管理**：风险登记册、预警升级、应对预案
- **质量门禁监督**：QG 评审组织、契约校验、不达标阻断
- **跨工种协调**：6 工种（售前/产品/研发/测试/交付/PM）协同、冲突解决、资源调配；PM 同时承担 **统筹师（Keeper）** 逻辑角色

**与交付工程师的边界**：PM 主协调（进度/风险/汇报），交付主执行（部署/验收/培训）。交付阶段 PM 监督，交付执行。

**统筹师（Keeper） 角色唯一性**：五阶段全程稳定角色，承担上下文/记忆/复盘职责，是阶段交接契约的最终签字人之一。

## 四、五阶段覆盖 + HITL 模式

| 阶段 | 项目经理角色 | HITL | 核心动作 |
|------|-------------|------|---------|
| **需求** | 监督 | **In**（L3 契约） | 项目章程、QG-需求 组织、契约签字 |
| **设计** | 监督 | **In**（L3 契约） | QG-设计 组织、契约签字 |
| **开发** | 监督 | On | 进度跟踪、风险预警 |
| **交付** | 监督 | **In**（L4 上线） | QG-交付 组织、上线审批 |
| **复盘**（主） | **主** | **In**（L3 复盘） | 复盘组织、经验入库、项目档案归档 |

详见 [03-执行层/03-HITL规则表.md](../03-HITL规则表.md)。

> **关键**：PM 是阶段交接契约的 统筹师（Keeper） 签字人，每份契约必须 PM 具名 + 时间戳。

## 五、Loop 5 字段（项目经理版）

```yaml
loop:
  goal: "项目按五阶段推进 → 各 QG 通过 → 客户验收 → 经验沉淀"
  context: |
    全程：项目章程 / WBS / 风险登记册 / 各阶段契约
    约束：项目类型/资源/时间/合规/HITL 模式
  tools:
    - 任意 AI 工具（Claude Code / Codex / Cursor 等，详见 05-适配层）
    - 项目管理工具（Jira/Redmine/Excel）
    - 文档版本工具（Git / WPS / OneDrive）
  checkpoint: "每个 QG 通过打 artifact_diff / 每个阶段 Exit 打 snapshot"
  exit: "复盘报告签字 + 经验入库 ≥10 条 + 项目档案 7 类齐全"
```

**全程监控 Loop（持续）**：

```
Plan     → 项目章程 + WBS + 里程碑
Act      → 各阶段推进 + QG 评审组织
Observe  → 进度偏差 + 风险数 + QG 通过率（客观）
Reflect  → 阶段评审会 + 客户汇报（主观）
Exit     → 每个 QG 通过签字 + 阶段交接契约归档
```

**复盘 Loop（项目结项）**：

```
Plan     → 列复盘对象（5 阶段 + 6 工种 ↔ 5 逻辑角色）+ 收集输入
Act      → AI 协助整理复盘报告 + 经验入库
Observe  → 归档完整度 100% + 经验条数 ≥10（客观）
Reflect  → 复盘会 + 全员确认（主观）
Exit     → 项目档案 7 类齐全 + 经验入库 → 项目关闭
```

## 七、典型协作流

### 7.1 全程统筹（5 阶段监督）

```
项目章程 → 声明项目类型 + Sprint 切法
   ↓
需求阶段 → 组织 QG-需求 → 签契约（需求→设计）
   ↓
设计阶段 → 组织 QG-设计 → 签契约（设计→开发）
   ↓
开发阶段 → 进度跟踪 + 风险预警 → 签契约（开发→交付）
   ↓
交付阶段 → 组织 QG-交付 → 客户验收
   ↓
复盘阶段 → 项目复盘 + 经验入库 + 档案归档
```

### 7.2 跨工种协调（6 工种 ↔ 5 逻辑角色）

PM 协调 6 工种协同（组织实务），同时按 5 逻辑角色在 handoff 契约上签字（方法论约束）：
- 售前 + 产品（需求阶段双主责）→ 共同承担 **需求规范师（Spec-Writer）**
- 产品 + 研发（设计阶段前半 PRD / 后半架构）→ Spec-Writer → **构建师（Builder）**
- 研发 + 测试（开发阶段联调）→ Builder + **审查师（Reviewer）**
- 测试 + 交付（交付阶段前半测试 / 后半部署）→ **交付师（Shipper）**
- 全员（复盘阶段）→ PM 承担 **统筹师（Keeper）**

### 7.3 QG 评审组织（各阶段 Exit）

```
PM 发起 QG 评审 → 各工种提交产物 → 校验契约
   ↓
评审会 → 通过/返工决策
   ↓
通过 → 签字（含 PM 的 统筹师（Keeper） 角色）→ 阶段交接契约归档
   ↓
返工 → 通知上游 → 重循环
```

## 九、反模式（禁止行为）

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 项目类型不声明 | Sprint 节奏混乱 | 章程必须明示项目类型 |
| QG 评审走过场 | 阶段产物质量失控 | 严格按 checklist 校验 + 契约签字 |
| 跳过复盘直接关项目 | 经验流失、重复踩坑 | 复盘报告 + 经验入库 ≥10 条 |
| 不维护交接契约 | 上下游脱节 | 每个 QG 通过即生成契约 + 归档 |
| 风险登记册只列不跟踪 | 风险升级失控 | 每周复核 + 预警升级路径 |
