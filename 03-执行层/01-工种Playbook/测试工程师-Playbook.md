# 测试工程师 Playbook

> **目标读者**：测试工程师 / QA / 自动化测试 / 性能测试工程师
> **主责阶段**：交付（Ship，前半：测试策略/用例/执行）
> **方法论逻辑角色**：交付师（Shipper）（主）+ 审查师（Reviewer）（交叉审查质量守门）
> **业界锚点**：Anthropic *Eval-Driven Development* / Context Engineering 四原则 / 测试金字塔
> **工具中立**：本 Playbook 不绑定具体 AI 工具。Claude Code / Codex / Cursor / 自带工具均可，详见 [05-适配层/](../../05-适配层/)。

---

## 一、工种定位

测试工程师是「可工作软件→可验收交付物」的守门人，主责质量侧：
- **测试策略**：测试金字塔（单测/集成/E2E）、覆盖率目标
- **测试用例**：基于 PRD + 验收标准 + 6 种设计方法
- **测试执行**：功能/性能/安全/回归测试
- **缺陷管理**：缺陷定级、跟踪、P0/P1 清零

**与研发工程师的边界**：研发写单测（白盒），测试写集成/E2E（黑盒）。开发阶段协同，测试给研发反馈缺陷。

**与交付工程师的边界**：测试主测试（用例/执行/报告），交付主部署（环境/上线/培训）。交付阶段前半测试主，后半交付主。

## 四、五阶段覆盖 + HITL 模式

| 阶段 | 测试工程师角色 | HITL | 核心动作 |
|------|-------------|------|---------|
| 需求 | 协（验收标准审查） | On | 验收标准可测试性审查 |
| 设计 | 协（用例预设计） | On | 早期测试场景识别 |
| 开发 | 协（联调验证） | On | 联调验证、早期缺陷发现 |
| **交付前半**（主） | **主**（测试策略/用例/执行） | **In**（L3 测试报告） | 测试策略、用例、执行、缺陷管理 |
| **交付后半**（协） | 协（验收支持） | **In**（L4 验收） | 验收会支持、回归测试 |
| 复盘 | 参 | In | 缺陷复盘输入 |

详见 [03-执行层/03-HITL规则表.md](../03-HITL规则表.md)。

## 五、Loop 5 字段（测试工程师版）

```yaml
loop:
  goal: "把可工作软件 → 可验收交付物 → P0/P1 清零"
  context: |
    上游：源码 + 单测 + 接口文档 + 联调报告 + PRD 验收标准
    约束：测试金字塔/覆盖率/P0P1 清零/性能阈值
  tools:
    - 任意 AI 工具（Claude Code / Codex / Cursor 等，详见 05-适配层）
    - 测试框架（JUnit/PyTest/Playwright/JMeter）
    - 缺陷跟踪（Jira/红牒）
  checkpoint: "测试基线变更打 test_baseline / 每轮回归打 snapshot"
  exit: "QG-交付 通过（用例通过率≥95% / P0=0 / P1=0 / 性能达标）→ 签交接契约 交付→部署"
```

**交付前半 Loop（软件→可验收）**：

```
Plan     → 列测试范围 + 金字塔分层 + 资源配置
Act      → AI 生成测试用例 + 自动化脚本
Observe  → 用例覆盖率 + 执行率 + 通过率（客观）
Reflect  → 测试评审会 + 研发确认（主观）
Exit     → 测试报告通过 → 配合 QG-交付
```

**缺陷修复 Loop（持续）**：

```
Plan     → 缺陷定级 + 优先级排序
Act      → 研发修复 + 测试回归
Observe  → P0/P1 数量 + 清零率（客观）
Reflect  → 缺陷评审会（主观）
Exit     → P0=0 + P1=0 → 进入验收
```

## 七、典型协作流

### 7.1 开发 → 交付（自循环）

```
研发完成编码 + 单测 → 联调报告 → 测试介入
   ↓
测试写测试策略 + 用例 → 执行测试 → 发现缺陷
   ↓
研发修复 → 测试回归 → P0/P1 清零
   ↓
测试报告通过 → QG-交付 → 交接给交付工程师部署
```

### 7.2 与研发工程师协作（开发阶段）

- 研发提供：源码 + 单测 + 接口文档 + 联调报告
- 测试反馈：缺陷清单 + 覆盖率盲区
- 协同产物：缺陷修复记录、回归测试通过证明

### 7.3 与交付工程师协作（交付阶段）

- 测试提供：测试报告 + 缺陷清零证明 + 性能报告
- 交付执行：部署演练 + 上线 + 验收
- 协同产物：验收报告、客户回退记录

### 7.4 与产品经理协作（验收阶段）

- 产品提供：验收标准清单
- 测试反馈：用例覆盖验收标准证明
- 协同产物：验收报告（双签）

## 九、反模式（禁止行为）

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 用例覆盖率不足就执行 | 缺陷逃脱率飙升 | 用例通过率 ≥95% / 执行率 100% |
| P0/P1 未清零就上线 | 生产事故 | P0=0 / P1=0 强制门禁 |
| 不做回归测试 | 修 A 坏 B | 每次修复后必跑回归 |
| 性能测试临时抱佛脚 | 上线后性能崩盘 | 提前做基线、持续压测 |
| 缺陷定级不准 | 优先级混乱 | 严格 P0-P3 标准 |
