# 交付工程师 Playbook

> **目标读者**：交付工程师 / 实施工程师 / 运维工程师 / 部署负责人
> **主责阶段**：交付（Ship，后半：部署/验收/培训）+ 复盘（L，参与）
> **方法论逻辑角色**：交付师（Shipper）（主）
> **业界锚点**：Anthropic *Building Effective Agents* / DevOps / SRE 实践
> **工具中立**：本 Playbook 不绑定具体 AI 工具。Claude Code / Codex / Cursor / 自带工具均可，详见 [05-适配层/](../../05-适配层/)。

---

## 一、工种定位

交付工程师是「可验收交付物→客户在生产环境使用」的落地者，主责上线侧：
- **部署实施**：部署方案、环境准备、灰度发布、回滚预案
- **验收管理**：客户验收会、验收报告、客户签字
- **培训交付**：用户手册、培训 PPT、考核题库
- **运维移交**：运维手册、监控告警、值班就位

**与测试工程师的边界**：测试主测试（用例/执行/报告），交付主部署（环境/上线/培训）。交付阶段前半测试主，后半交付主。

**与项目经理的边界**：交付主执行（部署/验收/培训），PM 主协调（进度/风险/汇报）。交付阶段交付主，PM 监督。

| 1 | 「写部署方案」 | 交付后半 | 部署方案文档（含回滚） |

## 四、五阶段覆盖 + HITL 模式

| 阶段 | 交付工程师角色 | HITL | 核心动作 |
|------|-------------|------|---------|
| 需求 | 参（部署约束） | On | 部署环境、合规约束反馈 |
| 设计 | 协（部署架构） | On | 部署架构、运维要求输入 |
| 开发 | 协（部署准备） | On | 部署脚本、配置项准备 |
| **交付后半**（主） | **主**（部署/验收/培训） | **In**（L4 生产/验收） | 部署演练、上线、验收会、培训 |
| **复盘**（参与） | 参 | In | 交付复盘输入、运维移交 |

详见 [03-执行层/03-HITL规则表.md](../03-HITL规则表.md)。

> **关键**：生产部署是 L4 不可逆，必须 HITL-In（每关键步骤审批）+ 部署演练（含回滚验证）。

## 五、Loop 5 字段（交付工程师版）

```yaml
loop:
  goal: "把可验收交付物 → 生产环境稳定运行 → 客户签字验收"
  context: |
    上游：测试报告（P0/P1 清零） + 源码 + 部署清单 + 验收标准
    约束：生产环境/SLA/合规/回滚窗口/培训计划
  tools:
    - 任意 AI 工具（Claude Code / Codex / Cursor 等，详见 05-适配层）
    - 部署工具（Docker/K8s/Ansible/CI/CD）
    - 监控告警（Prometheus/Grafana/ELK）
  checkpoint: "部署前打 deploy_snapshot / 验收前打 artifact_diff"
  exit: "客户签字 + 运维移交 3/3 → 项目结项 → 进入复盘"
```

**交付后半 Loop（可验收→生产）**：

```
Plan     → 部署方案 + 灰度策略 + 回滚预案
Act      → 部署演练 + 上线发布
Observe  → 一次部署成功率 ≥90% + 回滚演练通过（客观）
Reflect  → 客户验收会 + 运维确认（主观）
Exit     → 验收报告签字 + 运维移交 → QG-交付
```

**培训 Loop（持续）**：

```
Plan     → 列培训对象 + 培训大纲 + 考核标准
Act      → 培训执行 + 考核
Observe  → 培训考核通过率 ≥80%（客观）
Reflect  → 客户满意度 ≥4/5（主观）
Exit     → 培训完成 + 移交运维
```

## 七、典型协作流

### 7.1 交付自循环（测试→部署→验收）

```
测试通过 QG-交付前半（P0/P1 清零）→ 交付介入
   ↓
交付写部署方案 + 演练（含回滚验证）→ 上线发布
   ↓
客户验收会 → 客户签字
   ↓
培训 + 运维移交 → 项目结项 → 进入复盘
```

### 7.2 与测试工程师协作（交付阶段）

- 测试提供：测试报告 + 缺陷清零证明 + 性能报告
- 交付执行：部署演练 + 上线 + 验收
- 协同产物：验收报告、客户回退记录

### 7.3 与研发工程师协作（部署阶段）

- 研发提供：部署清单 + 配置项 + 回滚脚本
- 交付反馈：部署问题、生产缺陷
- 协同产物：部署演练记录、回滚验证

### 7.4 与项目经理协作（验收阶段）

- 交付提供：验收报告 + 培训记录 + 运维移交单
- PM 协调：客户关系、验收会组织
- 协同产物：结项报告

## 九、反模式（禁止行为）

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 没有回滚预案就上线 | L4 不可逆灾难 | 必须含回滚演练 + 双签 |
| 跳过部署演练直接上生产 | 部署回滚率飙升 | 部署演练（含回滚验证）通过 |
| 验收会没有客户签字 | 项目无法结项 | 验收报告必须具名签字 |
| 培训走过场 | 客户满意度崩盘 | 考核通过率 ≥80% |
| 运维移交不完整 | 上线后失联 | 手册+监控+值班 3/3 就位 |
