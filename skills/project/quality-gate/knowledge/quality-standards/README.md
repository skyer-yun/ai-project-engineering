# 质量门禁标准

> QG1-QG5 共 48 个检查项，每个门禁对应阶段交接点，未通过不允许进入下一阶段

---

## QG1: 项目规划完成度（N3 -> N4）

**交接点**：项目规划完成 -> 进入产品/需求阶段

### 检查项（10 项）

| 序号 | 分类 | 检查项 | 阻塞级别 |
|------|------|--------|---------|
| 1 | 规划完整性 | 项目章程已编写并确认 | BLOCK |
| 2 | 规划完整性 | 项目目标已明确（SMART 原则） | BLOCK |
| 3 | 规划完整性 | 项目范围已定义（包含/排除） | BLOCK |
| 4 | 规划完整性 | 干系人已识别并登记 | BLOCK |
| 5 | 计划完整性 | WBS 已分解到工作包级别（8-80h 粒度） | BLOCK |
| 6 | 计划完整性 | 工作量估算已完成（至少 1 种方法） | BLOCK |
| 7 | 计划完整性 | 甘特图已生成（含关键路径和里程碑） | BLOCK |
| 8 | 计划完整性 | 资源分配已完成 | WARN |
| 9 | 风险与质量 | 初始风险登记册已创建（>=3 条风险） | BLOCK |
| 10 | 风险与质量 | 质量门禁标准已确认 | WARN |

### 通过条件
- 10 项中 >= 8 项通过
- 序号 1-4（规划完整性）必须全部通过
- 序号 5-8 中 >= 3 项通过

### 交接产物
项目章程 / WBS + 甘特图 / 风险登记册

---

## QG2: 需求/设计就绪度（N7 -> N8）

**交接点**：产品设计完成 -> 进入开发阶段

### 检查项（12 项）

| 序号 | 分类 | 检查项 | 阻塞级别 |
|------|------|--------|---------|
| 1 | 需求完整性 | PRD 已编写（12 部分结构完整） | BLOCK |
| 2 | 需求完整性 | PRD Part 7 功能模块达到深度要求 | BLOCK |
| 3 | 需求完整性 | 功能优先级已确定（P0/P1/P2） | BLOCK |
| 4 | 需求完整性 | 非功能需求已明确（性能/安全/兼容性） | BLOCK |
| 5 | 需求完整性 | 数据模型已设计（ER 图/状态码） | WARN |
| 6 | 需求完整性 | 接口规范已定义 | BLOCK |
| 7 | 设计就绪度 | Demo/原型已确认 | BLOCK |
| 8 | 设计就绪度 | 技术方案已评审 | BLOCK |
| 9 | 设计就绪度 | 设计系统已选择 | WARN |
| 10 | 设计就绪度 | 前端页面结构已定义 | BLOCK |
| 11 | 评审确认 | PRD 已通过评审 | BLOCK |
| 12 | 评审确认 | 客户/业务方已确认需求 | BLOCK |

### 通过条件
- 12 项中 >= 10 项通过
- 序号 1-6 中 >= 5 项通过
- 序号 11-12 必须全部通过

### 交接产物
PRD / Demo 页面 / 设计规范 / 接口文档

---

## QG3: 开发完成度（N10 -> N11）

**交接点**：开发完成 -> 进入测试阶段

### 检查项（8 项）

| 序号 | 分类 | 检查项 | 阻塞级别 |
|------|------|--------|---------|
| 1 | 代码质量 | 代码已冻结（feature freeze） | BLOCK |
| 2 | 代码质量 | 代码审查已完成 | BLOCK |
| 3 | 代码质量 | 无编译错误/构建失败 | BLOCK |
| 4 | 功能完整性 | 所有 P0 功能已实现 | BLOCK |
| 5 | 功能完整性 | 所有 P1 功能已实现（或已确认延期） | BLOCK |
| 6 | 功能完整性 | 自测通过（开发冒烟测试） | BLOCK |
| 7 | 文档完整性 | 接口文档已更新（与实现一致） | WARN |
| 8 | 文档完整性 | 联调报告已完成（联调通过） | WARN |

### 通过条件
- 8 项必须全部通过
- 序号 1（代码冻结）和序号 4（P0 功能完成）为硬性条件

### 交接产物
源码（已打 Tag）/ 接口文档 / 联调报告

---

## QG4: 测试通过度（N12 -> N13）

**交接点**：测试完成 -> 进入部署/交付阶段

### 检查项（10 项）

| 序号 | 分类 | 检查项 | 阻塞级别 |
|------|------|--------|---------|
| 1 | 测试完成度 | 测试策略已制定并评审 | BLOCK |
| 2 | 测试完成度 | 测试用例已编写并基线化 | BLOCK |
| 3 | 测试完成度 | 用例执行率 100%（P0/P1） | BLOCK |
| 4 | 测试完成度 | 用例通过率 >= 95% | BLOCK |
| 5 | 缺陷管理 | P0 缺陷已清零（0 Open） | BLOCK |
| 6 | 缺陷管理 | P1 缺陷已清零（0 Open） | BLOCK |
| 7 | 缺陷管理 | P2 缺陷修复率 >= 80% | WARN |
| 8 | 缺陷管理 | 遗留问题已记录并评估风险 | BLOCK |
| 9 | 测试报告 | 测试报告已输出（含结论） | BLOCK |
| 10 | 测试报告 | 性能测试报告已输出（如适用） | WARN |

### 通过条件
- 10 项必须全部通过
- 序号 5-6（P0/P1 清零）为硬性条件，无例外
- 序号 3-4（执行率/通过率）为硬性条件

### 交接产物
测试报告 / 缺陷清单 / 性能报告 / 源码（已打 Tag）

---

## QG5: 交付完成度（N15 -> N16）

**交接点**：交付完成 -> 项目结项

### 检查项（8 项）

| 序号 | 分类 | 检查项 | 阻塞级别 |
|------|------|--------|---------|
| 1 | 部署验收 | 部署方案已制定并执行 | BLOCK |
| 2 | 部署验收 | 生产环境部署验证通过 | BLOCK |
| 3 | 部署验收 | 验收测试已完成 | BLOCK |
| 4 | 文档交付 | 用户手册已交付并确认 | BLOCK |
| 5 | 文档交付 | 运维手册已交付并确认 | BLOCK |
| 6 | 文档交付 | 培训已完成（或培训材料已交付） | WARN |
| 7 | 项目收尾 | 验收报告已签署 | BLOCK |
| 8 | 项目收尾 | 客户满意度已确认 | WARN |

### 通过条件
- 8 项必须全部通过
- 序号 7（验收报告签署）为硬性条件

### 交接产物
交付文档包 / 验收报告 / 运维手册

---

## 判定规则

| 条件 | 结论 |
|------|------|
| 所有阻塞项通过 + 警告项 <= 2 | PASS |
| 所有阻塞项通过 + 警告项 > 2 | PASS WITH WARNINGS |
| 存在阻塞项不通过 | FAIL |

## 不可例外项

- QG4 序号 5-6：P0/P1 缺陷清零
- QG5 序号 7：验收报告签署
- 所有门禁的产物存在性检查
