# 智能排期知识库

## 排期算法概述

### 关键路径法（CPM）

CPM 是项目排期的核心算法，通过分析任务依赖网络确定项目最短工期和关键任务。

**核心概念**：

| 概念 | 缩写 | 含义 |
|------|------|------|
| 最早开始时间 | ES | 任务在所有前置任务完成后最早可以开始的时间 |
| 最早完成时间 | EF | ES + 任务工期 |
| 最晚完成时间 | LF | 不影响项目总工期的最晚完成时间 |
| 最晚开始时间 | LS | LF - 任务工期 |
| 总浮动时间 | TF | LS - ES，任务可延迟的总时间 |
| 自由浮动时间 | FF | 不影响后续任务最早开始的可延迟时间 |

**关键路径判定**：TF = 0 的任务链即为关键路径，任何关键路径任务的延迟都将直接延长项目工期。

### PERT 三点估算法

当任务工期不确定时，使用三点估算提高准确度：

| 参数 | 公式 | 说明 |
|------|------|------|
| 期望工期 | Te = (O + 4M + P) / 6 | O=乐观, M=最可能, P=悲观 |
| 标准差 | σ = (P - O) / 6 | 衡量估算的不确定性 |
| 置信区间 | Te ± 1σ = 68% / ± 2σ = 95% | 按需选择置信度 |

## 资源平衡策略

### 策略矩阵

| 策略 | 工期影响 | 资源影响 | 适用场景 |
|------|----------|----------|----------|
| 资源平滑 | 无 | 优化分配 | 浮动时间充足 |
| 资源均衡 | 可能延长 | 负载均匀 | 资源有限且固定 |
| 赶工 | 缩短 | 成本增加 | 里程碑不可移动 |
| 快速跟进 | 缩短 | 风险增加 | 可并行的串行任务 |

### 资源利用率标准

| 利用率区间 | 状态 | 建议 |
|-----------|------|------|
| 60%-80% | 健康 | 正常排期 |
| 80%-100% | 紧张 | 关注风险，准备预案 |
| 100%-120% | 过载 | 必须平衡，重新排期 |
| >120% | 严重过载 | 立即干预，拆分任务 |

### 平衡启发规则

1. 关键路径任务优先分配最优资源
2. 浮动时间少的任务优先调度
3. 单点瓶颈资源安排在核心时段
4. 预留 10%-15% 缓冲产能应对变更

## 关键路径优化方法

### 快速跟进决策表

| 条件 | 决策 |
|------|------|
| 任务间 FS 依赖可改为 SS+滞后 | 执行快速跟进 |
| 并行增加的协调成本 < 节省的工期 | 执行快速跟进 |
| 并行风险可接受（风险评估为中低） | 执行快速跟进 |
| 并行风险高且无缓解措施 | 不建议快速跟进 |

### 赶工成本分析

```
赶工成本斜率 = (赶工成本 - 正常成本) / (正常工期 - 赶工工期)
```

优先选择赶工成本斜率最低的关键路径任务进行赶工。

## 缓冲管理

### 缓冲类型

| 缓冲类型 | 位置 | 大小计算 | 用途 |
|----------|------|----------|------|
| 项目缓冲 | 关键路径末端 | 关键链长度的 20%-50% | 保护项目交付日期 |
| 接驳缓冲 | 非关键路径汇入点 | 汇入路径长度的 50% | 防止非关键路径影响关键路径 |
| 资源缓冲 | 关键资源切换前 | 1-2 天 | 确保关键资源按时就绪 |

### 缓冲消耗监控

| 消耗比例 | 状态 | 行动 |
|----------|------|------|
| 0%-33% | 绿色 | 正常执行 |
| 33%-67% | 黄色 | 制定应急预案 |
| 67%-100% | 红色 | 执行应急预案，考虑升级 |

## 历史数据校准

### 校准因子

| 因子 | 计算方式 | 应用场景 |
|------|----------|----------|
| 效率系数 | 实际工期 / 估算工期 | 调整团队产能基线 |
| 需求变更率 | 变更需求数 / 总需求数 | 预留变更缓冲 |
| 缺陷返工率 | 返工工时 / 总工时 | 测试阶段工期加成 |
| 沟通开销 | 会议时间 / 总工作时间 | 增加管理开销估算 |

### 历史数据参考基准

| 项目类型 | 需求变更率 | 缺陷返工率 | 管理开销 |
|----------|-----------|-----------|----------|
| 政企定制项目 | 25%-35% | 15%-20% | 20%-25% |
| 标准产品项目 | 10%-15% | 8%-12% | 15%-20% |
| 迭代优化项目 | 5%-10% | 5%-8% | 10%-15% |

### 使用建议

1. 至少积累 3 个同类项目数据才具有参考价值
2. 关注中位数而非平均值（避免极端值干扰）
3. 每季度更新一次校准因子
4. 新团队初期效率系数按 0.6-0.7 估算
