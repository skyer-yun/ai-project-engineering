# 知识沉淀工作流

## 工作流概览

```
Phase 1: 产物收集 → Phase 2: 经验提炼 → Phase 3: 模板沉淀 → Phase 4: 知识库更新
```

## Phase 1: 产物收集

### 输入
- 项目全过程产物（由用户提供或从 07-project-copilot 获取）

### 活动
1. **收集项目产物清单**
   - 售前阶段：需求文档、技术方案、投标文件
   - 产品阶段：PRD、原型、需求变更记录
   - 设计阶段：架构设计、详细设计、数据库设计
   - 开发阶段：源代码、代码审查记录、接口文档
   - 测试阶段：测试策略、测试用例、测试报告、缺陷统计
   - 交付阶段：部署方案、用户手册、培训材料、验收报告
   - 管理记录：WBS、甘特图、风险登记册、变更记录、会议纪要

2. **评估产物完整性**
   - 按阶段检查产物是否齐全
   - 标记缺失产物
   - 评估已有产物是否足够进行经验沉淀

3. **确定沉淀范围**
   - 确认本次沉淀的重点领域
   - 确认需要沉淀的模板类型
   - 确认度量数据的采集范围

### 输出
- 项目产物清单（含完整性评估）
- 沉淀范围确认书

### 检查点
- [ ] 核心阶段产物已收集
- [ ] 产物完整性已评估
- [ ] 沉淀范围已确认

## Phase 2: 经验提炼

### 输入
- Phase 1 收集的项目产物

### 活动
1. **提炼成功经验（Top 5）**
   - 从方案/设计/代码中识别有效的技术决策
   - 从管理记录中识别有效的项目管理实践
   - 从测试报告中识别质量保障亮点
   - 从交付记录中识别客户满意的要素
   - 每条经验需包含：场景描述、具体做法、效果数据、适用条件

2. **提炼改进建议（Top 5）**
   - 从需求变更记录中识别需求管理不足
   - 从缺陷统计中识别质量薄弱环节
   - 从风险登记册中识别风险应对不足
   - 从工期/成本偏差中识别估算偏差
   - 每条建议需包含：问题描述、根因分析、改进措施、预期效果

3. **识别可复用资产**
   - 技术方案框架（可复用于同类行业）
   - 架构设计模式（可复用于同类技术栈）
   - 测试策略模板（可复用于同类项目）
   - 项目管理实践（可复用于同类团队规模）
   - 代码组件/工具（可复用于同类业务场景）

4. **采集度量数据**
   - 工期偏差 = (实际工期 - 计划工期) / 计划工期
   - 成本偏差 = (实际成本 - 计划成本) / 计划成本
   - 缺陷密度 = 缺陷总数 / 代码规模(KLOC)
   - 人均产出 = 功能点数 / 人月数
   - 需求变更率 = 变更需求数 / 总需求数
   - 缺陷修复率 = 已修复缺陷 / 总缺陷

### 输出
- 成功经验清单（Top 5，含场景/做法/效果/适用条件）
- 改进建议清单（Top 5，含问题/根因/措施/预期效果）
- 可复用资产清单
- 度量数据报告

### 检查点
- [ ] 成功经验有数据支撑
- [ ] 改进建议有根因分析
- [ ] 可复用资产已去除项目特定信息
- [ ] 度量数据有基线对比

## Phase 3: 模板沉淀

### 输入
- Phase 2 提炼的经验和可复用资产

### 活动
1. **判断模板沉淀价值**
   - 评估可复用性：同类项目是否需要？
   - 评估通用性：能否跨客户复用？
   - 评估时效性：技术是否过时？
   - 高价值 → 沉淀为标准模板
   - 中价值 → 沉淀为参考案例
   - 低价值 → 仅记录经验条目

2. **编写行业模板**
   - 行业背景：该行业的典型痛点和需求特征
   - 方案框架：解决该行业痛点的通用方案结构
   - 技术选型：推荐的技术栈及选型理由
   - 注意事项：该行业特有的合规/安全/性能要求
   - 参考案例：脱敏后的实际项目经验

3. **编写技术模板**
   - 技术场景：适用该技术方案的业务场景
   - 架构模式：推荐的系统架构
   - 关键设计：数据库/接口/安全等关键设计决策
   - 踩坑记录：实际项目中遇到的技术问题及解决方案
   - 最佳实践：总结的技术最佳实践

4. **模板质量审核**
   - 是否去除了项目特定信息（客户名/金额/人员）
   - 是否有明确的适用场景说明
   - 是否有使用注意事项
   - 是否有版本和更新日期

### 输出
- 行业模板文档
- 技术模板文档
- 模板质量审核记录

### 检查点
- [ ] 模板已去除敏感信息
- [ ] 适用场景明确
- [ ] 使用注意事项完整
- [ ] 版本和日期已标注

## Phase 4: 知识库更新

### 输入
- Phase 2 的经验总结
- Phase 3 的模板文档

### 活动
1. **确定更新类型**
   - 新增：全新的知识条目（新行业/新技术）
   - 更新：已有条目的内容补充或修正
   - 归档：过时或不再使用的条目

2. **编写知识条目**
   - 标题：简洁明确，包含行业/技术关键词
   - 分类：行业/技术/管理/工具
   - 标签：3-5个关键词标签
   - 内容：结构化的知识内容
   - 来源：标注来源项目和日期（脱敏）
   - 适用范围：说明适用的项目类型和规模

3. **更新知识库索引**
   - 更新分类目录
   - 更新标签索引
   - 更新最近更新记录

4. **设置回顾周期**
   - 新增条目：6个月后回顾
   - 更新条目：12个月后回顾
   - 超过2年未使用 → 标记为「待归档」

### 输出
- 知识库更新记录
- 更新后的知识库索引
- 回顾计划

### 检查点
- [ ] 更新类型正确（新增/更新/归档）
- [ ] 知识条目结构完整
- [ ] 标签和分类正确
- [ ] 索引已更新
