# Workflow: 竞品分析（Competitive Analysis）

4个阶段：竞品识别 → 数据收集（5维度） → SWOT分析 → 策略建议。

---

## Stage 1: 竞品识别（Competitor Identification）

### 输入
- 自家产品名称和描述
- 行业/领域信息（可选）
- 已知竞品名单（可选）

### 处理步骤
1. 根据产品定位确定竞品范围
2. 分类竞品：直接竞品 / 间接竞品 / 潜在竞品
3. 筛选 3-5 个核心竞品进行深入分析
4. 与用户确认竞品清单

### 竞品分类

| 类型 | 定义 | 分析深度 |
|------|------|----------|
| 直接竞品 | 同类产品、相同目标客户 | 深度分析 |
| 间接竞品 | 不同产品、满足相同需求 | 中度分析 |
| 潜在竞品 | 可能进入市场的竞争者 | 简要分析 |

### 输出
- 竞品清单（分类/名称/定位/理由）
- 核心竞品确认

---

## Stage 2: 数据收集（Data Collection - 5 Dimensions）

### 维度 1：功能对比

#### 收集内容
- 核心功能清单
- 功能覆盖度（有/无/部分）
- 差异化功能
- 功能实现深度

#### 输出格式

| 功能点 | 我方 | 竞品A | 竞品B | 竞品C |
|--------|------|-------|-------|-------|
| 核心功能1 | 完整 | 完整 | 部分 | 无 |
| 核心功能2 | 完整 | 部分 | 完整 | 完整 |
| 差异功能1 | 有 | 无 | 无 | 有 |

### 维度 2：技术对比

#### 收集内容
- 技术架构（公开信息）
- 性能指标（QPS/延迟/并发）
- 安全认证（等保/ISO/PCI-DSS）
- 集成能力（API/SDK/开放平台）
- 部署模式（SaaS/私有化/混合）

#### 输出格式

| 技术维度 | 我方 | 竞品A | 竞品B |
|----------|------|-------|-------|
| 技术架构 | 微服务 | 单体 | 微服务 |
| 性能 | 10k QPS | 5k QPS | 8k QPS |
| 安全认证 | 等保三级 | 等保二级 | ISO27001 |
| 部署模式 | SaaS+私有化 | SaaS | SaaS+私有化 |

### 维度 3：价格对比

#### 收集内容
- 定价模式（按用户/按量/包年）
- 各版本价格
- 性价比分析
- 隐性成本（实施/培训/运维）

#### 输出格式

| 价格维度 | 我方 | 竞品A | 竞品B |
|----------|------|-------|-------|
| 定价模式 | 按用户数 | 按功能模块 | 按使用量 |
| 基础版 | ¥X/用户/月 | ¥Y/模块/年 | ¥Z/调用 |
| 专业版 | ¥X/用户/月 | ¥Y/模块/年 | ¥Z/调用 |
| 实施费用 | 含 | 另计 | 含 |
| 性价比评级 | 高 | 中 | 高 |

### 维度 4：用户体验

#### 收集内容
- 界面设计（截图分析）
- 操作流程（核心路径步骤数）
- 用户评价（G2/Capterra/应用商店评分）
- 学习成本（上手时间）
- 客户支持（响应时间/满意度）

#### 输出格式

| 体验维度 | 我方 | 竞品A | 竞品B |
|----------|------|-------|-------|
| 界面设计 | 现代简洁 | 传统稳重 | 简洁但功能少 |
| 核心操作步骤 | 3步 | 5步 | 4步 |
| 用户评分 | 4.5/5 | 4.0/5 | 4.2/5 |
| 学习成本 | 低 | 中 | 低 |

### 维度 5：市场定位

#### 收集内容
- 目标客户群体
- 市场份额（如果有公开数据）
- 品牌影响力
- 渠道策略
- 典型客户案例

#### 输出格式

| 定位维度 | 我方 | 竞品A | 竞品B |
|----------|------|-------|-------|
| 目标客户 | 中大型企业 | 小微企业 | 全行业 |
| 市场份额 | 新进入 | 30% | 20% |
| 品牌影响力 | 新品牌 | 知名品牌 | 区域品牌 |
| 典型客户 | - | 客户A/B | 客户C/D |

### 信息收集方法

```
IF web-access 可用:
  1. 访问竞品官网获取产品信息
  2. 搜索行业报告和评测文章
  3. 查看用户评价和论坛讨论
  4. 搜索定价信息
ELSE:
  1. 基于已有知识整理
  2. 标注信息可能不够准确
  3. 建议用户补充最新信息
```

---

## Stage 3: SWOT 分析

### 输入
- Stage 2 的 5维度对比数据

### SWOT 矩阵

#### Strengths（优势）
- 基于功能/技术/价格维度中我方领先的部分
- 我方的独特竞争优势

#### Weaknesses（劣势）
- 基于功能/技术/价格维度中我方落后的部分
- 需要改进的短板

#### Opportunities（机会）
- 市场趋势中的有利因素
- 竞品的薄弱环节
- 客户未被满足的需求

#### Threats（威胁）
- 竞品的优势方向
- 市场趋势中的不利因素
- 新进入者的威胁

### 输出格式

| | 有利 | 不利 |
|---|------|------|
| **内部** | S: 优势1<br>S: 优势2 | W: 劣势1<br>W: 劣势2 |
| **外部** | O: 机会1<br>O: 机会2 | T: 威胁1<br>T: 威胁2 |

### 交叉策略

| 交叉 | 策略 |
|------|------|
| S+O | 发挥优势抓住机会（增长策略） |
| W+O | 改善劣势利用机会（转型策略） |
| S+T | 发挥优势抵御威胁（防御策略） |
| W+T | 改善劣势规避威胁（生存策略） |

---

## Stage 4: 策略建议（Strategy Recommendations）

### 输入
- SWOT 分析结果
- 5维度对比数据

### 策略维度

1. **产品策略**
   - 差异化功能方向
   - 功能优先级建议
   - 用户体验改进方向

2. **定价策略**
   - 定价模式建议
   - 价格区间建议
   - 促销和折扣策略

3. **营销策略**
   - 目标客户聚焦
   - 差异化卖点提炼
   - 营销渠道建议

4. **技术策略**
   - 技术投入方向
   - 技术差异化建议

### 输出
- 4个维度的策略建议（各3-5条）
- 优先级排序
- 执行时间线建议

### 报告模板

```markdown
# {产品名} 竞品分析报告

## 1. 分析概述
- 分析日期
- 竞品范围
- 分析维度

## 2. 竞品概况
- 竞品清单和分类
- 各竞品简介

## 3. 五维度对比分析
### 3.1 功能对比
### 3.2 技术对比
### 3.3 价格对比
### 3.4 用户体验对比
### 3.5 市场定位对比

## 4. SWOT 分析
### 4.1 优势（Strengths）
### 4.2 劣势（Weaknesses）
### 4.3 机会（Opportunities）
### 4.4 威胁（Threats）
### 4.5 交叉策略分析

## 5. 策略建议
### 5.1 产品策略
### 5.2 定价策略
### 5.3 营销策略
### 5.4 技术策略

## 6. 附录
- 信息来源
- 数据时效说明
- 分析方法说明
```
