# Test Coverage Analysis Workflow

> 需求追溯矩阵 + 覆盖率分析 + 遗漏检测

## 概览

| 项目 | 说明 |
|------|------|
| 输入 | 测试用例集 + PRD/详细设计/验收标准 |
| 输出 | 需求追溯矩阵 + 覆盖率报告 + 补充建议 |

---

## Stage 1: 映射用例到需求

### 1.1 构建追溯矩阵

```
映射规则：
  1. 读取 PRD Part 7 每个功能点（F01, F02, ...）
  2. 读取每条业务规则（BR-XXX）
  3. 读取验收标准（Part 11）
  4. 逐项匹配测试用例的"需求追溯"字段
```

### 1.2 追溯矩阵格式

```markdown
| 需求编号 | 需求描述 | 优先级 | 用例编号 | 覆盖状态 |
|---------|---------|--------|---------|---------|
| PRD-F01 | 用户登录 | P0 | TC-F01-001~020 | 已覆盖 |
| PRD-F01-BR01 | 密码6-20位 | P0 | TC-F01-003, TC-F01-004 | 已覆盖 |
| PRD-F01-BR02 | 错误5次锁定 | P0 | — | 未覆盖 |
| PRD-F11-AC01 | 登录响应<500ms | P1 | TC-F01-050 | 已覆盖 |
```

---

## Stage 2: 识别未覆盖需求

### 2.1 覆盖率统计

```
按优先级统计：
  P0 覆盖率：已覆盖 P0 需求数 / P0 需求总数 × 100%
  P1 覆盖率：已覆盖 P1 需求数 / P1 需求总数 × 100%
  P2 覆盖率：已覆盖 P2 需求数 / P2 需求总数 × 100%
  总覆盖率：已覆盖需求数 / 需求总数 × 100%

目标：
  P0 = 100%（硬性要求）
  P1 >= 95%
  P2 >= 80%
```

### 2.2 遗漏分类

```
类型 A：无任何用例覆盖（最严重）
  → 必须补充

类型 B：只有正向用例，缺少异常/边界
  → 建议补充异常和边界用例

类型 C：有用例但预期结果不明确
  → 建议完善预期结果

类型 D：验收标准未被测试
  → 必须补充验收用例
```

---

## Stage 3: 生成覆盖报告

### 报告模板

```markdown
# 测试覆盖率报告

## 概览

| 维度 | 总数 | 已覆盖 | 覆盖率 | 目标 | 达标 |
|------|------|--------|--------|------|------|
| 功能需求 | 42 | 40 | 95.2% | 100% | 否 |
| 业务规则 | 68 | 65 | 95.6% | 100% | 否 |
| 验收标准 | 35 | 35 | 100% | 100% | 是 |
| P0 需求 | 15 | 15 | 100% | 100% | 是 |
| P1 需求 | 18 | 17 | 94.4% | 95% | 否 |

## 遗漏清单

| 序号 | 需求编号 | 需求描述 | 遗漏类型 | 建议操作 |
|------|---------|---------|---------|---------|
| 1 | PRD-F01-BR02 | 错误5次锁定账号 | 类型A | 补充锁定测试用例 |
| 2 | PRD-F03-BR05 | 折扣金额不超过订单总额50% | 类型B | 补充边界值用例 |

## 结论

- P0 需求 100% 覆盖：达标
- P1 需求 94.4% 覆盖：差 1 项，建议补充后达标
- 总体评估：基本达标，补充 2 条用例后可进入测试执行
```

---

## Stage 4: 建议补充用例

### 4.1 自动生成补充建议

```
对每个遗漏项：
  1. 分析遗漏原因（缺少哪种设计方法）
  2. 推荐设计方法
  3. 生成补充用例草稿
  4. 供人工审核后补充
```

### 4.2 输出

```
补充用例列表（格式同测试用例模板）
+ 更新后的追溯矩阵
+ 更新后的覆盖率统计
```
