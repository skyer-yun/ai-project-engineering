# 测试设计方法速查

> 6 种核心设计方法 + 选择决策树 + 覆盖率标准，供用例生成工作流引用

---

## 方法 1：等价类划分

### 定义
将输入域划分为若干等价类，从每个等价类中选取代表性数据作为测试输入。同一等价类中的任一输入都应揭示相同的缺陷。

### 适用场景
- 表单输入验证（手机号、邮箱、身份证号）
- 数值范围输入（年龄、金额、数量）
- 枚举类型（性别、状态、类型）
- 配置参数（开关、阈值）

### 示例
输入：密码长度 6-20 位
- 有效等价类：6 <= len <= 20（取 10）
- 无效等价类：len < 6（取 3）、len > 20（取 25）、空值
- 用例数 = 有效类数 + 无效类数 = 3

### 用例数公式
`N = 有效等价类数 + 无效等价类数`

## 方法 2：边界值分析

### 定义
在等价类边界及其附近选取测试数据。大量缺陷集中在边界条件上，边界值是等价类的必要补充。

### 适用场景
- 数值范围（年龄 1-150、金额 0.01-99999.99）
- 字符串长度（密码 6-20、用户名 2-50）
- 日期范围（开始日期 <= 结束日期）
- 分页参数（页码 >= 1、每页 10-100）

### 边界值选取规则
闭区间 [a, b]：测试 a-1, a, a+1, b-1, b, b+1（6 个点）
特殊值：0、负数、null、空字符串

### 示例
输入：年龄 [1, 150]
- 边界值：0, 1, 2, 149, 150, 151
- 用例数 = 6

### 用例数公式
`N = 边界点数（通常每个边界 3 个点 = 上界3 + 下界3 = 6）`

## 方法 3：场景法

### 定义
通过分析业务流程，构建从开始到结束的完整操作路径（场景），覆盖正向流程、替代流程和异常流程。

### 适用场景
- 业务流程测试（下单、审批、报销）
- 多步骤操作（注册-验证-激活）
- 多角色协作流程（提交-审核-发布）
- 跨模块交互（购物车-结算-支付-发货）

### 示例
场景：电商下单流程
- 基本流：登录 → 浏览商品 → 加入购物车 → 结算 → 支付成功 → 确认收货
- 替代流：使用优惠券结算、选择货到付款
- 异常流：库存不足、支付超时、收货地址缺失
- 用例数 = 1(基本流) + N(替代流) + M(异常流)

### 用例数公式
`N = 1(基本流) + 替代流数 + 异常流数`

## 方法 4：判定表

### 定义
针对多条件组合逻辑，列出所有条件的真值组合，确定每种组合下的操作结果。适用于条件之间存在逻辑依赖的场景。

### 适用场景
- 多条件组合判断（折扣规则：VIP + 满减 + 限时）
- 权限组合（角色 + 部门 + 操作类型）
- 计费规则（套餐 + 用量 + 时段）
- 业务规则引擎（条件 A 且 条件 B 或 条件 C → 动作）

### 示例
条件：是否VIP(Y/N) + 订单金额 >= 200(Y/N)
| VIP | 金额>=200 | 折扣 |
|-----|----------|------|
| Y | Y | 7折 |
| Y | N | 8折 |
| N | Y | 9折 |
| N | N | 无折扣 |
用例数 = 4（可化简）

### 用例数公式
`N = 条件真值组合数（化简前 2^n，化简后视具体情况）`

## 方法 5：正交实验

### 定义
使用正交表从多因素多水平的全组合中选取具有代表性的子集，以最少的用例数覆盖所有因素间的两两交互。

### 适用场景
- 多因素配置测试（浏览器 x 分辨率 x 操作系统）
- 多参数组合（搜索：关键词 + 分类 + 排序 + 价格区间）
- 系统配置组合（缓存策略 + 连接池大小 + 超时时间）
- 兼容性矩阵覆盖

### 示例
3 因素 2 水平（全组合 8，正交表 L4 覆盖 4）
因素：浏览器(Chrome/Firefox) x 支付方式(微信/支付宝) x 网络(WiFi/4G)
- 用例数 = 4（通过 L4(2^3) 正交表选取）

### 用典数公式
`N = 正交表行数（远小于 m^n，m=水平数，n=因素数）`

## 方法 6：状态迁移

### 定义
分析系统或对象的状态变化，测试从每个状态到其他状态的合法转换，以及非法转换的正确拒绝。

### 适用场景
- 订单状态流转（待支付 → 已支付 → 已发货 → 已完成/已取消）
- 审批流程（草稿 → 待审 → 通过/驳回 → 归档）
- 工单状态（新建 → 处理中 → 已解决 → 已关闭）
- 设备状态（离线 → 在线 → 故障 → 维修中）

### 示例
订单状态：待支付、已支付、已发货、已完成、已取消
- 有效转换：待支付→已支付、待支付→已取消、已支付→已发货、已发货→已完成（4 条）
- 非法转换：已发货→待支付、已完成→已支付（n*(n-1)-有效转换数 条）
- 用例数 = 有效转换数 + 关键非法转换数

### 用例数公式
`N = 有效状态转换数 + 需验证的非法转换数`

## 方法选择决策树

```
被测对象特征？
│
├─ 有输入域/取值范围 → 等价类划分 + 边界值分析（组合使用）
├─ 有业务流程/多步骤操作 → 场景法
├─ 有多条件组合判断 → 判定表
├─ 有状态流转 → 状态迁移
├─ 有多因素配置/兼容性 → 正交实验
└─ 无法归类 → 错误推测 + 探索性测试（补充）
```

实际使用中，一个功能点通常组合多种方法：
- 登录功能 = 等价类(手机号) + 边界值(验证码) + 场景法(登录流程)
- 订单流程 = 场景法(主流程) + 状态迁移(订单状态) + 判定表(优惠规则)

## 覆盖率标准（按优先级）

| 优先级 | 用例覆盖率要求 | 说明 |
|--------|--------------|------|
| P0 核心 | 100% | 每条需求至少 1 条用例，所有方法覆盖 |
| P1 重要 | >= 95% | 每条需求至少 1 条用例，核心方法覆盖 |
| P2 一般 | >= 80% | 主要场景覆盖，非关键路径可适当裁剪 |
| P3 轻微 | >= 60% 或抽样 | 非核心功能可降低标准，重点覆盖基本流 |

### 覆盖率计算
- 需求覆盖率 = 已覆盖需求点 / 总需求点 * 100%
- 功能覆盖率 = 已生成用例的功能点 / 总功能点 * 100%
- 方法覆盖率 = 已使用的目标设计方法 / 应使用的设计方法 * 100%
