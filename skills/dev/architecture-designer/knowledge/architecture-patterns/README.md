# 架构模式参考（Architecture Patterns）

## 概述

本目录描述 6 种常见架构模式，供架构设计时参考选择。

---

## 1. 单体架构（Monolith）

### 适用场景
- 小型项目、初创产品
- 快速验证（MVP）
- 团队规模小（< 10人）
- 业务逻辑相对简单

### 优点
- 开发效率高，无分布式复杂度
- 部署简单，一个进程搞定
- 调试方便，本地可完整运行
- 事务管理简单

### 缺点
- 随着规模增长，代码耦合加剧
- 扩展性受限，只能整体扩展
- 技术栈锁定
- 故障影响面大

### 技术栈示例
- Spring Boot（Java）
- Django（Python）
- Laravel（PHP）
- Next.js（Node.js）

---

## 2. 微服务架构（Microservice）

### 适用场景
- 大型系统、复杂业务
- 多团队协作开发
- 需要独立部署和扩展
- 技术异构需求

### 优点
- 独立开发、部署、扩展
- 技术栈可异构
- 故障隔离
- 团队自治

### 缺点
- 分布式复杂度高（网络/一致性/调试）
- 运维成本高
- 需要服务治理（注册/发现/熔断/限流）
- 数据一致性挑战

### 技术栈示例
- 服务框架：Spring Cloud / Go Micro / Dubbo
- 服务网格：Istio / Linkerd
- API 网关：Kong / Nginx / APISIX
- 配置中心：Nacos / Apollo / Consul

---

## 3. 无服务器架构（Serverless）

### 适用场景
- 事件驱动型应用
- 流量波动大、需要弹性伸缩
- 短时任务处理
- API 后端、数据处理管道

### 优点
- 无需管理服务器
- 按需付费，成本优化
- 自动弹性伸缩
- 聚焦业务逻辑

### 缺点
- 冷启动延迟
- 调试和本地测试困难
- 供应商锁定
- 长时间运行任务受限

### 技术栈示例
- AWS Lambda + API Gateway
- Azure Functions
- 阿里云函数计算
- Cloudflare Workers

---

## 4. 事件驱动架构（Event-Driven）

### 适用场景
- 异步处理场景
- 系统解耦需求
- 实时数据处理
- 多系统联动

### 优点
- 松耦合，生产者和消费者独立
- 异步处理，提高响应速度
- 可扩展性好
- 支持事件回放

### 缺点
- 事件顺序性保证复杂
- 调试和追踪困难
- 最终一致性，不适合强一致性场景
- 事件 Schema 演进挑战

### 技术栈示例
- Kafka / RabbitMQ / RocketMQ
- EventBridge / Pulsar
- CDC：Debezium / Canal

---

## 5. 分层架构（Layered）

### 适用场景
- 企业应用系统
- 业务逻辑清晰、规则复杂
- 团队按层分工
- 需要清晰的职责划分

### 优点
- 职责清晰，层与层分离
- 易于测试和维护
- 关注点分离
- 标准化程度高

### 缺点
- 性能开销（多层调用）
- 可能出现"瀑布式"修改
- 层间耦合可能过紧
- 不适合高频交互场景

### 技术栈示例
- 经典三层：Presentation / Business / Data
- DDD 四层：Interface / Application / Domain / Infrastructure
- Clean Architecture

---

## 6. 六边形架构（Hexagonal / Ports & Adapters）

### 适用场景
- 领域驱动设计（DDD）
- 需要高可测试性
- 业务逻辑与技术实现解耦
- 多种输入输出适配

### 优点
- 业务核心与技术框架解耦
- 高可测试性（Mock 端口即可）
- 适配器可替换
- 领域模型纯粹

### 缺点
- 学习曲线陡峭
- 接口定义工作量大
- 简单场景过度设计
- 需要团队对 DDD 有共识

### 技术栈示例
- Java：Spring + DDD 战术设计
- TypeScript：NestJS + 领域层
- Go：Clean Architecture 变体

---

## 模式选择决策树

```
系统规模？
├── 小型（< 5个模块）
│   └── 单体架构
├── 中型（5-15个模块）
│   ├── 事件驱动需求？ → 事件驱动
│   ├── 清晰分层需求？ → 分层架构
│   └── 默认 → 模块化单体
└── 大型（> 15个模块）
    ├── 多团队协作？ → 微服务
    ├── 弹性伸缩？ → Serverless
    └── 领域复杂？ → 六边形 + 微服务
```
