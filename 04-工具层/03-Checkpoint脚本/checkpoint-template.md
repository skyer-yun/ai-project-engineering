# Checkpoint 记录模板（人工记录版）

> 当 `snapshot.sh` 无法运行（无 DB 权限 / 外部系统）时，人工填写本表。
> 自动场景请优先用 `snapshot.sh`，本模板用于补充关键 Checkpoint 元数据。

---

## Checkpoint 元数据

| 项目 | 内容 |
|------|------|
| Checkpoint ID | CP-{项目缩写}-{阶段}- {序号}（例：CP-PYSH-交付-003） |
| 类型 | deploy（部署前） / node（节点出口） / manual（手动） |
| 阶段 | {需求/设计/开发/交付/复盘/...} |
| 时间 | {YYYY-MM-DD HH:MM:SS} |
| 创建人 | {姓名} |
| 触发原因 | {例：交付阶段生产部署前 / 开发阶段集成完成 / 开发阶段特性交付} |

## 回滚条件（何时使用本 Checkpoint）

| 触发场景 | 阈值 | 决策人 |
|---------|------|--------|
| 错误率突增 | > 5% 持续 5 分钟 | 运维 + 业务 |
| 关键功能不可用 | 客户投诉 ≥ 3 单 | 业务 |
| 监控告警 | P0 告警持续 10 分钟 | 运维 |
| 数据异常 | DB 校验失败 | DBA |

---

## 回滚步骤（如需触发）

```
1. 决策会议（运维 + 业务双签，交付阶段 L4 不可逆）
2. 执行回滚：
   - 自动场景：./rollback.sh --to CP-PYSH-Ship-003
   - 手动场景：按本表的"备份内容清单"逐项恢复
3. 回滚后冒烟测试（健康检查 + 核心流程）
4. 通知干系人
5. 记录到 rollback-history.md
```

---

## 验证记录

- [ ] 备份完整性已校验（sha256）
- [ ] 备份可恢复（在测试环境验证）
- [ ] 回滚步骤已 dry-run
- [ ] 干系人已签字
