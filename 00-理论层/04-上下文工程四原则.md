# 上下文工程四原则

> **定位**：本文件是「上下文工程四原则」「上下文窗口治理规则」的**唯一权威源**。
> **业界锚**：Tobi Lütke (Shopify CEO) + Karpathy + Philipp Schmid (LangChain) *Context Engineering* (2025-06)；Anthropic *Effective Context Engineering for AI Agents* (2025-09)。

---

## 一、为什么"上下文工程"取代了"提示工程"

2025 年下半年业界共识：

> **"Prompt Engineering 已死，Context Engineering 当立。"**

核心论断：
- 单条 prompt 写得再好，也只是"一行字写得好"——LLM 不是看一行字，是看**整个 context window**
- Karpathy 类比：**"LLM 是 CPU，context window 是 RAM。"** 你不会"写好一行字"给 RAM，你要管理整个地址空间
- 真正决定 AI 输出质量的，是**整个上下文怎么构造、怎么压缩、怎么按需检索、怎么隔离**

**对本体系的意义**：跨角色对齐机制升级为「上下文工程层」，按四原则落地。

> **关于原则数量**：Anthropic 2025-09 工程博客明确为 **4 原则**（Write/Select/Compress/Isolate）。Layer 是落地形态不是独立原则，本体系遵循 Anthropic 官方四原则口径。

---

## 二、四原则映射表

| 原则 | 含义 | 落地形态 |
|------|------|---------|
| **Write** | 信息写入外部记忆，不让上下文无限增长 | 项目目录 + memory 双写 + 工件演化层 |
| **Select** | 按需 RAG/工具检索，不一次性塞满 | 启动扫描 + 推断阶段 + 加载 Top-3 知识；跨角色交接按需加载 |
| **Compress** | 对话历史摘要、工具结果截断、Token 预算 | 跨 20 轮对话自动摘要；长工具结果自动截断 + 链接全文 |
| **Isolate** | 多智能体拆分上下文窗口，避免污染 | 每角色/工具独立 context；交接元数据精简；Plan Mode 用 subagent 隔离探索 |

---

## 三、Karpathy OS 类比的落地

> **LLM 是 CPU，context window 是 RAM。**

落到本体系：

| 计算机层次 | 本体系对应 | 大小 | 加载策略 |
|----------|-----------|------|---------|
| **L1 cache**（系统层） | skill.md YAML 头 + 核心规则节 | 小 | 常驻 |
| **L2 cache**（记忆层） | preferences.md + 项目 MEMORY.md | 中 | 按需加载 |
| **RAM**（工件层） | 工件演化层 + Eval 报告 | 大 | 按 Select 加载 |
| **外设**（工具层） | MCP / CLI / API | 即时 | 调用时不持久化结果 |

**核心原则**：**L1 必须小**——常驻部分超过 200 行就过度膨胀 context，必须把细节下沉到子文件按需 Select。

## 四、四原则详细规则

### 4.1 Write（写入外部记忆）

**目的**：不让 context window 无限增长。

| 触发 | 写入动作 | 写入位置 |
|------|---------|---------|
| 完成一个阶段 | 工件版本 + Loop 签名 + 交接契约 | 项目目录 + 工件演化层 |
| 用户偏好被确认 | 偏好条目 | `memory/preferences.md` |
| 项目决策落定 | 决策记录 | 项目 `MEMORY.md` |
| 跨角色交接 | handoff 元数据 | `项目文档/{项目}/_handoffs/` |

**禁止**：把项目细节写入静态层（污染所有项目）；把一次性上下文写入 memory（污染所有会话）。

### 4.2 Select（按需检索）

**目的**：不一次性塞满 context。

| 触发 | Select 策略 |
|------|------------|
| 启动 AI 工具 | 扫描项目目录 → 推断阶段 → 加载 2-3 个最相关知识 |
| 跨角色交接 | 只加载交接契约 + 工件版本树，不全量传 |
| 工具调用 | 调用时不持久化结果，下次需要重新调用 |
| 长文档引用 | 只加载相关章节（如"读 PRD Part 7"而非"读 PRD 全文"） |

**铁律**：启动时加载知识文件**不超过 3 个**；超过则按推断阶段排序取 Top-3。

### 4.3 Compress（压缩）

**目的**：避免 context 爆炸。

| 触发条件 | 治理动作 |
|---------|---------|
| 单次对话超 20 轮 | 自动摘要前文，保留关键决策 + 丢弃过程讨论 |
| 单个工具结果超 2000 token | 截断展示 + 链接全文 |
| 单个工件超 500 行 | 引用路径，不内联全文 |
| 任务结束 | 写入 memory 的内容不超过 200 行 |

**摘要模板**：保留 ① 决策结论 ② 关键路径 ③ 待办事项；丢弃 ① 过程讨论 ② 重复确认 ③ 失败尝试。

### 4.4 Isolate（隔离）

**目的**：多智能体拆分上下文窗口，避免污染。

| 场景 | 隔离方式 |
|------|---------|
| 跨角色协作 | 每角色/工具独立 context |
| Plan Mode 探索 | 用 subagent 隔离，探索失败不影响主 context |
| 跨项目的 preferences | 项目级 memory 与全局 preferences 严格分离 |
| 工件演化层 | 不同阶段的 Loop 记录彼此隔离，按需读取 |

**铁律**：交接元数据**精简**为交接契约 + 工件版本树，**不全量传**原 context。

## 五、Layer 作为落地形态（不是独立原则）

四原则落地的物理分层形态：

| 层 | 性质 | 本体系位置 |
|----|------|-----------|
| **system 层** | 静态、所有项目共享 | skill.md YAML 头 + 核心规则节 |
| **memory 层** | 动态、按项目/用户加载 | `memory/preferences.md` + 项目 `MEMORY.md` |
| **artifact 层** | 工件演化、按需 Select | `项目文档/{项目}/` + 工件版本树 |
| **tool 层** | 工具描述 + MCP | skill.md tools 节 + MCP servers |

**铁律**：禁止混层。例如把项目细节写入静态层（动态入静态）、把工具描述写入 memory（外设入内存）都是错的。

## 六、上下文窗口治理规则（汇总）

| 触发条件 | 治理动作 | 关联原则 |
|---------|---------|---------|
| 启动加载知识 | ≤ 3 个知识文件 | Select |
| 单次对话 > 20 轮 | 自动摘要 | Compress |
| 单个工具结果 > 2000 token | 截断 + 链接 | Compress |
| 单个工件 > 500 行 | 引用路径 | Compress |
| 任务结束写 memory | ≤ 200 行 | Compress |
| 跨角色交接 | 精简为交接契约 | Isolate |
| 启动扫描项目 | 推断阶段 → Top-3 知识 | Select |
| 工具调用结果 | 不持久化 | Layer（落地形态） |
| 偏好/项目决策 | 严格分层写入 | Layer（落地形态） + Write |
