## 组合场景

常见的需求往往涉及多个技能组合，以下为典型组合模式：

| 场景 | 技能组合 | 执行顺序 |
|------|----------|----------|
| 技术评估 | `brainstorming` → 输出 Markdown | 先发散再收敛 |
| 客户演示 PPT | `web-access`（调研）→ `pptx` | 先采集再制作 |
| 竞品分析报告 | `web-access` → `docx` | 先搜索再输出 |
| 项目启动全套 | `write-a-prd` → `ai-product-dev-kit-modular` → `project-manager` | PRD → Demo → 项目管理 |
| 标注需求 | `ai-product-dev-kit-modular` → `prd-notes` | Demo → 标注 |
| 需求评审材料 | `write-a-prd` → `ai-product-dev-kit-modular` → `pptx` | PRD → Demo → 汇报 |
| 培训文档 | `web-access`（资料）→ `docx` 或 `pptx` | 采集→输出 |

### 组合执行原则

1. **顺序执行**：有依赖关系的技能按顺序执行
2. **上下文传递**：前一个技能的产出作为后一个技能的输入
3. **用户确认**：每个技能执行完成后，确认产出再进入下一个
4. **格式转换放最后**：`docx`/`xlsx`/`pptx` 等格式转换技能放在最后一步

## 意图识别流程

```
用户输入
  ├─ 匹配专用工作流关键词？
  │   ├─ 是 → 转交专用工作流
  │   └─ 否 ↓
  ├─ 匹配通用技能路由表？
  │   ├─ 是 → 调用对应技能
  │   └─ 否 ↓
  ├─ 是否为组合场景？
  │   ├─ 是 → 按组合模式依次执行
  │   └─ 否 ↓
  └─ 无法识别 → 询问用户具体需求
```

## 无法识别时的引导话术

当无法匹配到任何技能或工作流时，向用户询问：

> 请问你具体想做什么？我可以帮你：
> 1. 写 PRD / 产品需求文档
> 2. 做 Demo 原型页面
> 3. 项目管理（WBS / 甘特图 / 风险管理）
> 4. 写 Word 文档 / 方案报告
> 5. 做 PPT 演示材料
> 6. 处理 Excel 表格
> 7. 搜索资料 / 联网查询
> 8. 做前端页面设计
> 9. 其他（请描述）

## 注意事项

1. **不猜意图**：关键词不明确时直接问用户，不自行假设
2. **不重复调用**：同一技能在同一次对话中不要重复调用
3. **技能是黑盒**：调用技能后让技能自主执行，不干预内部逻辑
4. **产出归档**：每次技能执行完成后，提醒归档到项目目录
5. **更新记忆**：完成交付物后更新 `memory/projects.md`
