# PRD 编写工作流

> 本文件描述如何编排现有技能完成 PRD 编写任务。不重复技能内部逻辑，仅定义调用时机、衔接方式和质量检查点。

## 依赖技能

| 技能 | 用途 |
|------|------|
| `write-a-prd` | PRD 编写主技能（4 种方式） |
| `ai-product-dev-kit-modular` | Stage 1.5 调用 PRD 编写；方法 1 产出可转 12 部分中文 PRD |
| `prd-notes`（ai-product-dev-kit-modular 子模块） | 页面标注与 PRD 关联 |
| `project-manager` | PRD 完成后可启动项目管理 |

---

## 工作流步骤

### Step 1：触发与调用

**触发条件**：用户说「写 PRD」「需求文档」「产品需求」「PRD」等关键词。

**动作**：调用 `write-a-prd` 技能。

```
调用方式：Skill("write-a-prd")
```

**特殊入口**：当从 `ai-product-dev-kit-modular` Stage 1.5 进入时，技能已掌握项目上下文，可能直接跳到方法 1 的步骤 4（模块设计），无需重复问题描述和代码探索。

---

### Step 2：技能自主执行（不干预）

`write-a-prd` 技能会引导用户选择编写方式，然后自主执行。**本工作流不干预技能内部流程**。

技能提供 4 种编写方式：

| 方式 | 流程 | 产出格式 |
|------|------|----------|
| **方式 1：互动访谈** | 问题描述 → 代码探索 → 深度访谈 → 模块设计 → GitHub Issue | GitHub Issue |
| **方式 2：模板快填** | 直接使用 12 部分模板填写 | Markdown 12 部分 |
| **方式 3：HTML 逆向** | 从现有 HTML 页面反向推导 PRD | Markdown 12 部分 |
| **方式 4：导入改写** | 导入已有文档，改写为标准 PRD | Markdown 12 部分 |

**方式 1 详细步骤**（技能内部）：
1. 问题描述 — 用户描述要解决什么问题
2. 代码探索 — 如有代码库，分析现有架构
3. 深度访谈 — 逐模块追问需求细节
4. 模块设计 — 确定模块划分和功能点
5. 输出 GitHub Issue

**方式 2/3/4** 直接使用 12 部分标准模板：
- Part 1：文档信息
- Part 2：产品概述
- Part 3：范围与优先级
- Part 4：使用场景
- Part 5：角色与权限
- Part 6：业务流程
- **Part 7：模块详细设计（核心）**
- Part 8：数据模型
- Part 9：API 设计
- Part 10：非功能性需求
- Part 11：验收标准
- Part 12：版本路线图

---

### Step 3：产出质量检查

技能输出完成后，对 **Part 7 模块详细设计** 进行深度检查：

#### Part 7 质量标准（每个 P0 功能点必须满足）

| 维度 | 最低要求 | 检查方式 |
|------|----------|----------|
| 输入输出表 | >= 3 个字段 | 数字段条目 |
| 数据流向 | >= 3 个步骤 | 数流向步骤 |
| 业务规则 | >= 3 条（BR-XXX 编号） | 数规则条目 |
| 异常处理 | >= 3 种场景 | 数异常类型 |
| 状态定义 | 包含状态机或状态列表 | 检查是否存在 |

**检查不通过时**：提示用户补充缺失维度，不要自行编造内容。

#### 其他部分快速检查

- Part 3：P0/P1/P2 优先级是否明确
- Part 5：角色是否覆盖所有使用场景
- Part 6：是否有至少 1 个核心流程图（Mermaid）
- Part 12：版本规划是否与 Part 3 优先级对应

---

### Step 4：格式转换（按需）

| 场景 | 动作 |
|------|------|
| 方式 1 产出 GitHub Issue，需要中文 PRD | 通过 `ai-product-dev-kit-modular` Stage 1.5 转换为 12 部分中文 Markdown |
| 需要 Word 格式交付 | 调用 `docx` 技能转换为 .docx |
| 需要飞书文档 | 调用 `lark-mcp` 导入为飞书文档 |

---

### Step 5：后续衔接（可选）

产出完成后，向用户建议可选的后续步骤：

| 后续动作 | 调用技能 | 说明 |
|----------|----------|------|
| 制作 Demo 原型 | `ai-product-dev-kit-modular` | 选择开发路径 A（PR→Demo）或 D（PRD only） |
| 页面标注 | `prd-notes`（Workflow A） | 为 Demo 页面添加标注关联 |
| 启动项目管理 | `project-manager` | 基于 PRD 创建 WBS 和排期 |
| 竞品分析 | 联网搜索 | 补充 Part 2 竞品信息 |

---

### Step 6：归档

将产出物归档到项目目录：

```
{项目目录}/
├── 项目文档/
│   └── PRD.md              （或 PRD-{version}.md）
├── 项目文档/项目管理/        （如启动了项目管理）
└── memory/
    └── projects.md          （更新项目状态）
```

更新 `memory/projects.md`：
- 记录 PRD 完成状态
- 记录选用的编写方式
- 记录关键决策（模块划分、优先级判断依据）

---

## 决策速查

```
用户要写 PRD
  ├─ 有代码库 + 需要深度分析 → 方式 1（互动访谈）
  ├─ 新项目 + 需求清晰 → 方式 2（模板快填）
  ├─ 有现有 Demo/页面 → 方式 3（HTML 逆向）
  └─ 有旧文档/竞品文档 → 方式 4（导入改写）

从 ai-product-dev-kit 进入 → 跳到方式 1 步骤 4

产出后检查 Part 7 → 不通过则提示补充 → 通过则归档
```
