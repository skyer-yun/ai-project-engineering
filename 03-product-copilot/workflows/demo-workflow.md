# Demo 原型开发工作流

> 本文件描述如何编排 ai-product-dev-kit-modular 技能完成 Demo 原型开发任务。不重复技能内部逻辑，仅定义调用时机、阶段衔接和质量检查点。

## 依赖技能

| 技能 | 用途 |
|------|------|
| `ai-product-dev-kit-modular` | Demo 开发主技能（5 阶段 + Stage 1.5） |
| `write-a-prd` | Stage 1.5 PRD 编写（4 种方式） |
| `prd-notes`（ai-product-dev-kit-modular 子模块） | 页面标注与 PRD 关联 |
| `project-manager` | 基于 Demo 产出启动项目管理 |
| `docx` / `xlsx` | 格式转换（按需） |

---

## 技能阶段概览

```
Stage 1（需求收集）
  → Stage 1.5（PRD 编写，可选）
    → Stage 2（原型生成）
      → Stage 3（迭代修改）
        → Stage 4（交付打包）
          → Stage 5（校验验证）
```

### 4 条开发路径

| 路径 | 流程 | 适用场景 |
|------|------|----------|
| **A：PR→Demo** | 需求 → PRD → Demo → 标注 → 交付 | 新项目，需要完整文档 |
| **B：Demo→PRD** | 需求 → Demo → PRD → 标注 → 交付 | 快速验证，先出原型 |
| **C：仅 Demo** | 需求 → Demo → 交付 | 纯演示，不需要 PRD |
| **D：仅 PRD** | 需求 → PRD → 交付 | 只需文档，不出原型 |

---

## 工作流步骤

### Step 1：触发与调用

**触发条件**：用户说「做 Demo」「原型」「页面」「产品开发」「前端 Demo」等关键词。

**动作**：调用 `ai-product-dev-kit-modular` 技能。

```
调用方式：Skill("ai-product-dev-kit-modular")
```

---

### Step 2：Stage 1 需求收集（技能自主执行）

技能进入 Stage 1，引导用户完成需求收集。**本工作流不干预技能内部流程**。

技能内部步骤：

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1.0 | 确定项目类型 | 项目类型标识 |
| 1.1 | 收集基本信息 | 项目名称/背景/目标 |
| 1.2 | 扩展信息收集 | 技术偏好/设计系统/约束 |
| 1.3 | 页面树 YAML | `page-tree.yaml` |
| - 步骤 2 | 澄清与确认 | 确认后的页面树 |
| - 步骤 3 | 功能清单 | P0/P1/P2 功能列表 |
| - 步骤 4 | 选择开发路径 | A/B/C/D |

**关键决策点**：步骤 4 用户选择开发路径，决定后续流程走向。

---

### Step 3：Stage 1.5 PRD 编写（按路径触发）

根据用户选择的开发路径决定是否执行：

| 路径 | 是否执行 Stage 1.5 | 方式 |
|------|---------------------|------|
| A（PR→Demo） | **执行** | 4 种方式可选 |
| B（Demo→PRD） | **跳过**，Stage 2 完成后再写 PRD | - |
| C（仅 Demo） | **跳过** | - |
| D（仅 PRD） | **执行** | 转为纯 PRD 编写流程 |

Stage 1.5 的 4 种 PRD 编写方式：
1. **write-a-prd 技能**：调用独立技能，互动访谈方式
2. **HTML 逆向**：从现有 HTML 推导 PRD
3. **内置 12 部分**：直接使用模板填写
4. **导入**：导入已有文档改写

如选择方式 1，流程衔接至 `prd-workflow.md`。

---

### Step 4：Stage 2 原型生成（技能自主执行）

技能自动执行原型生成。**不干预**。

技能内部步骤：

| 步骤 | 内容 |
|------|------|
| 步骤 0 | 设计策略选择（5 种选项） |
| 步骤 1 | 生成多文件 Demo（pages/{模块目录}/*.html + shared/ + index.html） |
| 步骤 2 | 质量检查（11 项检查清单） |
| 步骤 3 | 提取标注数据（标注数据.json） |

产出文件结构：
```
{项目目录}/系统文件/
├── index.html                    （导航入口）
├── pages/
│   ├── 01-认证模块/
│   │   ├── 01-登录.html
│   │   └── 02-注册.html
│   ├── 02-核心模块/
│   │   ├── 01-首页.html
│   │   └── 02-详情.html
│   └── ...
├── shared/
│   ├── template.html
│   └── styles.css
项目文档/
├── 标注数据.json
└── PRD.md（如果路径 A/D）
```

---

### Step 5：Stage 3 迭代修改（按需循环）

用户可反复要求修改单个页面，技能独立处理每个页面的修改。

**常见迭代场景**：
- 调整某个页面的布局
- 修改组件样式
- 增删功能点
- 修改导航结构

每次修改后技能会更新对应页面文件和标注数据。

---

### Step 6：Stage 4 交付打包

技能执行交付打包，分三个子阶段：

| 子阶段 | 内容 | 前置依赖 |
|--------|------|----------|
| **4A 源文件** | 13 个必选交付物检查 | 无 |
| **4B 合成** | 单文件版/集成版/标注版合成 | **依赖检查**：需先满足 4A 产物完整性 |
| **4C 格式转换** | 按需转换为其他格式 | 4B 完成 |

**4B 合成的依赖检查**（v3.3 机制）：
- 技能会自动检查所需产物是否齐全
- 不满足时引导用户先完成缺失产物
- 不跳过检查直接合成

---

### Step 7：Stage 5 校验验证

技能调用 `verify_products.py` 进行 4 维度差异检查：

1. **功能清单对比**：PRD vs Demo 功能覆盖
2. **字段对比**：PRD 字段 vs Demo 表单字段
3. **状态流转对比**：PRD 状态机 vs Demo 页面状态
4. **交互行为对比**：PRD 交互描述 vs Demo 实际行为

---

### Step 8：标注衔接（按路径触发）

| 路径 | 标注动作 | 调用方式 |
|------|----------|----------|
| A（PR→Demo） | 初始化标注（Workflow A） | `prd-notes` 初始化 |
| B（Demo→PRD） | 更新标注（Workflow B） | PRD 完成后 `prd-notes` 更新 |
| C（仅 Demo） | 不做标注 | - |
| D（仅 PRD） | 不做标注 | - |

---

### Step 9：归档

将产出物归档：

```
{项目目录}/
├── 系统文件/
│   ├── index.html
│   ├── pages/
│   └── shared/
├── 项目文档/
│   ├── PRD.md
│   └── 标注数据.json
├── 流程图/源代码/          （如有 Mermaid 甘特图）
└── memory/
    └── projects.md
```

更新 `memory/projects.md`：
- 记录选用的开发路径（A/B/C/D）
- 记录设计策略选择
- 记录页面树结构
- 记录迭代轮次和关键修改

---

## 决策速查

```
用户要做 Demo
  → 调用 ai-product-dev-kit-modular
  → Stage 1 收集需求
  → 步骤 4 选路径
    ├─ A → Stage 1.5(PRD) → Stage 2(Demo) → 标注
    ├─ B → Stage 2(Demo) → Stage 1.5(PRD) → 标注
    ├─ C → Stage 2(Demo) → 交付
    └─ D → Stage 1.5(PRD) → 交付
  → Stage 3 迭代（按需循环）
  → Stage 4 交付（4A→4B→4C，含依赖检查）
  → Stage 5 校验
  → 归档
```

## 与其他工作流的衔接

| 当前阶段完成 | 可衔接工作流 |
|---------------|--------------|
| Stage 1.5 PRD 完成 | `project-management-workflow.md`（启动项目管理） |
| Stage 2 Demo 完成 | `prd-workflow.md`（路径 B 需写 PRD） |
| 全部交付完成 | `docx`/`xlsx`（格式转换）、`pptx`（汇报材料） |
