# ai-project-engineering

> **方法论**：五阶段（需求 / 设计 / 开发 / 交付 / 复盘）× Loop 微循环 × HITL 分级 × 工具中立
>
> **核心承诺**：用大家熟悉的"需求→设计→开发→测试部署→复盘"流程语言，叠加 AI 协作的 Loop 微循环、HITL 分级、阶段契约机制。不绑定任何具体 AI 工具——Claude Code、Codex、Cursor、用户自研 Agent 都能接入。
>
> **目标**：让售前 / 产品 / 架构 / 研发 / 测试 / 交付 / PM 各工种的 AI 协作像「接力赛」一样可追溯、可回滚、可度量。

## 五阶段速查

| 阶段 | 使命 | 主责工种 | HITL 模式 | 出口 QG |
|------|------|---------|-----------|---------|
| **需求** | 商机/痛点 → 结构化需求共识 | 售前 + 产品 | **In**（L3 共识不可逆） | QG-需求 |
| **设计** | PRD / 架构 / 详细设计 | 产品 + 架构师 + 研发 | **In**（L3 方案不可逆） | QG-设计 |
| **开发** | 编码 / 审查 / 联调 | 研发 + 测试 | **In + Fallback**（L2 可逆） | QG-开发 |
| **交付** | 测试 → 部署 → 验收 → 培训 | 测试 + 交付 | **In**（L4 生产/验收不可逆） | QG-交付 |
| **复盘** | 项目复盘 / 经验沉淀 | 项目经理 + 全员 | **In**（L3 复盘共识） | —（终态） |

> 每阶段内嵌 Loop 微循环：**Plan → Act → Observe → Reflect → Exit**，跑到满足出口 QG 才能交接下游。
> 阶段间用 `handoff.yaml`（YAML 交接契约）传递，可追溯、可校验、可回滚。

详见 `01-标准层/01-五阶段定义.md`。

## 方法论逻辑层：5 逻辑角色（对内约束用）

> 给方法论内部和 handoff 契约用。**关键**：1 工种可跨多角色，1 角色可由多工种承担——这是逻辑抽象，不对外推广。

| 逻辑角色 | 职责 | 主要承担工种 |
|---------|------|------------|
| **需求规范师（Spec-Writer）** | 需求 → 可执行规范 | 售前 + 产品 |
| **构建师（Builder）** | 规范 → 代码 | 研发（含架构师） |
| **审查师（Reviewer）** | 质量守门（跨阶段） | 测试 + 研发交叉审查 |
| **交付师（Shipper）** | 测试 → 部署 → 验收 → 培训 | 测试 + 交付 |
| **统筹师（Keeper）** | 上下文 / 记忆 / 复盘 | 项目经理 |

> 对外讲工种，对内讲逻辑角色。Playbook 按工种组织，handoff 契约按逻辑角色签字。

## 快速上手（3 步）

### 第 1 步：理解方法论（30 分钟）

读 `00-理论层/01-五阶段与Loop微循环原理.md`，理解「**外环 Sprint × 中环五阶段 × 内环 Loop 5 字段**」三层嵌套模型。

### 第 2 步：找到自己的工种 Playbook（10 分钟）

`03-执行层/01-工种Playbook/` 选一份（6 工种 ↔ 5 逻辑角色），按第 1 节「触发场景」开干。

### 第 3 步：选适配方案（5 分钟）

按 [05-适配层/README.md](./05-适配层/README.md) 的决策树选工具：

```bash
./install.sh --adapter claude-code   # Claude Code（参考实现就绪）
./install.sh --adapter codex         # Codex（生成 AGENTS.md）
./install.sh --adapter cursor        # Cursor（生成 .cursorrules）
./install.sh --adapter custom        # 自带工具（部署模板+schema）
./install.sh --templates-only        # 仅产物层模板
./install.sh --tools                 # 部署 snapshot/rollback/validate-handoff
./install.sh --check-neutral         # 工具中立性校验
```

## 核心设计原则

| 原则 | 含义 |
|------|------|
| **说人话** | 用业界熟悉的"需求/设计/开发/交付/复盘"语言，不造新词 |
| **保留先进内核** | Loop 微循环 + HITL 分级 + YAML 契约 + 工具中立 |
| **工种驱动** | Playbook 按售前/产品/研发/测试/交付/PM 真实岗位组织 |
| **工具中立** | 体系只定义契约（产物/Schema/HITL/QG），不绑定具体 AI 工具 |
| **契约下沉** | HITL/Eval/QG 写进标准层，所有工具通过适配层接入 |
| **单一权威源** | 每个概念只在 01-标准层 定义一次，其他位置一律引用 |
| **HITL 不可逆分级** | L1-L4 等级，L3/L4 强制人审（In 模式） |
| **上下文工程四原则** | Anthropic 2025-09 官方四原则（Write/Select/Compress/Isolate） |
