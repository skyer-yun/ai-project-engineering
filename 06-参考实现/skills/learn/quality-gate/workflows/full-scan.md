# Full Scan Workflow

> 全量门禁扫描流程

## Stage 1: 检测项目阶段

```
扫描项目目录 → 检测已有产物：
  01-需求/ 有产物 → 至少过了 需求阶段（理解+分析+方案）
  02-产品/ 有产物 → 至少过了 需求·确认
  03-设计/ 有产物 → 至少过了 设计阶段（PRD+原型）
  04-开发/ 有产物 → 至少过了 设计·技术设计-开发·代码审查
  05-测试/ 有产物 → 至少过了 开发末+测试
  06-交付/ 有产物 → 至少过了 交付后半

推断当前阶段 → 确定哪些门禁需要检查
```

## Stage 2: 顺序执行门禁

```
FOR each applicable gate (QG-需求 → QG-设计 → ... → QG-交付):
  1. 执行 single-gate-check 流程
  2. 记录结果
  3. IF FAIL → 可选择：停止扫描 / 继续扫描下一个
```

## Stage 3: 汇总评估

```markdown
| QG-设计 | 设计·原型→设计·技术设计 | 12 | — | — | — | 未执行 |
| QG-开发 | 开发·代码审查→开发·联调 | 8 | — | — | — | 未执行 |
| QG-交付 | 交付·测试执行→交付·部署 | 10 | — | — | — | 未执行 |
| QG-交付 | 交付·验收→交付·文档 | 8 | — | — | — | 未执行 |

总体判定：项目当前处于 阶段，QG-需求 未通过
```

## Stage 4: 建议与下一步

```
输出：
1. 当前阶段判定
2. 需要立即修复的阻塞项
3. 建议的下一步行动
4. 预计通过时间（如可估算）
```
