# 代码审查工作流

## 工作流概览

```
规范检查(1) → 安全扫描(2) → 性能审查(3) → 最佳实践(4) → 报告输出(5)
```

---

## Step 1: 规范检查

### 目标
检查代码是否符合语言编码规范，包括命名、格式、注释、结构。

### 输入
- 源代码文件（一个或多个）
- 语言类型（自动识别或手动指定）

### 处理步骤

#### 1.1 语言识别
- 根据文件扩展名识别语言
- 支持语言：Java(.java)、Python(.py)、JavaScript(.js)、TypeScript(.ts)、Go(.go)
- 无法识别时提示用户手动指定

#### 1.2 命名规范检查

**Java**：
- 类名：PascalCase（`UserService`）
- 方法名：camelCase（`getUserById`）
- 常量：UPPER_SNAKE_CASE（`MAX_RETRY_COUNT`）
- 包名：全小写（`com.example.service`）
- 布尔变量：is/has/should 前缀（`isActive`）

**Python**：
- 类名：PascalCase（`UserService`）
- 函数/方法：snake_case（`get_user_by_id`）
- 常量：UPPER_SNAKE_CASE（`MAX_RETRY_COUNT`）
- 模块名：snake_case（`user_service`）
- 私有方法：单下划线前缀（`_internal_method`）

**JavaScript/TypeScript**：
- 类名：PascalCase（`UserService`）
- 函数/方法：camelCase（`getUserById`）
- 常量：UPPER_SNAKE_CASE 或 camelCase（`MAX_RETRY` 或 `maxRetry`）
- 文件名：camelCase 或 kebab-case
- 接口：I 前缀可选（`UserService` 或 `IUserService`）
- 枚举：PascalCase（`enum UserRole`）

**Go**：
- 导出标识符：PascalCase（`UserService`）
- 非导出标识符：camelCase（`userService`）
- 常量：camelCase 或 PascalCase
- 接口：-er 后缀（`Reader`、`Writer`）
- 包名：简短全小写（`service`）

#### 1.3 格式规范检查
- 缩进一致性（空格 vs Tab）
- 行长度限制（Java 120、Python 88/120、JS 100/120、Go 无限制 gofmt 处理）
- 空行使用（方法间、逻辑段落间）
- 括号风格（K&R、Allman 等）

#### 1.4 注释规范检查
- 类/接口级别的文档注释
- 公共方法的文档注释（参数、返回值、异常）
- 复杂逻辑的行内注释
- TODO/FIXME/HACK 标记的规范性
- 过时注释的识别

### 输出
- 规范问题清单（S3/S4 级别为主）

## Step 2: 安全扫描

### 目标
识别代码中的安全漏洞，覆盖 OWASP Top 10 和常见安全风险。

### 输入
- 源代码文件

### 处理步骤

#### 2.1 OWASP Top 10 检查

**A01 - 权限控制失效**
- 检查是否缺少权限验证注解/中间件
- 检查是否存在越权访问风险（水平/垂直越权）
- 检查是否有硬编码的角色判断
- 检查 CORS 配置是否过于宽松

**A02 - 加密机制失效**
- 检查是否使用弱加密算法（MD5、SHA1、DES）
- 检查是否硬编码密钥/证书
- 检查 HTTPS 是否正确配置
- 检查随机数生成器是否安全（`Math.random` vs `crypto.randomBytes`）

**A03 - 注入攻击**
- 检查 SQL 拼接（`"SELECT * FROM " + table + " WHERE id = " + id`）
- 检查命令注入（`Runtime.exec`、`os.system`、`exec`）
- 检查 LDAP 注入
- 检查 XML 外部实体注入（XXE）
- 检查模板注入（SSTI）

**A04 - 不安全设计**
- 检查是否缺少速率限制
- 检查是否缺少输入验证
- 检查业务逻辑是否存在竞态条件
- 检查是否有不安全的默认配置

**A05 - 安全配置错误**
- 检查调试模式是否关闭
- 检查错误信息是否暴露敏感信息
- 检查不必要的功能/端口是否开放
- 检查默认密码是否修改

**A06 - 脆弱过时组件**
- 检查已知有漏洞的依赖版本
- 检查未使用的依赖
- 检查依赖版本是否锁定

**A07 - 身份认证失败**
- 检查密码存储方式（明文/弱哈希/强哈希+盐）
- 检查 Session 管理是否安全
- 检查 JWT 实现是否正确
- 检查多因素认证是否需要

**A08 - 数据完整性失效**
- 检查反序列化是否安全
- 检查 CI/CD 管道安全
- 检查客户端数据验证

**A09 - 日志监控不足**
- 检查敏感操作是否有日志记录
- 检查日志是否包含敏感信息
- 检查异常是否被正确捕获和记录

**A10 - 服务端请求伪造（SSRF）**
- 检查 URL 输入是否经过验证
- 检查内部服务调用是否安全
- 检查白名单机制

#### 2.2 敏感信息检查
- 硬编码密码/密钥/Token
- 配置文件中的明文凭据
- 日志中的敏感信息输出
- 错误堆栈中的敏感路径

### 输出
- 安全问题清单（S1/S2 级别为主）
- 安全问题必须附带修复方案

---

## Step 3: 性能审查

### 目标
识别代码中的性能瓶颈和资源浪费问题。

### 输入
- 源代码文件

### 处理步骤

#### 3.1 算法复杂度检查
- 循环嵌套深度（O(n^2)、O(n^3) 等）
- 不必要的全量遍历
- 递归深度和栈溢出风险
- 排序算法选择是否合理

#### 3.2 数据库性能检查
- N+1 查询问题
- 缺少索引的查询条件
- 大批量数据的全量加载
- 事务范围是否合理
- 连接池配置
- 慢 SQL 风险

#### 3.3 内存管理检查
- 大对象的频繁创建
- 内存泄漏风险（未关闭的资源、缓存无限增长）
- 不必要的数据拷贝
- 集合类型选择是否合理

#### 3.4 并发性能检查
- 锁的粒度是否合理
- 是否存在死锁风险
- 线程池配置是否合理
- 异步操作是否正确使用

#### 3.5 I/O 性能检查
- 文件操作是否使用缓冲
- 网络请求是否有超时设置
- 是否有不必要的同步等待
- 批量操作是否合并

### 输出
- 性能问题清单（S2/S3 级别为主）

---

## Step 4: 最佳实践

### 目标
从设计模式和编码最佳实践角度给出改进建议。

### 输入
- 源代码文件

### 处理步骤

#### 4.1 SOLID 原则检查
- **单一职责（SRP）**：类/方法是否职责单一
- **开闭原则（OCP）**：是否通过扩展而非修改来增加功能
- **里氏替换（LSP）**：子类是否可以安全替换父类
- **接口隔离（ISP）**：接口是否精简、不强迫实现不需要的方法
- **依赖反转（DIP）**：是否依赖抽象而非具体实现

#### 4.2 设计模式检查
- 是否存在可以用设计模式简化的代码
- 已使用的设计模式是否正确
- 工厂模式、策略模式、观察者模式等常见模式的合理使用

#### 4.3 错误处理检查
- 异常是否被正确捕获和处理
- 是否有空 catch 块
- 错误信息是否有意义
- 是否使用自定义异常区分错误类型
- 资源释放是否在 finally/using 中处理

#### 4.4 可测试性检查
- 代码是否便于单元测试
- 依赖是否可注入/可 Mock
- 方法是否有副作用
- 是否便于集成测试

#### 4.5 可维护性检查
- 方法长度是否合理（建议 < 30 行）
- 类长度是否合理（建议 < 300 行）
- 参数数量是否合理（建议 < 5 个）
- 嵌套深度是否合理（建议 < 4 层）
- 魔法数字/字符串是否提取为常量

### 输出
- 改进建议清单（S3/S4 级别为主）

---

## Step 5: 报告输出

### 目标
汇总所有审查结果，输出结构化的审查报告。

### 输入
- 规范问题清单
- 安全问题清单
- 性能问题清单
- 最佳实践建议清单

### 处理步骤
1. 合并所有问题清单
2. 按严重等级排序（S1 > S2 > S3 > S4）
3. 同类问题合并去重
4. 为每个问题生成：
   - 问题描述
   - 严重等级
   - 代码位置（文件名 + 行号）
   - 修改建议
   - 修改后的代码示例（S1/S2 必须）
5. 生成审查摘要统计

### 输出
- 代码审查报告
