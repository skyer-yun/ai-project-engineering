# Workflow: 架构设计（Architecture Design）

5个阶段：需求分析 → 模式选择 → 模块设计 → 技术选型 → 文档生成。

输出7章架构设计文档。

---

## Stage 1: 需求分析（Requirement Analysis）

### 输入
- PRD 文档或需求描述
- 非功能需求（性能/安全/可用性）
- 技术约束（团队/成本/时间）

### 处理步骤
1. 提取功能模块和业务流程
2. 识别非功能需求（QPS/延迟/并发/可用性）
3. 梳理技术约束和边界条件
4. 识别关键架构决策点

### 输出
- 需求摘要（功能模块列表）
- 非功能需求指标
- 约束条件清单
- 关键决策点列表

---

## Stage 2: 模式选择（Pattern Selection）

### 输入
- Stage 1 的需求分析结果

### 处理步骤
1. 根据系统特征匹配架构模式
2. 如有 brainstorming，发散 2-3 个候选方案
3. 对比候选方案的优劣
4. 推荐最佳方案并说明理由

### 架构模式匹配指南

| 系统特征 | 推荐模式 | 原因 |
|----------|----------|------|
| 小型项目/快速验证 | 单体架构 | 开发效率高、部署简单 |
| 大型系统/独立团队 | 微服务架构 | 独立部署、技术异构 |
| 事件驱动/弹性需求 | Serverless | 按需付费、自动伸缩 |
| 异步处理/系统解耦 | 事件驱动 | 松耦合、可扩展 |
| 企业应用/清晰分层 | 分层架构 | 职责清晰、易维护 |
| 领域驱动/高可测试 | 六边形架构 | 业务与技术解耦 |

### 输出
- 推荐架构模式及理由
- 候选方案对比（如有）
- 架构决策记录（ADR）

---

## Stage 3: 模块设计（Module Design）

### 输入
- 功能模块列表
- 选定的架构模式

### 处理步骤
1. 根据架构模式划分模块
2. 定义模块职责和边界
3. 设计模块间接口
4. 绘制模块依赖关系图

### 设计原则
- 高内聚：相关功能聚合在同一模块
- 低耦合：模块间通过接口通信
- 单一职责：每个模块只负责一类功能
- 可独立部署：模块可独立开发、测试、部署（微服务时）

### 输出
- 模块划分方案
- 模块职责说明
- 接口定义（API 概要）
- 依赖关系图

---

## Stage 4: 技术选型（Tech Selection）

### 输入
- 模块设计结果
- 技术约束条件

### 处理步骤
1. 确定各层技术栈候选
2. 评估候选方案（成熟度/社区/性能/团队匹配）
3. 如有 web-access，查询最新版本信息
4. 做出选型决策

### 选型维度

| 层级 | 候选项 | 评估维度 |
|------|--------|----------|
| 前端 | React/Vue/Angular | 生态/团队/性能 |
| 后端 | Java/Go/Node/Python | 性能/生态/团队 |
| 数据库 | MySQL/PostgreSQL/MongoDB/Redis | 数据模型/性能/成本 |
| 消息队列 | Kafka/RabbitMQ/RocketMQ | 吞吐/延迟/可靠性 |
| 部署 | Docker/K8s/Serverless | 复杂度/成本/弹性 |
| 监控 | Prometheus/Grafana/ELK | 覆盖度/易用性 |

### 输出
- 技术选型清单
- 选型决策记录（ADR）
- 技术风险说明

---

## Stage 5: 文档生成（Document Generation）

### 7章文档模板

#### 第1章：架构概述
- 系统定位和目标
- 架构设计范围
- 读者对象
- 术语定义

#### 第2章：架构原则
- 设计原则（5-8条）
- 每条原则的适用说明
- 原则间的权衡关系

#### 第3章：技术选型
- 各层技术选型清单
- 选型对比分析
- 选型决策记录（ADR）

#### 第4章：模块设计
- 模块划分和职责
- 模块依赖关系图
- 核心模块详细设计
- 接口定义

#### 第5章：数据架构
- 数据模型设计
- 存储方案
- 数据流向图
- 数据治理策略

#### 第6章：部署架构
- 部署拓扑图
- 环境规划
- 资源配置
- 弹性伸缩方案

#### 第7章：安全架构
- 安全架构图
- 认证授权方案
- 数据安全策略
- 安全审计方案

### 输出
- 完整的架构设计文档（Markdown/DOCX）
- 架构图（Mermaid/PlantUML）
- 文件命名：`{项目名}-架构设计文档-v{版本}.md`
