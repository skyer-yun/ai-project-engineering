# 测试用例模板

> 功能用例、API 用例、追溯矩阵、覆盖率报告的标准模板 + 编号/优先级/缺陷分级规则

---

## 1. 功能测试用例模板

### 简表格式

```
| 用例ID | 模块 | 用例标题 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 设计方法 | 需求追溯 |
|--------|------|---------|---------|---------|---------|--------|---------|---------|
| TC-AUTH-001 | 认证 | 正常手机号登录 | 已注册账号 | 输入手机号→获取验证码→输入→点击登录 | 登录成功跳转首页 | P0 | 等价类 | REQ-001 |
```

### 详细格式

```
## TC-{模块}-{序号}: {用例标题}

### 基本信息
- 优先级：P0/P1/P2/P3
- 设计方法：等价类/边界值/场景法/判定表/正交实验/状态迁移
- 关联需求：REQ-{N}
- 前置条件：{环境、数据、状态}

### 测试步骤
| 步骤 | 操作 | 输入数据 | 预期结果 |
|------|------|---------|---------|
| 1 | {操作描述} | {输入数据} | {预期} |
| 2 | {操作描述} | {输入数据} | {预期} |

### 测试数据
| 数据项 | 值 | 说明 |
|--------|-----|------|
| {字段} | {值} | 边界值/等价类代表值 |
```

## 3. 需求追溯矩阵

```
| 需求编号 | 需求描述 | 优先级 | 关联用例 | 覆盖状态 | 备注 |
|---------|---------|--------|---------|---------|------|
| REQ-001 | 手机号登录 | P0 | TC-AUTH-001, TC-AUTH-002 | 已覆盖 | |
| REQ-002 | 密码找回 | P1 | — | 未覆盖 | 待生成 |
```

覆盖率 = 已覆盖需求 / 总需求 * 100%

## 5. 用例编号规则

```
格式：TC-{类型}-{模块缩写}-{三位序号}

类型前缀（可选）：
  (默认) - 功能测试
  API    - 接口测试
  PERF   - 性能测试
  SEC    - 安全测试

模块缩写示例：
  AUTH  - 认证模块
  USER  - 用户管理
  ORDER - 订单模块
  PAY   - 支付模块
  ADMIN - 管理后台

示例：
  TC-AUTH-001      功能：正常手机号登录
  TC-API-AUTH-001  接口：POST /api/login 正常登录
  TC-PERF-ORDER-001 性能：订单列表查询响应时间
```

---

## 6. 优先级分配规则

| 优先级 | 定义 | 覆盖率目标 | 分配标准 |
|--------|------|-----------|---------|
| P0 | 核心功能，阻塞性 | 100% | 主流程、关键业务路径、资金/安全相关 |
| P1 | 重要功能，影响大 | >= 95% | 核心功能异常场景、主要交互、数据一致性 |
| P2 | 一般功能，可容忍 | >= 80% | 辅助功能、非核心路径、体验优化 |
| P3 | 轻微问题，低影响 | >= 60% | UI 细节、文案、边缘场景、优化建议 |

---

## 7. 缺陷严重度标准

| 级别 | 定义 | 响应时间 | 修复时限 | 示例 |
|------|------|---------|---------|------|
| P0 致命 | 系统不可用/数据丢失 | 立即 | 24h | 崩溃、数据损坏、安全漏洞、资金错误 |
| P1 严重 | 核心功能不可用 | 4h | 48h | 主流程阻断、性能下降 5x+、计算错误 |
| P2 一般 | 非核心功能异常 | 24h | 本迭代 | 体验问题、显示异常、非关键数据不一致 |
| P3 轻微 | UI/文案瑕疵 | 下版本 | 下版本 | 样式偏差、错别字、优化建议 |
