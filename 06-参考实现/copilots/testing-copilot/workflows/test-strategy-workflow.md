# 测试策略工作流

> 覆盖阶段：N11（测试策略制定）
> 对应角色：测试经理

---

## 适用场景

当项目进入测试阶段，需要制定整体测试策略和测试计划时使用。

- 项目首次进入测试阶段
- 需求变更导致测试范围调整
- 新版本/迭代需要更新测试策略
- 多模块/多系统需要协调测试

## 前置条件

```
必须：
  [x] PRD 已定稿（功能范围明确）
  [x] 技术设计已评审（接口/数据模型/架构确定）

建议：
  [ ] 接口文档已就绪
  [ ] 联调报告已完成
  [ ] 测试环境已规划
```

## 阶段

### Stage 1: 范围分析

- **输入**：PRD 文档 + 技术设计文档 + 接口文档（如有）
- **动作**：
  1. 逐模块拆解 PRD 功能点，识别测试对象
  2. 评估每个模块的风险等级（高/中/低）
  3. 确定需要的测试类型组合：
     - 功能测试（必选）
     - 性能测试（高并发/大数据量模块）
     - 安全测试（涉及权限/支付/隐私数据）
     - 兼容性测试（多端/多浏览器）
     - 接口测试（API 密集模块）
  4. 识别测试约束（时间/人力/环境）
- **输出**：测试范围说明书
  - 功能点清单（含风险等级标注）
  - 测试类型矩阵（模块 x 测试类型）
  - 约束条件说明
- **技能调用**：`brainstorming`（如已安装，用于测试场景发散）

### Stage 2: 策略制定

- **输入**：测试范围说明书 + 项目约束
- **动作**：
  1. 确定测试方法（黑盒/白盒/灰盒组合）
  2. 规划测试环境（开发/测试/预发布/生产）
  3. 选择测试工具（用例管理/缺陷跟踪/自动化/性能）
  4. 估算测试工作量（按模块 x 测试类型）
  5. 制定测试策略：
     - 优先级策略：P0 全覆盖 → P1 核心覆盖 → P2 抽样
     - 回归策略：全量回归 / 增量回归 / 精准回归
     - 自动化策略：冒烟自动化 / 接口自动化 / UI 自动化
- **输出**：测试策略文档
  - 测试方法说明
  - 环境规划
  - 工具选型
  - 工作量估算
  - 优先级策略
  - 回归策略
  - 自动化策略

### Stage 3: 计划输出

- **输入**：测试策略文档
- **动作**：
  1. 制定测试里程碑（与开发里程碑对齐）
  2. 分配测试任务（按模块/类型）
  3. 定义准入准出标准：
     - 准入：代码冻结 + 冒烟通过 + 环境就绪
     - 准出：用例 100% 执行 + P0/P1 清零 + 覆盖率达标
  4. 规划风险应对措施
  5. 输出最终测试计划
- **输出**：测试计划
  - 里程碑时间线
  - 任务分配表
  - 准入准出标准
  - 风险应对表
- **技能调用**：`docx`（如已安装，输出 Word 格式）或 Markdown

## 产物归档

```
项目文档/测试管理/
├── 测试范围说明书.md
├── 测试策略文档.md
└── 测试计划.md
```

## 降级策略

| 缺失资源 | 降级行为 |
|----------|----------|
| PRD 不完整 | 基于已有信息 + 用户口头补充 |
| brainstorming 未安装 | 使用内置测试范围清单 |
| docx 未安装 | 输出 Markdown 格式 |

## 评审检查点

```
测试策略评审需确认：
  [ ] 测试范围是否覆盖所有 P0/P1 功能
  [ ] 测试类型是否匹配风险等级
  [ ] 工作量估算是否合理
  [ ] 准入准出标准是否可执行
  [ ] 里程碑是否与项目整体对齐
  [ ] 风险应对措施是否充分
```
