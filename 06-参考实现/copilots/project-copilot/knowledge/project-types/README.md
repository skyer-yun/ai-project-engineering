# 项目类型速查

> 4 种项目类型的特征、输入、输出、流程差异速查

---

## [A] 产品开发

### 特征
- 从零构建新产品或系统
- 有明确的需求文档（PRD）
- 需要完整的软件生命周期
- 团队角色完整（产品/设计/开发/测试/运维）

### 输入
- PRD 或需求文档
- 客户/业务方口头需求
- 竞品分析报告（可选）
- 技术可行性评估（可选）

### 阶段路线
```
项目启动
  → 需求分析
    → 方案设计
      → [QG-需求] 质量门禁
        → 需求确认/PRD
          → 架构设计
            → 详细设计
              → [QG-设计] 质量门禁
                → 编码开发
                  → 代码审查
                    → 联调集成
                      → [QG-开发] 质量门禁
                        → 测试策略
                          → 测试执行
                            → 缺陷闭环
                              → [QG-交付] 质量门禁
                                → 部署
                                  → 验收
                                    → 交付文档
                                      → [QG-交付] 质量门禁
                                        → 结项
```

### 涉及智能体
- pre-sales-copilot（需求阶段（理解+分析+方案），如需售前支持）
- product-copilot（需求确认→设计前半）
- dev-copilot（设计后半+开发）
- testing-copilot（开发末+测试）
- delivery-copilot（交付后半）
- project-copilot（全流程协调）

### 典型周期
- 小型项目：4-8 周
- 中型项目：2-3 个月
- 大型项目：3-6 个月

### 关键风险
- 需求变更频繁
- 技术选型不当
- 资源不足或流失
- 第三方依赖延期

---

## [B] 售前/投标

### 特征
- 有明确的招标文件或客户需求
- 时间紧、竞争压力大
- 需要快速产出方案和 Demo
- 重点是客户匹配度和竞争力

### 输入
- 招标文件 / RFP
- 客户需求说明
- 竞争对手信息（如有）
- 公司资质和案例

### 阶段路线
```
项目启动（快速）
  → 需求分析
    → 方案编写
      → [QG-需求] 方案评审
        → 需求确认（方案确认）
          → 技术方案
            → 设计·原型 Demo制作
              → [QG-设计] Demo评审
                → 投标提交
                  → 评标答辩
                    → 结项
```

### 涉及智能体
- pre-sales-copilot（需求阶段（理解+分析+方案），核心）
- product-copilot（设计阶段（PRD+原型），Demo 支持）
- delivery-copilot（交付·部署，投标文档）
- project-copilot（全流程协调）

### 典型周期
- 小型投标：1-2 周
- 中型投标：2-4 周
- 大型投标：1-2 个月

### 关键风险
- 时间紧迫
- 需求理解偏差
- 方案竞争力不足
- Demo 效果不理想

---

## [C] 迭代优化

### 特征
- 基于已有系统进行改进
- 有明确的变更需求
- 重点是增量交付和回归质量
- 通常在敏捷框架下执行

### 输入
- 变更需求列表
- 用户反馈
- 数据分析报告
- 技术债务清单

### 阶段路线
```
迭代规划
  → 需求拆分
    → [QG-需求] 迭代评审
      → 编码
        → 代码审查
          → 联调
            → [QG-开发] 质量门禁
              → 回归测试策略
                → 回归测试执行
                  → 缺陷验证
                    → [QG-交付] 测试通过
                      → 发布
                        → 迭代回顾
```

### 涉及智能体
- dev-copilot（设计·技术设计-开发·代码审查，核心）
- testing-copilot（开发末+测试，回归测试）
- delivery-copilot（交付·部署，发布）
- project-copilot（迭代管理）

### 典型周期
- 单次迭代：1-2 周
- 版本发布：2-4 周

### 关键风险
- 回归测试覆盖不足
- 变更影响范围评估不准
- 技术债务积累
- 发布时间窗口受限

---

## [D] 自由规划

### 特征
- 无明确前置文档
- 灵活启动、按需调整
- 适合内部项目或探索性项目
- 重点是快速启动和持续调整

### 输入
- 用户口头描述
- 项目意向
- 无固定模板

### 阶段路线
```
根据实际情况灵活编排，可跳过不涉及的阶段。
典型路径：
  启动 → 规划 → 按需进入开发/测试/交付
```

### 涉及智能体
- 根据实际需要选择
- project-copilot（全流程管理）

### 典型周期
- 按需确定

### 关键风险
- 范围不明确
- 目标模糊
- 缺少基线对比
- 干系人期望不一致

---

## 项目类型选择决策树

```
开始
  ↓
是否有招标文件或投标需求？
  → 是 → [B] 售前/投标
  → 否 ↓

是否基于已有系统改进？
  → 是 → [C] 迭代优化
  → 否 ↓

是否有明确的PRD或需求文档？
  → 是 → [A] 产品开发
  → 否 ↓

→ [D] 自由规划（灵活启动）
```

## 项目类型对比

| 维度 | [A]产品开发 | [B]售前投标 | [C]迭代优化 | [D]自由规划 |
|------|-----------|-----------|-----------|-----------|
| 输入 | PRD | 招标文件 | 变更需求 | 口头描述 |
| 周期 | 2-6个月 | 1-4周 | 1-4周 | 按需 |
| 团队 | 完整 | 小型 | 核心 | 按需 |
| 风险 | 需求变更 | 时间紧迫 | 回归质量 | 范围模糊 |
| 核心智能体 | 全部 | pre-sales | dev+testing | project |
| 质量门禁 | QG-需求/QG-设计/QG-开发/QG-交付 | QG-需求-2 | QG-需求,3,4 | 按需 |
