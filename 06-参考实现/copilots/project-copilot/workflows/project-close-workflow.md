# 项目结项工作流

> 覆盖阶段：N16（项目结项）
> 对应角色：汇报人 + 协调员

---

## 适用场景

当项目交付物已完成，需要进行交付确认、经验总结、文档归档和项目关闭时使用。

- 项目最终验收通过后
- 项目阶段结束时
- 项目因故终止时

## 前置条件

```
必须：
  [x] 交付物已交付（QG-Ship 已通过）
  [x] 验收报告已签署

建议：
  [ ] 所有遗留问题已处理或确认
  [ ] 客户已确认满意
  [ ] 团队成员已可释放
```

## 阶段

### Stage 1: 交付确认

- **输入**：验收报告 + 交付物清单 + 合同要求
- **动作**：
  1. 检查交付物完整性
     - 对照合同/PRD 验收标准逐项核对
     - 对照交付文档清单逐项核对
     - 确认每个交付物已签收
  2. 确认验收结论
     - 验收报告已签署
     - 遗留问题已记录并确认处理计划
     - 客户满意度已收集
  3. 交付物签收
     - 生成交付确认单
     - 获取双方签字确认
- **输出**：交付确认单
  ```
  交付确认单：

  项目名称：{名称}
  交付日期：{日期}

  交付物清单：
  | 序号 | 交付物 | 交付状态 | 签收状态 |
  |------|--------|---------|---------|
  | 1 | 用户操作手册 v1.0 | 已交付 | 已签收 |
  | 2 | 运维手册 v1.0 | 已交付 | 已签收 |
  | 3 | 源码（Git Tag: v1.0.0） | 已交付 | 已签收 |
  | 4 | 验收报告 | 已签署 | — |

  遗留问题：
  | 序号 | 问题描述 | 计划完成 | 责任人 |
  |------|---------|---------|--------|

  确认签字：
    客户方：______ 日期：______
    我方：______ 日期：______
  ```

### Stage 2: 经验总结

- **输入**：项目全生命周期文档 + 团队反馈
- **动作**：
  1. 组织回顾会议
     - 邀请核心团队成员参加
     - 回顾项目全过程
  2. 总结经验教训
     - 做得好的（保持）
     - 做得不好的（改进）
     - 意外的发现（记录）
  3. 分类整理
     - 流程改进建议
     - 技术经验积累
     - 沟通协作经验
     - 风险管理经验
  4. 提炼可复用资产
     - 项目模板
     - 文档模板
     - 检查清单
     - 最佳实践
- **输出**：经验总结报告
  ```
  经验总结报告：

  项目概况：
    项目名称：{名称}
    项目周期：{开始日期} ~ {结束日期}，共 {N} 天
    团队规模：{N} 人
    实际工作量：{N} 人天（计划 {N} 人天）

  项目数据：
    计划偏差：+{N} 天（{%}）
    缺陷密度：{N} 个/功能点
    验收通过率：{%}
    客户满意度：{评分}

  做得好的：
    1. {经验1}
    2. {经验2}

  需要改进的：
    1. {改进1}
    2. {改进2}

  可复用资产：
    1. {资产1}（建议写入 memory/proposal-framework.md）
    2. {资产2}

  下次项目建议：
    1. {建议1}
    2. {建议2}
  ```

### Stage 3: 归档

- **输入**：项目全量文档
- **动作**：
  1. 整理项目文档
     - 确保文档完整性
     - 确保文档版本正确
     - 确保命名规范一致
  2. 分类归档
     ```
     项目文档/{客户名}-{项目名}/
     ├── 01-售前文档/
     │   ├── 需求确认书.md
     │   └── 技术方案.md
     ├── 02-产品文档/
     │   ├── PRD.md
     │   └── Demo/
     ├── 03-开发文档/
     │   ├── 接口文档.md
     │   └── 联调报告.md
     ├── 04-测试文档/
     │   ├── 测试策略.md
     │   ├── 测试用例.md
     │   └── 测试报告.md
     ├── 05-交付文档/
     │   ├── 用户手册.docx
     │   ├── 运维手册.docx
     │   ├── 验收报告.docx
     │   └── 培训材料.pptx
     └── 06-项目管理/
         ├── 项目章程.md
         ├── 项目计划.md
         ├── WBS.md
         ├── 甘特图.mmd
         ├── 风险登记册.md
         ├── 周报/
         ├── 变更记录.md
         ├── 交付确认单.md
         └── 经验总结.md
     ```
  3. 知识沉淀
     - 将可复用经验写入记忆文件
     - 更新客户信息（如适用）
     - 更新方案模板（如适用）
- **输出**：归档清单
  ```
  归档清单：
  | 目录 | 文件数 | 状态 |
  |------|--------|------|
  | 01-售前文档 | {N} | 已归档 |
  | 02-产品文档 | {N} | 已归档 |
  | 03-开发文档 | {N} | 已归档 |
  | 04-测试文档 | {N} | 已归档 |
  | 05-交付文档 | {N} | 已归档 |
  | 06-项目管理 | {N} | 已归档 |

  知识沉淀：
    [x] 客户信息已更新到 memory
    [x] 经验教训已记录
    [x] 可复用模板已提取
  ```

### Stage 4: 结项

- **输入**：交付确认单 + 经验总结 + 归档清单
- **动作**：
  1. 编写结项报告
     - 项目概述
     - 交付成果
     - 项目数据（工期/工作量/质量）
     - 经验教训
     - 遗留事项
  2. 资源释放
     - 释放项目团队成员
     - 释放项目环境资源
     - 归档项目权限
  3. 项目关闭
     - 确认所有活动已完成
     - 确认所有文档已归档
     - 确认所有资源已释放
     - 正式标记项目状态为"已关闭"
  4. 通知干系人
     - 通知客户项目已关闭
     - 通知管理层项目已完成
     - 通知团队项目已结束
- **输出**：结项报告
  ```
  # 结项报告

  ## 1. 项目概述
  项目名称：{名称}
  项目周期：{开始} ~ {结束}
  项目目标：{SMART目标}
  目标达成：{是/部分/否}

  ## 2. 交付成果
  | 交付物 | 版本 | 状态 |
  |--------|------|------|

  ## 3. 项目数据
  - 计划工期：{N} 天
  - 实际工期：{N} 天
  - 偏差：+{N} 天
  - 计划工作量：{N} 人天
  - 实际工作量：{N} 人天
  - 缺陷总数：{N} 个
  - 验收通过率：{%}
  - 质量门禁：QG-D/S/B/Ship 全部通过

  ## 4. 经验教训
  （引用经验总结报告）

  ## 5. 遗留事项
  | 序号 | 事项 | 责任人 | 计划完成 |
  |------|------|--------|---------|

  ## 6. 项目关闭确认
  [x] 所有交付物已签收
  [x] 所有文档已归档
  [x] 经验教训已总结
  [x] 资源已释放
  [x] 干系人已通知

  项目状态：已关闭
  关闭日期：{日期}
  项目经理签字：______
  ```

## 产物归档

```
项目文档/{客户名}-{项目名}/06-项目管理/
├── 交付确认单.md
├── 经验总结.md
├── 归档清单.md
└── 结项报告.md（或 .docx）
```

## 结项检查清单

```
结项完成需确认：
  [ ] 交付确认单已双方签字
  [ ] 验收报告已归档
  [ ] 经验总结已完成
  [ ] 所有文档已归档
  [ ] 知识已沉淀到记忆文件
  [ ] 资源已释放
  [ ] 结项报告已编写
  [ ] 干系人已通知
  [ ] 项目状态已标记为"已关闭"
```

## 降级策略

| 缺失资源 | 降级行为 |
|----------|----------|
| 验收报告缺失 | 标注"验收报告待补充"，基于其他交付物确认 |
| 团队无法参加回顾 | 收集书面反馈，异步总结 |
| docx 未安装 | 结项报告输出 Markdown 格式 |
