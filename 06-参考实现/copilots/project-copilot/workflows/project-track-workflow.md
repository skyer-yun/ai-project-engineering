# 项目跟踪工作流

> 覆盖阶段：N4-N12（项目执行与跟踪）
> 对应角色：跟踪师/风险师/汇报人

---

## 适用场景

当项目进入执行阶段，需要持续跟踪进度、监控风险、管理变更、输出报告时使用。

- 周进度更新
- 里程碑检查
- 风险状态更新
- 变更请求处理
- 项目报告输出

## 前置条件

```
必须：
  [x] 项目计划已确认（WBS+甘特图+里程碑）
  [x] 项目已进入执行阶段

建议：
  [ ] 质量门禁检查点已设定
  [ ] 各智能体已激活
```

## 阶段

### Stage 1: 进度更新

- **输入**：项目计划 + 实际进展信息
- **动作**：
  1. 收集实际进度
     - 各任务完成百分比
     - 已完成的交付物
     - 遇到的问题/阻塞
     - 资源使用情况
  2. 更新项目数据
     - 更新任务状态（未开始/进行中/已完成/已延期）
     - 记录实际开始/完成时间
     - 记录实际工作量消耗
  3. 对比计划 vs 实际
     - 计划完成 vs 实际完成
     - 计划工作量 vs 实际工作量
     - 计划时间 vs 实际时间
- **输出**：进度偏差表
  ```
  | 任务 | 计划完成% | 实际完成% | 偏差 | 原因 |
  |------|----------|----------|------|------|
  | 前端开发 | 60% | 45% | -15% | UI组件库升级导致返工 |
  | 后端开发 | 60% | 65% | +5% | — |
  | 联调 | 0% | 0% | 0% | 未开始 |
  ```

### Stage 2: 偏差分析

- **输入**：进度偏差表 + 项目数据
- **动作**：
  1. 计算偏差指标
     - SV（进度偏差）= EV - PV
     - CV（成本偏差）= EV - AC
     - SPI（进度绩效指数）= EV / PV
     - CPI（成本绩效指数）= EV / AC
  2. 判断偏差严重程度
     - SPI > 1.0：进度超前
     - SPI = 1.0：进度正常
     - SPI 0.9-1.0：轻微延迟
     - SPI < 0.9：显著延迟
  3. 分析偏差原因
     - 估算偏差
     - 资源问题
     - 技术困难
     - 外部依赖
     - 范围蔓延
  4. 提出纠正措施
     - 加资源（赶工）
     - 调整范围（快速跟进）
     - 调整排期
     - 风险应对
- **输出**：偏差分析报告
  ```
  偏差分析：
  SPI = 0.92（轻微延迟）
  CPI = 1.05（成本略省）

  主要偏差：
  1. 前端开发延迟 15%（UI组件库升级）
  2. 联调开始时间预计后移 3 天

  纠正措施：
  1. 前端增加 1 名开发人员（赶工）
  2. 后端先行准备接口文档（并行）
  3. 调整甘特图，联调后移 3 天

  预测：
  - 总工期影响：+2 天（可通过赶工弥补）
  - 下个里程碑风险：中（需密切关注前端进度）
  ```

### Stage 3: 风险监控

- **输入**：风险登记册 + 新增风险信息
- **动作**：
  1. 更新已有风险状态
     - 风险是否发生
     - 应对措施是否有效
     - 风险值是否变化
     - 关闭已解决的风险
  2. 识别新风险
     - 基于偏差分析发现的新风险
     - 基于外部变化的新风险
     - 基于团队反馈的新风险
  3. 调整风险应对策略
     - 风险升级：概率或影响增加
     - 风险降级：应对措施生效
     - 风险关闭：不再存在
  4. 预警通知
     - 高风险值风险 → 立即通知干系人
     - 风险升级 → 通知项目经理
     - 新增关键路径风险 → 调整计划
- **输出**：风险状态更新
  ```
  风险更新：
    R001 第三方接口延期：概率 高→中（已提前对接）
    R002 需求变更：新增 1 次变更请求
    R004 [新增] 前端开发人员请假：概率中/影响中/风险值0.16

  当前风险状态：
    高风险(>0.3)：0 个
    中风险(0.1-0.3)：2 个
    低风险(<0.1)：3 个
  ```

### Stage 4: 变更管理

- **输入**：变更请求 + 项目计划
- **动作**：
  1. 接收变更请求
     - 变更来源（客户/团队/内部）
     - 变更类型（范围/进度/成本/质量）
     - 变更描述
  2. 影响评估
     - 对进度的影响
     - 对成本的影响
     - 对范围的影响
     - 对质量的影响
     - 对其他任务/里程碑的影响
  3. 变更审批
     - 小变更（影响 < 1 天）：项目经理审批
     - 中变更（影响 1-3 天）：项目经理 + 技术负责人审批
     - 大变更（影响 > 3 天）：需客户确认 + 项目经理审批
  4. 变更执行
     - 更新 WBS
     - 更新甘特图
     - 更新风险登记册
     - 通知受影响的相关方
- **输出**：变更记录
  ```
  | 编号 | 变更描述 | 类型 | 来源 | 影响 | 审批状态 | 执行状态 |
  |------|---------|------|------|------|---------|---------|
  | CR001 | 新增数据导出功能 | 范围 | 客户 | +3人天 | 已批准 | 已执行 |
  | CR002 | 交付日期后移1周 | 进度 | 内部 | +5天 | 待审批 | — |
  ```

### Stage 5: 报告输出

- **输入**：进度数据 + 偏差分析 + 风险状态 + 变更记录
- **动作**：
  1. 选择报告类型
     - 周报：每周输出
     - 月报：每月输出
     - 里程碑报告：每个里程碑输出
     - 专项报告：按需输出
  2. 编写报告
  3. 格式化输出
- **输出**：项目报告

  **周报模板**：
  ```
  # 项目周报 - 第 {N} 周

  ## 1. 本周进展
  ### 已完成
  - {任务1}（{负责人}，{实际耗时}）
  - {任务2}（{负责人}，{实际耗时}）

  ### 进行中
  - {任务3}：完成 {N}%（{负责人}）
  - {任务4}：完成 {N}%（{负责人}）

  ### 阻塞/延迟
  - {任务5}：延迟 {N} 天，原因：{描述}

  ## 2. 下周计划
  - {计划任务1}（{负责人}，预计 {N} 天）
  - {计划任务2}（{负责人}，预计 {N} 天）

  ## 3. 风险与问题
  | 编号 | 描述 | 状态 | 应对 |
  |------|------|------|------|

  ## 4. 里程碑状态
  | 里程碑 | 计划日期 | 预计完成 | 状态 |
  |--------|---------|---------|------|

  ## 5. 需要决策的事项
  - {事项1}：{描述}
  ```

## 降级策略

| 缺失资源 | 降级行为 |
|----------|----------|
| 实际进度数据不足 | 标注"数据待确认"，基于已知信息分析 |
| risk-analyzer 未安装 | 使用内置风险框架（概率x影响矩阵） |
| docx/pptx 未安装 | 报告输出 Markdown 格式 |
