## 1. 审批流程

### 概述

审批流程是最通用的业务流程，覆盖请假、报销、采购、合同、用印等场景。核心特点：多节点流转、条件分支、驳回回退。

### 节点类型定义

| 节点类型 | 编码 | 图标 | 说明 | 必选 |
|---------|------|------|------|------|
| 开始节点 | START | ● | 流程发起，自动触发 | 是 |
| 审批节点 | APPROVAL | ◆ | 单人/多人审批 | 是 |
| 抄送节点 | CC | ○ | 知会相关人员，不阻塞流程 | 可选 |
| 条件节点 | CONDITION | ◇ | 根据条件走不同分支 | 可选 |
| 会签节点 | COUNTERSIGN | ◆◆ | 多人同时审批，需全部/多数通过 | 可选 |
| 或签节点 | OR_SIGN | ◆| 多人审批，任一通过即可 | 可选 |
| 结束节点 | END | ■ | 流程结束（通过/驳回/撤回） | 是 |

### 标准流程模型

```
START → APPROVAL_1 → CONDITION → ┬ 通过 → APPROVAL_2 → CC → END(通过)
                                  └ 驳回 → END(驳回)
```

### 节点详细规则

#### 审批节点

| 属性 | 说明 | 示例 |
|------|------|------|
| 审批人类型 | 指定人/角色/部门主管/发起人主管 | 部门主管 |
| 审批方式 | 或签/会签/依次审批 | 或签 |
| 超时规则 | 超时自动通过/超时提醒/超时转办 | 超时24h提醒 |
| 可用操作 | 同意/驳回/转办/加签/退回 | 全部 |

#### 驳回规则

| 驳回方式 | 编码 | 说明 | 适用场景 |
|---------|------|------|---------|
| 驳回到上一节点 | REJECT_PREV | 回到上一个审批节点 | 补充材料 |
| 驳回到发起人 | REJECT_START | 回到发起节点重新填写 | 重大问题 |
| 驳回到指定节点 | REJECT_TARGET | 回到任意指定节点 | 定向回退 |
| 驳回并结束 | REJECT_END | 直接结束流程 | 不予审批 |

#### 转办规则

| 属性 | 说明 |
|------|------|
| 转办类型 | 转办（交出权限）/ 协办（保留权限） |
| 转办范围 | 同部门/同角色/不限 |
| 转办后 | 原审批人不再收到待办 |

#### 加签规则

| 属性 | 说明 |
|------|------|
| 加签方式 | 前加签（当前节点前）/ 后加签（当前节点后） |
| 加签人 | 指定具体人员 |
| 加签后 | 增加临时审批节点 |

### 条件分支定义

```yaml
条件节点:
  名称: "金额判断"
  分支:
    - 条件: "金额 ≤ 5000"
      流向: "部门主管审批"
    - 条件: "5000 < 金额 ≤ 50000"
      流向: "部门主管 → 财务总监"
    - 条件: "金额 > 50000"
      流向: "部门主管 → 财务总监 → CEO"
```

### 状态定义

| 状态 | 编码 | 说明 | 可流转到 |
|------|------|------|---------|
| 草稿 | DRAFT | 尚未提交 | 已提交 |
| 已提交 | SUBMITTED | 等待审批 | 审批中/已撤回 |
| 审批中 | APPROVING | 审批进行中 | 已通过/已驳回/已撤回 |
| 已通过 | APPROVED | 审批通过 | - |
| 已驳回 | REJECTED | 审批驳回 | 已提交（重新提交） |
| 已撤回 | WITHDRAWN | 发起人撤回 | 已提交（重新提交） |
| 已取消 | CANCELLED | 流程取消 | - |

### 流程变量

| 变量名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| initiator | String | 发起人ID | user_001 |
| department | String | 发起人部门 | 技术部 |
| amount | Number | 申请金额 | 12000 |
| urgency | String | 紧急程度 | normal/urgent/critical |
| attachmentCount | Number | 附件数量 | 3 |

### 数据模型

```yaml
审批流程实例:
  流程ID: string          # 唯一标识
  流程类型: string        # 请假/报销/采购/...
  发起人: string          # 用户ID
  发起时间: datetime
  当前状态: string        # DRAFT/SUBMITTED/APPROVING/...
  当前节点: string        # 当前所在节点ID
  标题: string
  表单数据: object        # 业务表单JSON
  附件: array             # 附件列表

审批记录:

  审批人: string
  审批时间: datetime
  操作: string            # 同意/驳回/转办/加签
  意见: string
  附件: array
```

## 2. 发布流程

### 概述

发布流程适用于内容管理、产品版本、公告通知等场景。核心特点：草稿→多级审核→发布→归档的线性流转，强调版本管理和回滚能力。

### 标准流程模型

```
DRAFT → REVIEW → APPROVED → PUBLISHED → ARCHIVED
  ↑        │                              │
  └────────┘                              │
  REJECTED                    WITHDRAWN ←─┘
```

### 节点定义

| 阶段 | 编码 | 角色 | 操作 | 说明 |
|------|------|------|------|------|
| 草稿 | DRAFT | 编辑 | 编辑/预览/提交审核 | 初始状态 |
| 审核中 | REVIEW | 审核 | 通过/驳回/修改建议 | 内容审核 |
| 已通过 | APPROVED | 发布管理员 | 发布/退回/定时发布 | 待发布 |
| 已发布 | PUBLISHED | 系统 | 撤回/下线/编辑新版本 | 对外可见 |
| 已归档 | ARCHIVED | 系统 | 恢复/永久删除 | 历史存档 |
| 已驳回 | REJECTED | 编辑 | 修改/重新提交 | 退回修改 |

### 状态流转规则

| 当前状态 | 操作 | 目标状态 | 条件 |
|---------|------|---------|------|
| 草稿 | 提交审核 | 审核中 | 必填字段完整 |
| 审核中 | 通过 | 已通过 | 审核通过 |
| 审核中 | 驳回 | 已驳回 | 填写驳回原因 |
| 已驳回 | 重新提交 | 审核中 | 修改后提交 |
| 已通过 | 立即发布 | 已发布 | - |
| 已通过 | 定时发布 | 已发布 | 到达定时时间 |
| 已通过 | 退回 | 草稿 | - |
| 已发布 | 撤回 | 草稿 | 生成新版本号 |
| 已发布 | 下线 | 已归档 | 确认操作 |
| 已归档 | 恢复 | 草稿 | 生成新版本号 |

### 版本管理规则

| 规则 | 说明 |
|------|------|
| 版本号格式 | v{major}.{minor}（如 v1.0, v1.1, v2.0） |
| 编辑已发布内容 | 自动创建新版本（草稿状态） |
| 版本对比 | 支持任意两个版本内容对比 |
| 版本回滚 | 可回滚到任意历史版本 |
| 发布记录 | 保留完整发布历史 |

### 审核规则

```yaml
审核配置:
  是否需要审核: true
  审核层级: 1  # 1=单级, 2=双级
  审核人: "角色:内容审核员"
  审核字段:
    - 标题
    - 正文内容
    - 封面图
    - 分类/标签
    - SEO信息
  自动通过条件:
    - 修改类型 = "格式修正"
    - 修改内容 < 5%
```

### 数据模型

```yaml
内容:
  ID: string
  类型: string           # 文章/公告/产品/...
  标题: string
  内容: string           # 富文本/Markdown
  当前版本: string        # v1.0
  状态: string           # DRAFT/REVIEW/PUBLISHED/...
  作者: string
  创建时间: datetime
  发布时间: datetime
  定时发布: datetime      # 可选
  下线时间: datetime      # 可选

版本记录:
  ID: string
  内容ID: string
  版本号: string
  标题: string
  内容: string
  变更说明: string
  操作人: string
  操作时间: datetime
  状态: string
```

## 3. 工单流程

### 概述

工单流程适用于 IT 运维、客户服务、售后服务、任务派发等场景。核心特点：创建→分配→处理→验证→关闭，强调 SLA 和工单状态追踪。

### 标准流程模型

```
CREATE → ASSIGN → PROCESS → VERIFY → CLOSE
  │                      │       │
  │                      │       └→ REOPEN → ASSIGN
  │                      └→ ESCALATE → PROCESS
  └→ CANCEL
```

### 节点定义

| 阶段 | 编码 | 角色 | 操作 | 说明 |
|------|------|------|------|------|
| 创建 | CREATE | 提交人 | 提交/保存草稿/取消 | 填写工单信息 |
| 已分配 | ASSIGN | 调度/系统 | 分配/转派/退回 | 确定处理人 |
| 处理中 | PROCESS | 处理人 | 处理/升级/转派/挂起 | 执行处理 |
| 待验证 | VERIFY | 提交人 | 验证通过/不通过 | 确认解决 |
| 已关闭 | CLOSE | 系统/提交人 | 关闭/重开工单 | 终态 |
| 已取消 | CANCEL | 提交人 | 取消 | 终态 |

### 优先级与 SLA

| 优先级 | 编码 | 响应时间 | 解决时间 | 升级规则 |
|--------|------|---------|---------|---------|
| 紧急 | P1 | 15 分钟 | 2 小时 | 超时自动升级到上级 |
| 高 | P2 | 30 分钟 | 4 小时 | 超时自动升级 |
| 中 | P3 | 2 小时 | 8 小时 | 超时提醒 |
| 低 | P4 | 8 小时 | 24 小时 | 超时提醒 |

### 状态流转规则

| 当前状态 | 操作 | 目标状态 | 条件 |
|---------|------|---------|------|
| 创建 | 提交 | 已分配 | 必填完整+选择类型 |
| 创建 | 取消 | 已取消 | 提交人操作 |
| 已分配 | 开始处理 | 处理中 | 处理人接单 |
| 已分配 | 转派 | 已分配 | 选择新处理人 |
| 处理中 | 提交解决 | 待验证 | 填写处理结果 |
| 处理中 | 升级 | 处理中 | 升级到更高级处理人 |
| 处理中 | 转派 | 已分配 | 转给其他人 |
| 处理中 | 挂起 | 处理中（挂起） | 填写挂起原因 |
| 待验证 | 验证通过 | 已关闭 | - |
| 待验证 | 验证不通过 | 已分配 | 填写原因，重新分配 |
| 已关闭 | 重开 | 已分配 | 在重开期限内 |

### 工单分类

```yaml
工单类型:
  IT运维:
    - 硬件故障
    - 软件问题
    - 网络问题
    - 账号权限
  客户服务:
    - 咨询
    - 投诉
    - 建议
    - 售后
  任务派发:
    - 安装部署
    - 现场服务
    - 巡检维护
```

### 数据模型

```yaml
工单:
  工单ID: string           # 自动生成（WO-20260518-001）
  标题: string
  描述: string
  类型: string             # 工单分类
  优先级: string           # P1/P2/P3/P4
  状态: string
  提交人: string
  处理人: string
  当前SLA:
    响应截止: datetime
    解决截止: datetime
    已耗时: number         # 分钟
  关联资产: array          # 关联的设备/系统
  附件: array

工单记录:
  记录ID: string
  工单ID: string
  操作: string             # 创建/分配/处理/转派/升级/验证/关闭
  操作人: string
  操作时间: datetime
  内容: string
  附件: array
```

## 4. 数据采集流程

### 概述

数据采集流程适用于 ETL（Extract-Transform-Load）、数据同步、报表生成等场景。核心特点：配置驱动、定时调度、数据质量校验、异常告警。

### 标准流程模型

```
SOURCE_CONFIG → RULES_DEFINE → TRANSFORM → STORAGE → SCHEDULE → TEST → ACTIVE
       │              │            │          │                      │
       └── 编辑 ──────┴────────────┴──────────┘                      │
                                                                       │
                  MONITOR ←────────────────────────────────────────────┘
                    │
              ┌─────┼──────┐
              │     │      │
           SUCCESS WARNING ERROR
```

### 节点定义

| 阶段 | 编码 | 操作 | 说明 |
|------|------|------|------|
| 数据源配置 | SOURCE_CONFIG | 配置数据源连接信息 | 数据库/API/文件/消息队列 |
| 规则定义 | RULES_DEFINE | 定义采集规则和字段映射 | 字段映射/过滤条件/增量标识 |
| 数据转换 | TRANSFORM | 配置清洗和转换规则 | 格式转换/计算字段/去重 |
| 存储配置 | STORAGE | 配置目标存储 | 目标表/分区策略/写入模式 |
| 调度配置 | SCHEDULE | 配置执行计划 | Cron 表达式/依赖关系/重试策略 |
| 测试验证 | TEST | 试运行并验证 | 采样验证/全量验证/性能测试 |
| 运行监控 | MONITOR | 监控运行状态 | 成功率/数据量/耗时/告警 |

### 数据源类型

| 类型 | 编码 | 配置项 | 说明 |
|------|------|--------|------|
| 关系型数据库 | RDBMS | JDBC URL/用户名/密码/表名 | MySQL/Oracle/PostgreSQL |
| API接口 | API | URL/Method/Header/Auth | RESTful/SOAP |
| 文件 | FILE | 路径/格式/编码/分隔符 | CSV/Excel/JSON/XML |
| 消息队列 | MQ | Broker/Topic/Group | Kafka/RabbitMQ |
| NoSQL | NOSQL | 连接信息/集合/查询 | MongoDB/Redis/ES |

### 转换规则

```yaml
转换类型:
  字段映射:
    源字段: "src_field"
    目标字段: "dst_field"
    类型转换: "string → number"

  数据清洗:
    - 去除空值
    - 去除重复
    - 格式标准化（日期/电话/身份证）
    - 脱敏处理

  计算字段:
    名称: "total_amount"
    表达式: "price * quantity"
    类型: "number"

  条件过滤:
    字段: "status"
    操作: "in"
    值: ["active", "pending"]

  数据聚合:
    分组: ["department", "month"]
    聚合: {"amount": "sum", "count": "count"}
```

### 调度策略

| 策略 | 说明 | 示例 |
|------|------|------|
| 定时调度 | Cron 表达式 | `0 0 2 * * ?`（每天凌晨2点） |
| 事件触发 | 上游完成触发 | 上游任务成功后执行 |
| 手动触发 | 人工执行 | 点击"立即执行" |
| 增量同步 | 基于时间戳/ID增量 | `update_time > last_sync_time` |
| 全量同步 | 每次全量覆盖 | 适用于小数据量 |

### 数据质量校验

| 校验类型 | 说明 | 阈值 |
|---------|------|------|
| 完整性 | 字段空值率 | ≤ 5% |
| 准确性 | 数据格式合规率 | ≥ 99% |
| 一致性 | 源端目标端数量差 | ≤ 1% |
| 时效性 | 数据延迟 | ≤ 配置值 |
| 唯一性 | 重复记录率 | 0% |

### 异常处理

| 异常 | 处理策略 | 告警方式 |
|------|---------|---------|
| 连接失败 | 重试 3 次，间隔递增 | 短信+邮件 |
| 数据格式错误 | 跳过错误行，记录日志 | 邮件 |
| 数据量异常 | 与昨日对比偏差>50%暂停 | 短信+邮件 |
| 执行超时 | 终止并告警 | 短信+邮件 |
| 目标写入失败 | 重试 3 次，写入错误表 | 邮件 |

```yaml
采集任务:
  任务ID: string
  任务名称: string
  数据源: object           # 数据源配置
  目标存储: object          # 存储配置

  调度配置: object          # 调度策略
  质量规则: array           # 质量校验规则

  创建人: string
  创建时间: datetime

执行记录:
  记录ID: string

  开始时间: datetime
  结束时间: datetime
  状态: string             # RUNNING/SUCCESS/WARNING/ERROR
  读取行数: number
  写入行数: number
  错误行数: number
  耗时: number             # 秒
  日志: string
```

## 5. 采购流程

### 概述

采购流程适用于企业物资、服务、设备等采购场景。核心特点：申请→审批→询价/招标→合同→验收→结算，涉及多部门协作和财务合规。

### 标准流程模型

```
APPLY → APPROVE → BID → CONTRACT → RECEIVE → SETTLE
  │       │                      │          │
  │    REJECT                REJECT     RETURN
  │       │                      │          │
  └───────┘                  ←──────────────┘
```

### 节点定义

| 阶段 | 编码 | 角色 | 操作 | 说明 |
|------|------|------|------|------|
| 采购申请 | APPLY | 需求人 | 提交/保存草稿 | 填写采购需求 |
| 审批 | APPROVE | 部门领导/采购部/财务 | 同意/驳回 | 多级审批 |
| 询价/招标 | BID | 采购专员 | 询价/比价/定标 | 确定供应商 |
| 合同签订 | CONTRACT | 采购/法务/供应商 | 起草/审核/签署 | 合同全流程 |
| 到货验收 | RECEIVE | 需求人/仓管 | 验收/入库/退货 | 确认收货 |
| 结算付款 | SETTLE | 财务 | 审核/付款 | 财务结算 |

### 金额分级审批

```yaml
金额分级:
  小额采购 (≤ 5000):
    审批: 部门主管
    方式: 直接采购
    周期: 1-3天

  一般采购 (5000 - 50000):
    审批: 部门主管 → 采购部
    方式: 询价比价（≥3家）
    周期: 5-10天

  大额采购 (50000 - 500000):
    审批: 部门主管 → 采购部 → 财务总监
    方式: 竞争性谈判/邀请招标
    周期: 15-30天

  重大采购 (> 500000):
    审批: 部门主管 → 采购部 → 财务总监 → CEO
    方式: 公开招标
    周期: 30-60天
```

## 通用流程配置

### 流程引擎选型参考

| 引擎 | 适用场景 | 特点 |
|------|---------|------|
| Activiti/Flowable | Java 体系 | BPMN 2.0 标准，功能完善 |

### 流程设计原则

| 原则 | 说明 |
|------|------|
| 最短路径 | 减少不必要的审批节点 |
| 明确规则 | 条件分支规则清晰无歧义 |
| 超时处理 | 每个节点都设超时规则 |
| 可追溯 | 全流程操作留痕 |
| 可配置 | 流程节点/规则可动态调整 |
| 易回退 | 驳回/撤回/取消路径清晰 |
