# 项目管理工作流

> 本文件描述如何编排 project-manager 技能完成项目管理任务。不重复技能内部逻辑，仅定义调用时机、阶段衔接和交付物归档。

## 依赖技能

| 技能 | 用途 |
|------|------|
| `project-manager` | 项目管理主技能（4 阶段） |
| `docx` | 项目计划书转 Word 格式 |
| `xlsx` | WBS/风险登记册/甘特图数据转 Excel |
| `ai-product-dev-kit-modular` | 从 Demo 产出提取项目信息 |
| `write-a-prd` | 从 PRD 提取 WBS 输入 |

---

## 技能阶段概览

```
Stage 1：项目启动
  → Stage 2：项目规划（WBS + 估算 + 排期 + 风险）
    → Stage 3：执行跟踪
      → Stage 4：汇报收尾
```

---

## 工作流步骤

### Step 1：触发与调用

**触发条件**：用户说「项目管理」「WBS」「甘特图」「排期」「风险管理」「项目计划」「里程碑」等关键词。

**动作**：调用 `project-manager` 技能。

```
调用方式：Skill("project-manager")
```

---

### Step 2：Stage 1 项目启动（技能自主执行）

技能进入 Stage 1，引导用户完成项目启动。**本工作流不干预技能内部流程**。

技能内部步骤：

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1.0 | 确定项目类型 | A/B/C/D 类型 |
| 1.1 | 收集项目信息 | 项目名称/背景/目标/约束 |
| 1.2 | 识别干系人 | 干系人列表及角色 |

#### 项目类型

| 类型 | 代码 | 适用场景 |
|------|------|----------|
| **产品开发** | A | 新产品从 0 到 1 |
| **售前投标** | B | 投标文件、技术方案 |
| **迭代优化** | C | 已有产品功能迭代 |
| **自由规划** | D | 其他类型项目 |

---

### Step 3：Stage 2 项目规划（技能自主执行）

这是最核心的阶段，技能自主完成规划工作。**不干预**。

#### 2.1 WBS 分解

- 方法：交付物 → 任务 → 子任务
- 叶节点粒度：<= 5 人天
- 原则：100% 覆盖（所有 WBS 项加起来等于项目总范围）

#### 2.2 估算

3 种估算方法，技能会根据项目类型推荐：

| 方法 | 适用场景 | 原理 |
|------|----------|------|
| **专家法（Delphi）** | 有经验团队 | 多轮专家独立评估后收敛 |
| **类比法** | 有类似历史项目 | 参考历史数据按比例估算 |
| **三点法（PERT）** | 不确定性高 | (乐观+4×最可能+悲观)/6 |

#### 2.3 里程碑与甘特图

- 里程碑定义（关键节点）
- 甘特图（Mermaid 格式）
- 关键路径分析
- 资源分配

#### 2.4 风险管理

- 风险登记册（风险项列表）
- 风险矩阵（概率 × 影响）
- 4 种应对策略：规避 / 转移 / 减轻 / 接受

#### 2.5 项目计划文档

生成 7 节标准项目计划文档。

技能参考文件：
- `WBS模板.md` — WBS 分解参考
- `估算方法.md` — 估算方法详解
- `风险管理模板.md` — 风险登记册格式
- `汇报模板.md` — 汇报文档格式

---

### Step 4：Stage 3 执行跟踪（按需循环）

项目进入执行阶段后，用户可反复要求跟踪。

| 步骤 | 内容 | 频率 |
|------|------|------|
| 3.1 | 进度跟踪 | 按需/周/双周 |
| 3.2 | 风险监控 | 持续 |
| 3.3 | 变更管理 | 按需 |

---

### Step 5：Stage 4 汇报收尾

| 步骤 | 内容 |
|------|------|
| 4.1 | 定期汇报（周报/双周报/里程碑报告） |
| 4.2 | 项目收尾（12 节收尾报告） |

---

### Step 6：格式转换（按需）

产出完成后，可根据用户需要转换格式：

| 交付物 | 推荐格式 | 调用技能 |
|--------|----------|----------|
| 项目计划书 | .docx | `docx` |
| WBS 工作分解 | .xlsx | `xlsx` |
| 风险登记册 | .xlsx | `xlsx` |
| 甘特图 | Mermaid / .xlsx | 保留 Mermaid 或转 Excel |
| 汇报材料 | .pptx | `pptx` |

---

### Step 7：归档

将交付物归档到标准目录：

```
{项目目录}/
├── 项目文档/
│   └── 项目管理/
│       ├── 项目计划.md（或 .docx）
│       ├── WBS.md（或 .xlsx）
│       ├── 风险登记册.md（或 .xlsx）
│       └── 汇报/
│           ├── 周报-W01.md
│           └── 里程碑报告-M1.md
├── 流程图/
│   └── 源代码/
│       └── 甘特图.mmd
└── memory/
    └── projects.md
```

更新 `memory/projects.md`：
- 记录项目类型（A/B/C/D）
- 记录估算方法和关键路径
- 记录风险 Top 3
- 记录当前阶段和进度

## 从其他工作流衔接

| 来源工作流 | 衔接点 | 输入 |
|------------|--------|------|
| `prd-workflow.md` | PRD 完成后 | PRD 文档（提取 WBS 输入） |
| `demo-workflow.md` | Demo 交付后 | 页面列表 + 功能清单（估算基础） |

衔接时可将已有产出物作为 Stage 1 的输入，减少重复收集。

---

## 决策速查

```
用户要管理项目
  → 调用 project-manager
  → Stage 1 确定类型（A/B/C/D）
  → Stage 2 规划
    ├─ WBS 分解（交付物→任务→子任务，叶节点 <= 5 人天）
    ├─ 估算（Delphi/类比/PERT）
    ├─ 甘特图 + 关键路径
    ├─ 风险登记册 + 矩阵
    └─ 项目计划文档
  → Stage 3 执行跟踪（循环）
  → Stage 4 汇报收尾
  → 格式转换（按需）
  → 归档
```
