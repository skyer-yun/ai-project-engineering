# 行业方案知识库

## 概述

本目录包含 4 个重点行业的方案知识，为售前方案编写提供行业背景、常见系统、核心模块、合规要求和技术偏好参考。

## 行业索引

### 1. 政务

**核心痛点**：
- 数据孤岛严重，跨部门数据共享难
- 系统老旧，信创替换压力大
- 群众办事体验差，线上服务能力弱
- 监管效率低，数据驱动决策能力不足

**常见系统**：
- 一网通办 / 政务服务平台
- 城市大脑 / 智慧城市
- 数据共享交换平台
- 政务协同办公系统
- 社会治理综合平台
- 智慧应急指挥系统

**核心模块**：
- 统一身份认证（SSO）
- 统一门户 / 政务大厅
- 电子证照管理
- 行政审批流程引擎
- 数据共享交换
- GIS 地图服务
- 移动端服务（小程序/App）

**合规要求**：
- 等级保护 2.0（通常三级）
- 信创适配（国产 CPU/OS/数据库/中间件）
- 政务数据安全管理办法
- 个人信息保护法
- 电子签章相关法规

**技术偏好**：
- 微服务架构
- 国产数据库（达梦、人大金仓、GaussDB）
- 国产中间件（东方通、宝兰德）
- 信创云 / 政务云部署
- Vue/Element UI 前端（政企项目主流）

### 2. 金融

**核心痛点**：
- 监管合规要求严格，系统审计复杂
- 业务系统繁多，集成改造难度大
- 数据安全和隐私保护要求极高
- 实时交易处理性能要求高

**常见系统**：
- 核心业务系统
- 风险管理系统
- 反欺诈系统
- 合规审计系统
- 客户关系管理（CRM）
- 智能投顾 / 智能客服
- 数据中台

**核心模块**：
- 统一认证与权限管理
- 交易处理引擎
- 风控规则引擎
- 实时监控告警
- 数据脱敏与加密
- 审计日志全链路
- API 网关

**合规要求**：
- 银保监会/证监会监管要求
- 金融数据安全分级
- 个人金融信息保护
- 等级保护三级以上
- 反洗钱（AML）合规
- PCI DSS（如涉及支付）

**技术偏好**：
- 分布式微服务
- 消息队列（Kafka/RocketMQ）
- 分布式数据库
- 容器化部署（K8s）
- Java/Spring 技术栈
- 高可用架构（双活/多活）

### 3. 教育

**核心痛点**：
- 教学资源分散，优质资源共享难
- 教学管理信息化程度参差不齐
- 学生数据隐私保护要求提升
- 家校沟通效率低

**常见系统**：
- 智慧校园平台
- 教务管理系统
- 在线教学平台
- 教育资源管理平台
- 学生成长档案系统
- 校园安全监控系统
- 家校互通平台

**核心模块**：
- 统一身份认证
- 课程管理
- 在线考试
- 教学评价
- 资源共享
- 校园一卡通
- 数据分析与可视化

**合规要求**：
- 未成年人保护法
- 教育数据安全管理
- 等级保护二级以上
- 教育信息化标准

**技术偏好**：
- 云原生架构
- 微服务 / Serverless
- 视频流媒体技术
- 移动端优先（小程序/H5）
- AI 能力集成（智能批改/推荐）

### 4. 企业

**核心痛点**：
- 数字化转型缺乏顶层设计
- 系统烟囱式建设，数据不通
- 流程自动化程度低，效率不高
- 移动办公能力不足

**常见系统**：
- 企业门户 / 门户中台
- 协同办公（OA）系统
- 人力资源管理系统（HRM）
- 客户关系管理（CRM）
- 企业资源计划（ERP）
- 项目管理系统
- 知识管理平台
- 数据分析平台（BI）

**核心模块**：
- 统一认证与权限
- 流程引擎（BPMN）
- 消息通知中心
- 移动办公
- 报表与数据分析
- API 集成平台
- 低代码/无代码平台（趋势）

**合规要求**：
- 数据安全法
- 个人信息保护法
- 等级保护（通常二级）
- 行业特定合规（如医疗、制造业子行业）

**技术偏好**：
- SaaS / 混合云部署
- 低代码平台
- React/Vue 前端
- Node.js / Java 后端
- 开源技术栈为主
- DevOps 实践

## 使用方式

1. 编写方案前加载对应行业知识
2. 方案中使用行业术语和表达
3. 架构设计参考行业技术偏好
4. 安全章节对照合规要求
5. 根据行业常见系统设计功能模块

## 扩展

如需新增行业，在本目录创建 `{行业名}.md`，包含以上 5 个维度信息。
