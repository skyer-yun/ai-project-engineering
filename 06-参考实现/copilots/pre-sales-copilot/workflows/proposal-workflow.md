# 技术方案编写工作流（N3）

## 概述

本工作流覆盖 N3（方案编写）阶段，基于需求分析报告生成标准技术方案文档。

## 工作流步骤

### Step 1：方案框架确认

**输入**：
- 需求分析报告
- 客户技术偏好（如有）
- 项目约束（预算/时间/技术栈）

**处理**：
1. 确定方案类型（技术方案/解决方案/架构设计）
2. 根据类型选择对应模板
3. 生成方案目录大纲
4. 与用户确认框架

**输出**：
- 方案目录大纲
- 待确认清单（需用户决策的技术选型等）

**人工参与**：
- 确认方案类型
- 确认目录结构
- 确认技术选型方向

### Step 2：内容编写

**输入**：
- 确认后的方案框架
- 需求分析报告
- 行业参考资料

**处理**：
1. 按章节逐章填充内容
2. 生成架构图（Mermaid/PlantUML）
3. 技术选型对比分析
4. 项目实施计划排期
5. 风险识别与应对

**输出**：
- 完整方案初稿

**依赖**：
- technical-proposal-writer（核心）
- knowledge/proposal-templates/（模板参考）
- knowledge/industry-solutions/（行业参考）
- web-access（增强，搜索最新技术资料）

### Step 3：方案审查

**输入**：
- 方案初稿

**处理**：
1. 完整性检查（对照模板章节）
2. 一致性检查（需求覆盖度）
3. 可行性检查（技术方案是否可落地）
4. 格式规范检查

**输出**：
- 审查意见清单
- 待修改项清单

### Step 4：方案输出

**输入**：
- 审查修改后的方案

**处理**：
1. 按选定格式输出最终文档
2. 生成附件（架构图、部署图等）
3. 归档至项目文档目录

**输出**：
- 技术方案（.docx）
- 或解决方案（.docx）
- 或架构设计文档（.docx）

**依赖**：
- docx（增强，缺失则输出 .md）

## 标准 11 章技术方案结构

```
第1章 项目概述
  1.1 项目背景
  1.2 建设目标
  1.3 建设范围
  1.4 术语定义

第2章 需求理解
  2.1 业务需求分析
  2.2 功能需求清单
  2.3 非功能需求
  2.4 需求优先级

第3章 总体架构设计
  3.1 设计原则
  3.2 系统架构图
  3.3 技术架构
  3.4 数据架构
  3.5 网络架构

第4章 功能设计
  4.1 功能模块划分
  4.2 各模块详细设计
  4.3 业务流程图
  4.4 页面/接口设计

第5章 技术选型
  5.1 技术选型原则
  5.2 前端技术栈
  5.3 后端技术栈
  5.4 数据库选型
  5.5 中间件选型
  5.6 对比分析表

第6章 数据设计
  6.1 数据模型设计
  6.2 数据流转方案
  6.3 数据安全方案
  6.4 数据备份与恢复

第7章 安全设计
  7.1 安全架构
  7.2 认证与授权
  7.3 数据安全
  7.4 网络安全
  7.5 安全合规

第8章 部署方案
  8.1 部署架构图
  8.2 环境规划
  8.3 部署策略
  8.4 容灾方案

第9章 项目实施计划
  9.1 实施方法论
  9.2 项目阶段划分
  9.3 里程碑计划
  9.4 资源需求

第10章 风险与应对
  10.1 风险识别
  10.2 风险评估
  10.3 应对措施
  10.4 风险监控机制

第11章 服务与保障
  11.1 项目团队
  11.2 质量保障
  11.3 培训方案
  11.4 售后服务
  11.5 验收标准
```

## 7 章解决方案结构

```
第1章 项目背景与目标
第2章 行业现状与痛点
第3章 解决方案概述
第4章 核心能力
第5章 实施路径
第6章 预期效果

```

```

第2章 架构原则

第4章 应用架构
第5章 数据架构

```

## 产物清单

| 产物 | 格式 | 说明 |
|------|------|------|
| 技术方案/解决方案/架构设计 | .docx / .md | 主文档 |
| 架构图 | Mermaid / PlantUML | 系统架构、部署架构 |
| 实施计划 | .docx / .md | 含甘特图（可选） |

## 产物归档

```
项目文档/{客户名}-{项目名}/01-需求/
  └── {日期}-技术方案-v{版本}.docx
```

## 回退与异常

| 异常 | 处理 |
|------|------|
| technical-proposal-writer 缺失 | 使用手动引导 + 模板 |
| 需求信息不足以支撑方案 | 列出缺失项 + 请求补充 |
| 用户中途修改需求 | 评估影响范围 + 标注变更章节 |
| 行业特性不确定 | 联网搜索 + 加载行业知识库 |
