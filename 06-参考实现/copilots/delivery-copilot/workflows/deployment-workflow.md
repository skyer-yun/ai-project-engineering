# 部署管理工作流

> 覆盖阶段：交付·部署（部署实施）
> 对应角色：部署工程师

---

## 适用场景

当测试通过、代码冻结后，需要制定部署方案并执行上线时使用。

- 生产环境首次部署
- 版本升级部署
- 多环境部署（开发/测试/预发布/生产）
- 私有化/云服务/混合部署

## 前置条件

```
必须：
  [x] 测试报告已通过（All Pass 或条件通过）
  [x] P0/P1 缺陷已清零
  [x] 代码已打 Tag（版本号确定）

建议：
  [ ] 部署目标环境信息已收集
  [ ] 依赖服务/中间件已确认
  [ ] 回滚环境已准备
```

## 阶段

### Stage 1: 环境评估

- **输入**：系统架构文档 + 服务器清单 + 客户环境信息
- **动作**：
  1. 调研目标环境
     - 服务器配置（CPU/内存/磁盘/网络）
     - 操作系统版本
     - 已安装中间件（数据库/缓存/消息队列/Web服务器）
     - 网络拓扑与安全策略
  2. 检查依赖
     - 系统依赖（JDK/Node.js/Python 版本）
     - 第三方服务（支付/短信/对象存储）
     - 外部接口（需要开放的端口/域名）
  3. 风险评估
     - 环境差异风险（开发 vs 生产）
     - 数据迁移风险
     - 依赖服务可用性风险
  4. 选择部署模式（参考 `knowledge/deployment-patterns/README.md`）
- **输出**：环境评估报告
  ```
  目标环境：
    服务器：{数量}台，{配置}
    操作系统：{类型+版本}
    中板件：{列表}
    网络：{拓扑描述}

  依赖检查：
    [OK] MySQL 8.0
    [OK] Redis 7.0
    [!!] Node.js 版本不匹配（需 18.x，现有 16.x）
    [OK] Nginx 已安装

  风险评估：
    - 高：Node.js 版本需升级
    - 中：数据迁移量较大（约 10GB）
    - 低：SSL 证书需更新

  推荐部署模式：Docker Compose
  ```

### Stage 2: 方案制定

- **输入**：环境评估报告 + 系统架构文档
- **动作**：
  1. 制定部署架构
     - 服务器角色分配
     - 服务部署拓扑
     - 负载均衡策略
  2. 编写部署步骤
     - 前置检查（环境/依赖/权限）
     - 部署顺序（数据库→中间件→应用→前端）
     - 配置修改（环境变量/配置文件/域名）
     - 数据迁移（脚本/验证/回滚）
     - 后置验证（健康检查/功能验证/性能验证）
  3. 制定回滚方案
     - 回滚触发条件（健康检查失败/P0缺陷/性能不达标）
     - 回滚步骤（代码回退/数据库回滚/DNS切换）
     - 回滚验证（功能验证/数据一致性）
  4. 选择发布策略
     - 蓝绿发布：两套环境切换
     - 金丝雀发布：逐步放量
     - 滚动更新：逐台替换
     - 全量发布：一次全部更新
- **输出**：部署方案
  - 部署架构图
  - 部署步骤（详细操作手册）
  - 回滚方案
  - 发布策略说明
  - 人员分工表

### Stage 3: 配置管理

- **输入**：部署方案 + 环境信息
- **动作**：
  1. 整理配置项
     - 应用配置（端口/日志级别/线程池）
     - 数据源配置（数据库连接/连接池）
     - 缓存配置（Redis 地址/过期策略）
     - 第三方服务配置（API Key/回调地址）
     - 安全配置（SSL 证书/CORS/密钥）
  2. 按环境区分配置
     - 开发环境 → 测试环境 → 预发布环境 → 生产环境
     - 标注每个环境的不同配置项
  3. 敏感信息处理
     - 密码/密钥使用环境变量或密钥管理服务
     - 不硬编码在配置文件中
  4. 数据迁移脚本
     - 建表脚本（DDL）
     - 初始数据脚本（DML）
     - 数据迁移脚本（如需）
     - 数据验证脚本
- **输出**：配置清单
  - 环境变量清单
  - 配置文件模板
  - 数据迁移脚本
  - 配置差异表（环境间对比）

### Stage 4: 部署执行

- **输入**：部署方案 + 配置清单
- **动作**：
  1. 部署前检查
     - 确认所有前置条件已满足
     - 确认回滚方案已验证
     - 确认相关人员已就位
     - 确认维护窗口/停机时间已通知
  2. 按步骤部署
     - 严格按照部署方案执行
     - 每步记录执行结果
     - 遇到异常立即评估是否需要回滚
  3. 部署后验证
     - 健康检查（/health 接口）
     - 核心功能验证（冒烟测试）
     - 性能基线对比
     - 日志检查（无 ERROR/FATAL）
  4. 如需回滚
     - 按回滚方案执行
     - 验证回滚结果
     - 记录回滚原因
- **输出**：部署记录
  - 部署时间线
  - 每步执行记录
  - 验证结果
  - 问题记录（如有）
  - 回滚记录（如有）

### Stage 5: 文档归档

- **输入**：部署记录 + 验证结果
- **动作**：
  1. 整理部署文档
  2. 编写运维文档（日常操作/巡检/应急）
  3. 更新系统架构文档
  4. 归档所有交付物
- **输出**：
  - 部署文档
  - 运维操作手册
  - 系统架构更新
