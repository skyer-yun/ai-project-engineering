# 交付文档工作流

> 覆盖阶段：交付·文档（交付文档）
> 对应角色：文档工程师

---

## 适用场景

当系统功能已冻结，需要编写完整的交付文档包时使用。

- 用户手册编写
- 运维手册编写
- 培训材料制作
- 快速入门指南
- API 文档整理

## 前置条件

```
必须：
  [x] 系统功能已冻结
  [x] PRD 已定稿（功能描述参考）

建议：
  [ ] 验收标准已确认（文档需覆盖验收范围）
  [ ] 系统已部署（可截取真实界面截图）
  [ ] 运维信息已收集（监控/告警/巡检配置）
```

## 阶段

### Stage 1: 规划

- **输入**：PRD 文档 + 验收标准 + 客户要求
- **动作**：
  1. 确定文档清单
     - 根据合同/验收要求确定必须交付的文档
     - 根据项目特点补充建议文档
  2. 受众分析
     - 每份文档的目标读者
     - 读者的技术水平和使用场景
     - 阅读习惯和偏好
  3. 选择模板
     - 从 `knowledge/doc-templates/` 选择匹配模板
     - 根据项目特点调整模板结构
  4. 制定编写计划
     - 文档优先级
     - 编写时间估算
     - 评审安排
- **输出**：文档规划表
  ```
  | 文档名称 | 目标读者 | 优先级 | 模板 | 预计页数 | 负责人 |
  |---------|---------|--------|------|---------|--------|
  | 用户操作手册 | 业务操作人员 | P0 | 用户手册模板 | 40-60页 | {姓名} |
  | 管理员手册 | 系统管理员 | P0 | 运维手册模板 | 30-50页 | {姓名} |
  | 快速入门指南 | 新用户 | P1 | 快速入门模板 | 5-10页 | {姓名} |
  | 培训PPT | 全体用户 | P1 | 培训模板 | 30-50页 | {姓名} |
  | API接口文档 | 开发人员 | P2 | API文档模板 | 自动生成 | — |
  | 应急预案 | 运维人员 | P2 | 应急模板 | 10-20页 | {姓名} |
  ```

### Stage 2: 编写

- **输入**：文档规划表 + 模板 + PRD + 系统访问权限
- **动作**：

#### 2.1 用户手册编写

- **目标读者**：业务操作人员（非技术人员）
- **语言风格**：通俗易懂，避免技术术语
- **内容结构**：
  1. 文档信息（版本/修订记录）
  2. 系统概述（简介/功能范围/运行环境）
  3. 快速入门（登录/首次使用/核心操作）
  4. 功能详解（按模块/菜单逐项说明）
     - 每个功能：功能说明 → 操作步骤 → 注意事项
     - 每步配截图（带红色标注框）
     - 包含常见问题和异常处理
  5. 常见问题（FAQ）
  6. 附录（术语表/快捷键/联系方式）

#### 2.2 运维手册编写

- **目标读者**：系统管理员/运维人员
- **语言风格**：技术准确，操作精确
- **内容结构**：
  1. 文档信息
  2. 系统架构（部署拓扑/服务清单/依赖关系）
  3. 安装部署（环境要求/安装步骤/配置说明）
  4. 日常运维
     - 启停操作（启动/停止/重启命令）
     - 巡检操作（每日/每周/每月巡检清单）
     - 备份恢复（备份策略/恢复步骤/验证方法）
     - 日志管理（日志位置/查看方法/清理策略）
  5. 监控告警
     - 监控指标（CPU/内存/磁盘/QPS/RT/错误率）
     - 告警规则（阈值/级别/通知方式）
     - 监控面板使用说明
  6. 应急预案
     - 常见故障及处理（服务宕机/数据库异常/磁盘满/网络不通）
     - 升级流程（故障定级/升级路径/联系人）
     - 数据恢复（备份恢复/数据修复）
  7. 安全管理
     - 账号管理（创建/禁用/权限调整）
     - 证书管理（SSL 证书更新/密钥轮换）
     - 安全审计（日志审计/漏洞修复）

#### 2.3 培训材料制作

- **目标读者**：全体用户
- **形式**：PPT 演示文稿 + 操作演示视频（可选）
- **内容结构**：
  1. 课程目标
  2. 系统介绍（5-10min）
  3. 核心功能演示（20-30min）
  4. 实操练习（20-30min）
  5. 常见问题解答（10min）
  6. 联系方式与支持

- **输出**：交付文档集（按文档规划表）
- **技能调用**：`docx`（用户手册/运维手册）、`pptx`（培训材料）

### Stage 3: 审核

- **输入**：交付文档集
- **动作**：
  1. 内部评审
     - 技术准确性（技术描述是否正确）
     - 操作可复现性（每个步骤是否可按文档操作）
     - 覆盖完整性（功能是否全部覆盖）
     - 语言规范性（是否面向目标读者）
  2. 客户确认
     - 提交客户审阅
     - 收集修改意见
     - 修订文档
  3. 终版归档
     - 确定最终版本
     - 打印/签名/盖章（如需）
     - 归档到项目文档目录
- **输出**：
  - 终版交付文档集
  - 评审记录
  - 修订记录

## 文档质量检查清单

```
通用检查：
  [ ] 文档信息完整（版本/作者/日期）
  [ ] 目录结构清晰
  [ ] 语言面向目标读者
  [ ] 截图清晰、标注明确
  [ ] 操作步骤可复现
  [ ] 无错别字/格式错误

用户手册专项：
  [ ] 覆盖所有面向用户的功能
  [ ] 每个功能有操作步骤 + 截图
  [ ] 包含常见问题与异常处理
  [ ] 非技术人员可理解

运维手册专项：
  [ ] 部署架构完整描述
  [ ] 启停操作命令精确
  [ ] 巡检清单覆盖日常运维
  [ ] 应急预案可执行
  [ ] 监控指标和告警规则明确

培训材料专项：
  [ ] 课程目标明确
  [ ] 演示步骤与实际操作一致
  [ ] 包含实操练习环节
  [ ] 时间安排合理
```

## 降级策略

| 缺失资源 | 降级行为 |
|----------|----------|
| docx 未安装 | 输出 Markdown 格式，提示手动转换 |
| pptx 未安装 | 输出 Markdown 格式培训大纲 |
| delivery-doc-generator 未安装 | 使用内置模板逐个编写 |
| 系统未部署（无法截图） | 使用 PRD/Demo 截图 + 标注"以实际界面为准" |
