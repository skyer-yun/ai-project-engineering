## 五、改进建议（按优先级）

### P1：增强 Phase 3 技能知识库

4 个技能（customer-satisfaction / multi-project-dashboard / smart-scheduler / risk-sentinel）知识库仅 128-130 行，是系统最薄弱的部分。

**建议内容：**
- `customer-satisfaction`：增加评分细则（每维度 1-5 分的判定标准）、行业基准数据、问卷模板
- `multi-project-dashboard`：增加 HTML 看板模板参考、数据源对接方案、典型布局示例
- `smart-scheduler`：增加 CPM/PERT 计算实例、资源平衡算法步骤、甘特图生成对接
- `risk-sentinel`：增加风险概率-影响矩阵量化标准、SPI/CPI 阈值分段表、升级触发条件

### P2：补充 7 个引用但不存在的技能

当前 4 个智能体引用了 7 个未创建的技能（api-doc-generator、tech-stack-selector、test-automator、defect-analyzer、acceptance-manager、delivery-doc-generator、stakeholder-manager），均有降级方案但增加了依赖检测噪音。

**建议：** 评估是否真正需要，不需要则从 dependencies.md 中移除，避免检测时的"未安装"提示干扰用户。

### P3：知识库去重优化

5 份 `prompt-engineering/提示词模板与协作规范.md`（358-413 行/份，合计 ~1,923 行）内容高度相似。可考虑抽取共享基础模板 + 智能体专属覆盖段落，减少维护成本。

## 七、最佳实践总结

这个系统做得最好的几件事：

1. **统一范式**：所有智能体/技能严格遵循 9 节 skill.md 结构，找到任何信息的路径是可预测的
2. **降级策略**：每个依赖都有显式降级方案，不存在"缺一个技能整个系统不可用"的情况
3. **交接产物链**：5 个 Handoff 点 + QG1-QG5 共 48 项检查，上下游产物对齐可追踪
4. **行业知识**：售前智能体的行业方案文件含具体技术栈/合规/架构，不是泛泛而谈
5. **部署知识**：交付智能体的 deployment-patterns（387 行）是最扎实的单文件，含完整配置示例
