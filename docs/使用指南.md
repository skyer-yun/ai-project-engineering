# 使用指南

> **方法论**：DSBL 五阶段 × Loop 微循环 × 五角色 × HITL × 工具中立
> **目标**：1 小时理解体系 → 选适配方案 → 按 Playbook 开场 → 产物可校验可度量

---

## 0. 5 分钟快速入门

如果你只想知道「**今天怎么开始用**」：

1. 读根 `README.md` 的「按角色快速导航」表，找到自己角色
2. 选适配方案：`./install.sh --adapter claude-code`（或其他）
3. 打开对应 Playbook：`03-执行层/01-角色Playbook/{你角色}-Playbook.md`
4. 看 Playbook 第 1 节「触发场景」，作为开场白
5. 让 AI 跑完阶段 → 用 `04-工具层/04-交接契约工具/validate-handoff.sh` 校验产物
6. 周例会用 `04-工具层/02-Loop度量看板/` 看 KPI

不需要先读完整方法论——边干边查，遇到概念疑问时回到 `01-标准层/` 查权威源。

## 1. 场景驱动：开场第一句话

### 场景 1：售前接新客户（Spec-Writer 角色）

```
你（在 Claude Code 内）：
售前编排。客户是 XX 银行，要做风控规则引擎，预算 200 万，下周三交方案。

Claude（加载 pre-sales-copilot，承担 Spec-Writer）：
→ D-Discover 阶段 Loop 执行
  · Plan：需求理解 + 干系人识别
  · Act：客户邮件结构化、需求条目化（HITL: On，逐条确认）
  · Observe：需求完整度 ≥0.9
  · Reflect：架构师 + 客户共审
  · Exit：写 handoff.yaml（from_stage=D, to_stage=S, QG-D=passed）
→ 交接 product-copilot 或 dev-copilot（Builder）

校验：./04-工具层/04-交接契约工具/validate-handoff.sh 项目文档/.../D-to-S.yaml
预期：[OK] PASS
```

### 场景 2：产品写 PRD（Spec-Writer 角色）

```
你：写 PRD。已收到 D 阶段的需求分析报告 + 干系人清单。

Claude（加载 product-copilot，承担 Spec-Writer）：
→ 解析上游 handoff.yaml（gate_status=passed）
→ 加载需求分析报告
→ S-Spec 阶段 Loop：
  · PRD 编写：12 部分模板，Part 7 细化到界面
  · 生成验收标准（可测试率 ≥90%）
  · Exit：handoff.yaml（from_stage=S, to_stage=B, QG-S=passed）
```

### 场景 3：研发编码（Builder 角色）

```
你：研发编排。已收到 PRD v1.0 + 原型 Demo。

Claude（加载 dev-copilot，承担 Builder）：
→ S-Spec 后半：架构设计 + 详细设计（HITL: In，L3 不可逆）
→ QG-S 门禁
→ B-Build 阶段 Loop：
  · 关键模块：HITL-In（Plan 审批）
  · CRUD/样板：Fallback 自动
  · code-reviewer skill 跑四维审查（Reviewer）
  · Observe：单测 ≥80% 行覆盖 + lint 零严重
→ Exit：handoff.yaml（from_stage=B, to_stage=Ship, QG-B=passed）
```

### 场景 4：测试执行（Shipper 角色）

```
你：测试编排。

Claude（加载 testing-copilot，承担 Shipper）：
→ Ship 阶段 Loop：
  · 测试策略 + 用例生成（test-case-generator skill）
  · 执行（HITL: On，缺陷逐条确认）
  · 缺陷清零（P0/P1=0）
→ Exit：handoff.yaml（from_stage=Ship, to_stage=L, QG-Ship=passed）
```

### 场景 5：交付上线（Shipper 角色）

```
你：交付编排。

Claude（加载 delivery-copilot，承担 Shipper）：
→ Ship 阶段部署前 ./snapshot.sh 强制打快照
→ 部署：HITL-In（L4 不可逆，每步签字）+ 多人签
→ 部署失败：./rollback.sh --to <tag> 回滚
→ 验收（HITL-In，客户签字）
→ 培训材料 + 运维手册
→ Exit：handoff.yaml（from_stage=Ship, to_stage=L）
```

### 场景 6：Keeper 全程管理

```
你：项目启动。

Claude（加载 project-copilot，承担 Keeper）：
→ 项目章程 + WBS + 甘特图 + 风险登记册
→ 周例会：Loop 度量看板看 KPI
→ DSBL 横向协调：QG-D/S/B/Ship 门禁
→ L-Learn 阶段：项目复盘 + 知识沉淀
```

## 2. 关键工作流

### 2.1 阶段交接契约链路（跨角色交接）

每个 DSBL 阶段结束 → 写 handoff.yaml → 下游解析 → 校验 → 加载产物：

```
D ────→ S ────→ B ────→ Ship ────→ L
↓        ↓        ↓        ↓          ↓
yaml    yaml    yaml    yaml       yaml
（存在 项目文档/{项目}/）
```

**回溯**：Ship 部署失败 → 反向查 B→S→D 的 handoff.yaml，定位问题阶段。

详见 `01-标准层/04-阶段交接契约Schema.md`。

### 2.2 Checkpoint 协议（部署前快照）

Ship 阶段部署前 → 强制 snapshot → 失败回滚：

```
snapshot.sh --type deploy --stage Ship
↓
[快照目录] snapshots/pre-deploy-{时间戳}/
  ├─ db-backup.sql
  ├─ config-backup.tar.gz
  ├─ ai-context-backup.tar.gz
  └─ manifest.sha256
↓
部署失败 → rollback.sh --to pre-deploy-{时间戳}
↓
回滚后自动执行 scripts/smoke-after-rollback.sh
```

详见 `04-工具层/03-Checkpoint脚本/README.md`。

### 2.3 HITL 模式选择

| 模式 | 适用 | AI 行为 | 人工介入 |
|------|------|---------|---------|
| **In** | L4 不可逆（Ship 部署/验收/DB 迁移）+ L3 共识（D/S） | 每步等审批 | 每键/每步签字 |
| **On** | L3 监督（多数节点） | 持续执行 + 关键节点暂停 | 审查产物 |
| **Fallback** | L2/L1 辅助（B 编码 CRUD / 文档生成） | 自主跑 + 安全网 | 异常时介入 |

详见 `00-理论层/03-HITL模式与不可逆性矩阵.md` 和 `03-执行层/03-HITL规则表.md`。

## 3. 项目类型路由

### 瀑布型项目（政府/银行大型项目）

```
D → S → B → Ship → L 顺序走
每阶段 Loop 内迭代（2-4 轮）
```

### 迭代型 MVP（互联网/创新项目）

```
Sprint 1: D 部分 + S 关键 + B 编码闭环
Sprint 2..N: 补回完整 D/S/B/Ship
```

### 敏捷型项目（持续迭代）

```
每个 Sprint: 完整 S → B → Ship 闭环
D 在项目级走，L 每 Sprint 末走一次
```

详见 `00-理论层/01-DSBL阶段模型与Loop微循环原理.md`。

## 5. 故障排查

### AI 工具触发语不响应

- 检查 `~/.claude/skills/` 是否有对应 copilot：`ls ~/.claude/skills/ | grep copilot`
- 没装：`./install.sh --adapter claude-code` 重新部署
- 触发语拼写：参考各 Playbook 第 1 节

### skill.md 引用的技能找不到

- 检查 `~/.claude/skills/{技能名}` 是否存在
- 找不到：手动从 `06-参考实现/skills/` 复制或重跑 install.sh

### handoff.yaml 校验失败

- 跑 `./04-工具层/04-交接契约工具/validate-handoff.sh <file.yaml>`
- 看错误信息：缺字段 / 类型错 / 阶段名非法 / 角色名非法
- 修 YAML 重跑，直到 `[OK] PASS`

### snapshot.sh 失败

- 看 `04-工具层/03-Checkpoint脚本/README.md` FAQ
- 常见：mysqldump 未装 → `apt install default-mysql-client`
- DB 太大：用 RDS 快照代替 → `DB_TYPE=none` 跳过自动 dump

### HTML 看板打不开

- 默认浏览器：Chrome 80+ / Edge / Firefox / Safari
- 不要用 IE
- 控制台报错：F12 查看，多半是 localStorage 被禁用（隐私模式）

## 6. 进阶用法

### 6.1 自定义 KPI

编辑 `04-工具层/02-Loop度量看板/` 内 HTML 的 `KPI_GROUPS` 常量。

### 6.2 自定义交接契约校验规则

编辑 `04-工具层/04-交接契约工具/validate-handoff.sh` 内嵌 Python 校验函数。

### 6.3 添加新 copilot

参考 `06-参考实现/copilots/dev-copilot/` 结构：skill.md + config + workflows + knowledge + memory。必填 §1 触发场景 + §8 体系契约 + §9 启动流程。

### 6.4 换 AI 工具

详见 [05-适配层/](../05-适配层/) 对应指南。体系标准层和产物层模板完全通用，无需改动。

### 6.5 接入 CI/CD

`rollback.sh --yes` 跳过双签确认，但**生产环境禁用**——只用于 CI/CD 自动化场景。
