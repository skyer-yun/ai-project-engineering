# 使用指南

## 快速开始

### 调用智能体

在 Claude Code 对话中，直接使用自然语言描述你的需求，智能体会根据关键词自动匹配：

```
你：帮我分析一下竞品情况
→ 触发 competitive-analyzer

你：写一份技术方案
→ 触发 solution-architect

你：系统架构设计
→ 触发 architecture-designer

你：生成测试用例
→ 触发 test-case-generator

你：部署方案怎么做
→ 触发 auto-deployer
```

### 调用独立技能

独立技能可以通过 `/skill-name` 方式调用，也可以通过自然语言触发。

## 典型使用场景

### 场景一：投标项目全流程

```
1. "分析客户需求"           → pre-sales-copilot (N1-N2)
2. "竞品分析"               → competitive-analyzer
3. "写技术方案"             → solution-architect
4. "QG1 需求确认"           → quality-gate
5. "写PRD"                  → product-copilot → write-a-prd
6. "系统架构设计"            → architecture-designer
7. "详细设计"               → detailed-designer
8. "生成测试用例"            → test-case-generator
9. "部署方案"               → auto-deployer
10. "培训材料"              → user-trainer
11. "项目总结"              → knowledge-compiler
```

### 场景二：需求变更

```
"需求变更：客户要求增加移动端适配"
→ requirement-change-manager
  - 输出变更影响分析（6维度评估）
  - 更新关联产物
```

### 场景三：项目风险管理

```
"检查项目健康状态"           → risk-sentinel
"多项目看板"                → multi-project-dashboard
"智能排期"                  → smart-scheduler
```

## 智能体-技能对照表

| 智能体 | 归属技能 | 典型触发词 |
|--------|---------|-----------|
| pre-sales | solution-architect, competitive-analyzer | 需求分析/写方案/竞品分析 |
| product | requirement-change-manager | 写PRD/需求变更 |
| dev | architecture-designer, detailed-designer, code-reviewer | 架构设计/详细设计/代码审查 |
| testing | test-case-generator, performance-tester | 测试用例/性能测试 |
| delivery | auto-deployer, user-trainer, customer-satisfaction | 部署方案/培训材料/客户满意度 |
| project | quality-gate, gantt-visualizer, smart-scheduler, risk-sentinel, multi-project-dashboard, knowledge-compiler, continuous-optimizer | 甘特图/质量门禁/风险预警/项目排期 |

## 自定义和扩展

### 修改智能体行为

编辑智能体的 `knowledge/` 目录下的文件即可修改其知识储备：

```
~/.claude/skills/02-pre-sales-copilot/
├── knowledge/
│   ├── competitive-intel/README.md      # 竞品情报知识
│   ├── industry-solutions/              # 行业方案知识
│   │   ├── README.md                    # 行业索引
│   │   ├── 政务与智慧园区.md
│   │   ├── 制造业与医疗.md
│   │   └── 零售与能源.md
│   ├── proposal-templates/README.md     # 方案模板知识
│   └── prompt-engineering/             # 提示词模板
```

### 添加新行业

在 `knowledge/industry-solutions/` 下创建新文件，遵循已有格式：

```markdown
# {行业名}

## 核心痛点
| 编号 | 痛点 | 说明 |
|------|------|------|

## 常见系统
| 系统 | 全称 | 核心功能 |
|------|------|---------|

## 核心模块 / 合规要求 / 技术偏好 / 典型架构 / 售前话术
```

## 故障排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 智能体没有触发 | 触发词不匹配 | 检查 `config/triggers.md`，添加触发词 |
| 知识库内容没加载 | 文件路径错误 | 检查 `skill.md` Knowledge 节的路径引用 |
| 技能降级运行 | 依赖未安装 | 检查 `config/dependencies.md`，确认依赖技能已安装 |
| 产出格式不对 | 模板过时 | 更新 `knowledge/` 下的模板文件 |
