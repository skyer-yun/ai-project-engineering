# 测试用例设计工作流

> 覆盖阶段：N11（测试用例设计）
> 对应角色：测试设计师

---

## 适用场景

当测试策略确定后，需要设计具体测试用例时使用。

- 模块级用例设计
- 接口测试用例设计
- 业务流程测试用例设计
- 回归测试用例基线建立

## 前置条件

```
必须：
  [x] 测试策略已确定（范围/方法/优先级）
  [x] PRD 中功能需求明确

建议：
  [ ] 接口文档已就绪（接口测试用例必需）
  [ ] 原型/Demo 已完成（UI 测试用例参考）
  [ ] 测试数据已准备
```

## 阶段

### Stage 1: 需求分析

- **输入**：PRD 文档 + 测试策略 + 接口文档（如有）
- **动作**：
  1. 按模块拆解功能点，形成功能点清单
  2. 识别每个功能点的测试对象（输入/输出/业务规则/状态流转）
  3. 确定每个功能点的优先级（与 PRD P0/P1/P2 对齐）
  4. 识别功能间依赖关系
  5. 标注适合的测试设计方法
- **输出**：功能点分析表
  ```
  | 功能点 | 优先级 | 测试对象 | 适用方法 | 依赖 |
  |--------|--------|---------|---------|------|
  | 用户登录 | P0 | 输入/状态 | 等价类+边界值+状态迁移 | 无 |
  | 密码重置 | P1 | 流程/输入 | 场景法+等价类 | 登录 |
  ```
- **技能调用**：无（纯分析阶段）

### Stage 2: 用例设计

- **输入**：功能点分析表 + 测试方法参考（`knowledge/test-methods/README.md`）
- **动作**：针对每个功能点，选择合适的设计方法生成用例

#### 6 种测试设计方法

**方法 1：等价类划分**

```
适用场景：输入域测试（表单/参数/配置）
产出：有效等价类 + 无效等价类
示例：
  输入：手机号
  有效等价类：11位数字、1开头、有效号段
  无效等价类：空值、非数字、长度不足、长度超长、无效号段
  用例数 = 有效等价类数 + 无效等价类数（每条用例覆盖一个无效等价类）
```

**方法 2：边界值分析**

```
适用场景：数值/日期/字符串长度等有明显边界的输入
产出：边界值 + 次边界值
示例：
  输入：密码长度 6-20
  边界值：5/6/7（下边界）/ 19/20/21（上边界）
  规则：边界-1 / 边界值 / 边界+1
```

**方法 3：场景法**

```
适用场景：业务流程测试（多步骤操作）
产出：正向场景 + 异常场景
示例：
  正向：正常登录 → 浏览商品 → 加入购物车 → 下单 → 支付
  异常：登录超时 / 库存不足 / 支付失败 / 网络中断
  规则：1个正向主流程 + N个异常分支
```

**方法 4：判定表**

```
适用场景：多条件组合逻辑（权限/折扣/规则引擎）
产出：条件组合矩阵
示例：
  条件：VIP用户(y/n) + 订单金额>100(y/n) + 首次购买(y/n)
  组合：2^3 = 8种，精简后可能有 5-6 种有效组合
  规则：列出所有条件组合 → 标注每种组合的预期结果
```

**方法 5：正交实验**

```
适用场景：多因素多水平（配置组合/兼容性矩阵）
产出：正交表选出的最少组合
示例：
  因素：浏览器(3) x 操作系统(3) x 分辨率(3)
  全组合：27种 → 正交表 L9(3^4)：9种
  规则：使用正交表选择代表性组合
```

**方法 6：状态迁移**

```
适用场景：状态流转业务（订单/审批/工单）
产出：状态转换矩阵
示例：
  订单状态：待支付→已支付→发货中→已完成
  非法转换：待支付→发货中（不允许）
  规则：列出所有状态 + 所有触发事件 → 标注合法/非法转换
```

- **输出**：测试用例集
  ```
  用例格式：
  | 用例ID | 模块 | 功能点 | 优先级 | 设计方法 | 前置条件 | 测试步骤 | 预期结果 | 关联需求 |
  |--------|------|--------|--------|---------|---------|---------|---------|---------|
  | TC-001 | 登录 | 手机号验证 | P0 | 等价类 | 登录页已打开 | 输入11位有效手机号 | 通过验证 | REQ-001 |
  ```
- **技能调用**：`test-case-generator`（如已安装）或人工按方法设计

### Stage 3: 输出归档

- **输入**：测试用例集
- **动作**：
  1. 用例评审（检查覆盖率和质量）
  2. 覆盖率分析（功能点覆盖率/需求覆盖率）
  3. 用例编号规范化（TC-{模块}-{序号}）
  4. 基线化（版本标记）
  5. 归档输出
- **输出**：
  - 测试用例文档（Markdown/Excel）
  - 覆盖率矩阵
  - 评审记录
- **技能调用**：`xlsx`（如已安装，输出 Excel 格式）或 Markdown

## 质量检查标准

```
用例评审需确认：
  [ ] P0 功能覆盖率 100%（每条需求至少 1 条用例）
  [ ] P1 功能覆盖率 >= 95%
  [ ] 有效等价类 + 无效等价类均覆盖
  [ ] 边界值必测项全部包含
  [ ] 业务流程正向 + 异常场景覆盖
  [ ] 状态流转合法 + 非法转换均覆盖
  [ ] 每条用例可追溯到需求点
  [ ] 预期结果明确可验证
```

## 降级策略

| 缺失资源 | 降级行为 |
|----------|----------|
| test-case-generator 未安装 | 人工按 6 种方法逐项设计 |
| 接口文档缺失 | 基于功能描述设计，补充"待接口文档确认"标注 |
| xlsx 未安装 | 输出 Markdown 表格 |
| PRD Part 7 不完整 | 基于已有信息 + 与用户确认补充 |

## 设计方法选择决策树

```
开始
  ↓
是否涉及状态流转？
  → 是 → 状态迁移法
  → 否 ↓
是否涉及多条件组合？
  → 是 → 判定表
  → 否 ↓
是否涉及多因素多水平？
  → 是 → 正交实验
  → 否 ↓
是否涉及业务流程？
  → 是 → 场景法
  → 否 ↓
是否有明显输入域？
  → 是 → 等价类划分 + 边界值分析
  → 否 → 探索性测试
```
