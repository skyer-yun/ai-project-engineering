## 2. 测试用例模板

### 2.1 用例表头

```markdown
| 用例ID | 模块 | 功能点 | 优先级 | 设计方法 | 前置条件 | 测试步骤 | 预期结果 | 关联需求 |
|--------|------|--------|--------|---------|---------|---------|---------|---------|
| TC-{模块}-{序号} | {模块名} | {功能点} | P0/P1/P2/P3 | {方法} | {条件} | {步骤} | {结果} | REQ-{N} |
```

### 2.2 详细用例格式

```markdown
## TC-{模块}-{序号}: {用例标题}

### 基本信息
- 优先级：P0/P1/P2/P3
- 设计方法：等价类划分/边界值分析/场景法/判定表/正交实验/状态迁移
- 关联需求：REQ-{N}
- 前置条件：{环境/数据/状态}

### 测试步骤
| 步骤 | 操作 | 输入数据 | 预期结果 |
|------|------|---------|---------|
| 1 | {操作描述} | {输入数据} | {预期} |
| 2 | {操作描述} | {输入数据} | {预期} |

### 测试数据
| 数据项 | 值 | 说明 |
|--------|-----|------|
| {字段} | {值} | {说明} |

### 预期结果
{详细描述}

### 备注
{补充说明}
```

### 2.3 用例编号规范

```
格式：TC-{模块缩写}-{三位序号}

模块缩写示例：
  AUTH - 认证模块
  USER - 用户管理
  ORDER - 订单模块
  PAY - 支付模块
  ADMIN - 管理后台
  API - 接口测试
  PERF - 性能测试
  SEC - 安全测试

示例：
  TC-AUTH-001：正常手机号登录
  TC-AUTH-002：无效手机号登录
  TC-ORDER-015：订单状态流转-待支付到已取消
```

```markdown

### 基本信息
| 项目 | 内容 |
|------|------|
| 报告人 | {姓名} |
| 报告时间 | {日期} |
| 模块 | {所属模块} |
| 级别 | P0/P1/P2/P3 |
| 状态 | New/Confirmed/In Progress/Fixed/Verifying/Closed |
| 指派 | {开发人员} |

### 环境信息
| 项目 | 内容 |
|------|------|
| 浏览器 | {类型+版本} |
| 操作系统 | {类型+版本} |

### 复现步骤

### 实际结果
{观察到的错误行为}

- 日志：{内容或链接}

### 关联信息
- 关联用例：TC-{模块}-{序号}
- 关联需求：REQ-{N}
- 关联缺陷：BUG-{模块}-{序号}（如有）
```

### 4.2 缺陷分级速查

```
P0 致命（立即响应，24h内修复）：
  - 系统崩溃/死机/无响应
  - 数据丢失/损坏
  - 安全漏洞（可被利用）
  - 核心数据泄露
  - 资金计算错误

P1 严重（4h内响应，48h内修复）：
  - 核心功能不可用
  - 性能严重下降（>5x 基线）
  - 数据计算/显示错误
  - 流程阻断（无法继续操作）
  - 第三方集成失败

P2 一般（24h内响应，本迭代内修复）：
  - 非核心功能异常
  - 体验问题（操作繁琐/提示不清）
  - 显示错位/样式问题
  - 搜索结果不精准
  - 非关键数据不一致

P3 轻微（下版本修复）：
  - UI 瑕疵（间距/颜色/字体）
  - 文案错误/错别字
  - 优化建议
  - 不影响使用的体验问题
```
