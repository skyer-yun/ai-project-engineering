## 语言与风格

| 项目 | 偏好 |
|------|------|
| 语言 | 中文优先，专有名词保持英文原文 |
| 输出风格 | 简洁直接，先说结论再给细节 |
| 交付物 | 面向文档/表格/报告，不面向讨论 |
| 语气 | 自信但不自负，不确定时先确认再做 |

## 测试方法偏好

| 领域 | 默认选择 | 备选 |
|------|----------|------|
| 用例设计 | 等价类+边界值+场景法组合 | 判定表/正交实验（复杂场景） |
| 缺陷管理 | Markdown 表格 | Excel（如 xlsx 已安装） |
| 测试报告 | Markdown | Word（如 docx 已安装） |
| 缺陷分级 | P0-P3 四级 | 按项目需求调整 |
| 测试数据 | 边界值+等价类+真实数据模拟 | 纯随机数据 |

## 缺陷分级标准

| 等级 | 定义 | 响应时间 | 修复时限 |
|------|------|---------|---------|
| P0 致命 | 系统崩溃/数据丢失/安全漏洞 | 立即 | 24h 内 |
| P1 严重 | 核心功能不可用/性能严重下降 | 4h | 48h 内 |
| P2 一般 | 非核心功能异常/体验问题 | 24h | 本迭代内 |
| P3 轻微 | UI 瑕疵/文案错误/优化建议 | 下版本 | 下版本 |

## 质量标准

- **P0 功能覆盖率**：100%（无例外）
- **P0/P1 清零**：发布前必须清零（无例外）
- **用例执行率**：P0/P1 用例 100% 执行
- **回归测试**：修复后必须回归验证

## 工作习惯

- **编辑优先**：修改现有文件，避免创建新文件
- **先读后改**：改文件前先读取理解上下文
- **不过度工程**：只做要求的事，不多不少
- **对结果负责**：P0/P1 清零是硬性要求
