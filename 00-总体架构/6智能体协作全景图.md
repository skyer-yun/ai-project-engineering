## 回溯链路

需求变更和问题反馈的反向流转路径：

```
交付阶段 ──反馈──▶ 测试阶段 ──缺陷──▶ 开发阶段 ──影响──▶ 产品阶段 ──变更──▶ 售前阶段
   N14               N11               N8              N5              N2
```

- **缺陷回溯**：delivery → testing → dev，走缺陷修复流程
- **需求变更**：任意阶段 → product，走变更评审流程
- **方案调整**：product → pre-sales，重新评估技术可行性和商务影响
- **project-copilot 全程跟踪**：记录回溯原因、影响范围、时间损耗

## 6 智能体职责边界

### pre-sales-copilot（售前智能体）

- **核心职责**：需求收集与分析、技术方案编写、投标文件、客户演示
- **输入边界**：客户原始需求、招标文件、行业背景
- **输出边界**：需求分析报告、技术方案、投标文件、演示材料
- **不负责**：PRD 编写、代码开发、测试用例

### product-copilot（产品智能体）

- **核心职责**：需求深度分析、PRD 编写、原型设计、验收标准定义
- **输入边界**：需求分析报告、竞品分析、业务目标
- **输出边界**：PRD（12 部分）、原型 Demo、数据字典、验收标准
- **不负责**：技术方案编写、代码实现、部署运维

### dev-copilot（开发智能体）

- **核心职责**：架构设计、详细设计、编码实现、代码审查、联调
- **输入边界**：PRD、原型 Demo、接口规范、技术约束
- **输出边界**：源代码、技术设计文档、API 文档、单元测试
- **不负责**：需求分析、测试用例编写、客户交付

### testing-copilot（测试智能体）

- **核心职责**：测试策略、用例设计、测试执行、缺陷管理、自动化测试
- **输入边界**：PRD、技术设计文档、源代码、验收标准
- **输出边界**：测试用例、测试报告、缺陷清单、自动化脚本
- **不负责**：需求定义、代码编写、生产部署

### delivery-copilot（交付智能体）

- **核心职责**：部署方案、环境搭建、客户验收、用户培训、运维文档
- **输入边界**：测试报告、源代码、部署要求、客户环境信息
- **输出边界**：部署文档、验收报告、培训材料、运维手册
- **不负责**：功能开发、测试执行、需求变更评审

### project-copilot（项目管理智能体）

- **核心职责**：项目计划、进度跟踪、风险管理、资源协调、汇报材料
- **输入边界**：项目目标、资源约束、各阶段产物
- **输出边界**：WBS、甘特图、风险登记册、项目周报/月报
- **不负责**：具体技术实现、单点需求分析、代码编写

## 协作场景

### 场景 1：完整交付流程

```
客户需求 → [pre-sales] 需求分析
                    ↓
         [product] PRD + 原型
                    ↓
         [dev] 设计 + 编码 + 联调
                    ↓
         [testing] 测试 + 回归
                    ↓
         [delivery] 部署 + 验收 + 培训

[project] 全程：计划 → 跟踪 → 汇报 → 收尾
```

### 场景 2：需求变更

```
变更请求 → [product] 影响分析（范围/进度/成本）
                    ↓
         [pre-sales] 商务影响评估（可选）
                    ↓
         [project] 变更评审 → 更新计划
                    ↓
         [dev] 影响模块重新设计
                    ↓
         [testing] 回归测试
                    ↓
         [delivery] 更新部署/文档

全过程记录变更日志，维护需求追溯矩阵
```

### 场景 3：售前快速响应

```
客户紧急需求 → [pre-sales] 快速方案
                        ↓
             [product] 轻量 PRD（可选）
                        ↓
             [project] 快速排期评估

目标：2 小时内完成初步响应，24 小时内输出正式方案
```
