## 第二部分：模块概述

停车业务模块负责处理停车场相关的所有业务，包括停车场查询、车辆入场登记、实时计费、费用支付、出场确认等功能。

## 第三部分：类与接口设计

### 3.1 核心类图

- **ParkingController** - 接收HTTP请求，参数校验，调用Service，返回响应
  - queryLots()：停车场列表查询
  - getLotDetail()：停车场详情
  - createOrder()：创建停车订单
  - calculateFee()：计算停车费用
  - payOrder()：支付停车订单
  - handleExit()：处理车辆出场
  - queryOrders()：查询停车订单

- **ParkingService** - 核心业务逻辑
  - parkingLotRepository：停车场仓储
  - parkingOrderRepository：订单仓储
  - feeCalculator：费用计算器
  - parkingAdapter：厂家适配器
  - queryNearbyLots()：查询附近停车场
  - createParkingOrder()：创建停车订单
  - calculateFee()：计算费用
  - processPayment()：处理支付
  - notifyExit()：通知出场

- **FeeCalculator** - 停车费用计算，支持多时段、会员折扣
  - calcBaseFee()
  - calcDiscount()
  - calcMemberFee()
  - calcTotalFee()

- **ParkingAdapter** - 停车厂家系统适配
  - syncLotInfo()
  - notifyEntry()
  - notifyExit()
  - queryFee()
  - sendPayResult()

- **PaymentClient** - 支付服务客户端
  - createPayment()
  - queryPayment()
  - refund()

## 第四部分：接口定义

### 4.1 C端接口

**查询停车场列表** - GET /api/v1/parking/lots

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| longitude | decimal(10,6) | 是 | 用户经度 |
| latitude | decimal(10,6) | 是 | 用户纬度 |
| radius | int | 否 | 搜索半径(米)，默认3000 |
| keyword | string | 否 | 搜索关键词 |
| pageNum | int | 否 | 页码，默认1 |
| pageSize | int | 否 | 每页条数，默认10 |

**创建停车订单** - POST /api/v1/parking/orders

**计算停车费用** - GET /api/v1/parking/orders/{orderId}/fee

**支付停车订单** - POST /api/v1/parking/orders/{orderId}/pay

### 4.2 第三方回调接口

**车辆入场通知** - POST /third/parking/entry

**车辆出场通知** - POST /third/parking/exit

## 第六部分：业务流程设计

### 6.1 停车业务主流程

```
[用户打开停车模块] → [查询附近停车场] → [选择停车场]
→ [车辆入场(厂家推送)] → [停车中(实时计费)] → [车辆出场(厂家推送)]
→ [用户发起支付] → [支付成功] → [通知厂家系统] → [用户驾车出场] → [订单完成]
```

### 6.2 订单状态流转

```
                    ┌─────────────┐
                    │   创建订单   │
                    └─────────────┘
                          │
                          ▼
          ┌────────│  停车中(1)  │────────┐
          │        └─────────────┘        │
          │              │               │
          │              │ 出场          │ 异常取消
          │              ▼               │
          │        ┌─────────────┐        │
          │        │  待支付     │        │
          │        └─────────────┘        │
          │              │               │
          │              │ 支付成功      │
          │              ▼               ▼
          │        ┌─────────────┐  ┌─────────────┐
          │        │  已支付     │  │  已取消(3)  │
          │        └─────────────┘  └─────────────┘
          │              │
          │              │ 抬杆出场
          │              ▼
          │        ┌─────────────┐
          └───────→│  已完成(2)  │
                   └─────────────┘
```

## 第七部分：第三方对接设计

### 7.1 对接接口清单

| 接口 | 方向 | 用途 | 调用时机 |
|------|------|------|---------|
| /third/parking/lot/sync | 厂家→平台 | 停车场信息同步 | 每1小时 |
| /third/parking/space/sync | 厂家→平台 | 车位数据同步 | 每30秒 |
| /third/parking/entry | 厂家→平台 | 车辆入场通知 | 实时 |
| /third/parking/exit | 厂家→平台 | 车辆出场通知 | 实时 |
| /third/parking/fee/query | 平台→厂家 | 费用查询 | 支付前 |
| /third/parking/pay/callback | 平台→厂家 | 支付结果通知 | 支付成功后 |
| /third/parking/barrier/open | 平台→厂家 | 抬杆指令 | 支付成功后 |

### 7.2 签名机制

签名算法：MD5(所有参数按key排序拼接 + timestamp + secretKey)

### 7.3 异常处理

| 异常场景 | 处理策略 | 重试机制 |
|---------|---------|---------|
| 厂家系统超时 | 返回降级数据或错误提示 | 重试3次，间隔5秒 |
| 厂家系统不可用 | 记录日志，降级为离线模式 | 定时重试 |
| 签名校验失败 | 拒绝请求，记录异常IP | 不重试 |

## 第八部分：缓存设计

| 数据 | Key格式 | 类型 | TTL | 更新策略 |
|------|---------|------|-----|---------|
| 停车场信息 | parking:lot:{lotId} | Hash | 1小时 | 定时同步 |
| 空余车位 | parking:space:{lotId} | String | 30秒 | 实时同步 |
| 用户车辆 | parking:vehicle:{userId} | List | 1天 | 变更更新 |
| 停车订单 | parking:order:{orderNo} | Hash | 1小时 | 变更更新 |
| 停车中订单 | parking:active:{plateNo}:{lotId} | String | 无 | 入场创建/出场删除 |

## 第九部分：性能设计

| 指标 | 要求 | 实现方案 |
|------|------|---------|
| 停车场列表查询 | <500ms | Redis缓存 + 地理索引 |
| 费用计算 | <100ms | 内存计算 + 规则缓存 |
| 支付接口 | <2s | 异步化 + 并行调用 |
| 入场通知处理 | <1s | MQ异步处理 |
