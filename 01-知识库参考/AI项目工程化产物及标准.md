## 二、N1-N16 节点定义

### N1：需求收集

| 要素 | 内容 |
|------|------|
| 输入 | 客户原始需求、招标文件、会议纪要 |
| 人工处理 | 客户沟通、需求初步澄清 |
| AI 处理 | 需求整理、分类、关键字提取 |
| 输出 | 结构化需求记录 |
| AI 参与度 | L2（辅助整理） |
| 质量门禁 | 需求条目化、无遗漏核心诉求 |
| 交接标准 | 需求记录可传递给 N2 分析 |

### N2：需求分析

| 要素 | 内容 |
|------|------|
| 输入 | 结构化需求记录 |
| 人工处理 | 需求优先级排序、可行性判断 |
| AI 处理 | 需求分解、依赖分析、冲突检测、竞品对比（可选） |
| 输出 | 需求分析报告 |
| AI 参与度 | L3（深度参与） |
| 质量门禁 | 需求无二义性、业务目标可量化、干系人已确认 |
| 交接标准 | 需求分析报告可作为方案输入 |

### N3：方案编写

| 要素 | 内容 |
|------|------|
| 输入 | 需求分析报告 |

| 输出 | 技术方案 / 解决方案 / 投标文件 |
| AI 参与度 | L4（主导生成） |
| 质量门禁 | 方案结构完整、技术可行、风险已识别 |
| 交接标准 | 方案通过评审 |

## 三、各阶段产物标准表

| 阶段 | 核心产物 | 格式 | 必含章节 |
|------|----------|------|----------|
| N1-N2 | 需求分析报告 | .docx / .md | 背景目标/需求清单/优先级/约束/干系人 |
| N3 | 技术方案 | .docx | 11 章（见方案模板） |
| N3-N4 | PRD | .md | 12 部分（见 PRD 模板） |
| N5 | 架构设计文档 | .md | 架构图/技术选型/部署方案/安全方案 |
| N6-N7 | 详细设计文档 | .md | 接口定义/数据模型/时序图/状态图 |
| N8 | 测试用例 | .xlsx / .md | 用例编号/模块/优先级/步骤/预期结果 |
| N10-N11 | 测试报告 | .docx | 测试概况/执行结果/缺陷统计/结论 |
| N12-N13 | 部署文档 | .md | 环境/步骤/验证/回滚 |
| N14 | 验收报告 | .docx | 验收标准/测试结果/签字确认 |
| N15 | 运维手册 | .md | 日常运维/故障处理/监控告警 |

## 四、产物质量标准

### PRD 质量标准

- 12 部分完整无遗漏
- 每个功能点有验收标准
- 状态流转定义完整
- 异常处理已覆盖
- 数据流向清晰

### 技术方案质量标准

- 11 章结构完整
- 架构图至少含：系统架构图、部署架构图
- 技术选型有对比分析
- 非功能需求有量化指标
- 风险识别与应对措施

### 测试报告质量标准

- 用例执行率 100%
- 通过率 >= 95%
- 缺陷按严重程度分类统计
- 无 P0/P1 遗留
- 性能指标达标（如有）

### 交付文档质量标准

- 部署步骤可复现
- 运维手册覆盖日常操作 + 故障处理
- 培训材料面向目标用户角色
- 验收报告含客户签字

