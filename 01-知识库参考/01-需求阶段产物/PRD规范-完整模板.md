## 第二部分：产品概述

### 2.1 项目背景

蒲阳社区配套停车场、充电站、加油站、食堂、酒店、温泉、药店、电影院、商城等10大业态。目前各业态独立运营，用户需分别注册、支付，体验割裂数据不通。

### 2.2 产品定位

覆盖社区生活10大业态的一站式服务平台，提供统一账号、统一支付、统一会员的便捷服务。

### 2.3 业务目标

| 目标 | 指标 |
|------|------|
| 用户规模 | 6个月达到5万注册用户 |
| 交易规模 | 月均交易额100万元 |
| 业态覆盖 | 10大业态全部接入 |

## 第六部分：主业务流程

### 6.1 用户消费主流程

```
用户打开小程序 → 登录 → 进入首页/业态页
    → 选择业态(停车/充电/加油/食堂)
        → 查询→下单→创建订单
            → 选择支付方式(微信/余额/混合)
                → 支付成功
                    → 发放积分、更新会员、推送通知
                        → 订单完成
```

### 6.2 支付中心流程

```
发起支付 → 计算支付金额(订单金额-优惠券-会员折扣)
    → 选择支付方式
        ├── 余额支付 → 查询余额 → 扣减 → 记录流水
        ├── 微信支付 → 调用JSAPI → 等待回调
        └── 混合支付 → 先扣余额 → 后走微信
    → 支付成功回调
        → 更新订单 → 发放积分 → 推送通知 → 通知第三方
```

#### 7.1.4 功能点详细说明

**PK-F001 停车场查询与列表展示**

功能描述：用户打开停车模块，基于当前定位展示附近停车场列表。

输入/输出：

| 方向 | 数据项 | 类型 | 来源/去向 | 说明 |
|------|--------|------|----------|------|
| 输入 | 用户经纬度 | decimal(10,6) | 地图SDK定位 | 前端获取 |
| 输入 | 搜索半径 | int | 前端默认3000米 | 可选 |
| 输出 | 停车场列表 | array | API响应 | 含以下字段 |
| 输出 | 停车场ID | string | 后端生成 | 后续关联标识 |
| 输出 | 停车场名称 | string | 后台配置 | 如「蒲阳广场停车场」 |
| 输出 | 距离 | int | 后端计算 | 单位：米 |
| 输出 | 总车位/空余车位 | int | 停车厂家同步 | 实时数据 |
| 输出 | 收费规则摘要 | string | 后台配置 | 如「首小时免费」 |

数据流向：

```
[地图SDK] → 前端获取经纬度 → 请求API
    → 后端查询Redis(停车场信息)
    → 后端查询Redis(实时车位, 30秒TTL)
    → 后端计算距离
    → 返回排序后的列表 → 前端渲染
```

业务规则：

| 编号 | 规则描述 |
|------|---------|
| BR-001 | 默认搜索半径3000米，无结果扩大到5000米 |
| BR-002 | 按距离由近到远排序 |
| BR-003 | 空余车位为0时显示「已满」灰色状态 |
| BR-004 | 停车场状态为「停用」时不展示 |
| BR-005 | 车位数据缓存30秒 |

UI/交互说明：
- 卡片式布局，展示：名称、距离、空余/总车位、收费摘要
- 空余车位颜色：>20绿色、5~20橙色、<5红色、0灰色
- 下拉刷新更新车位数据

**PK-F005 车辆入场登记**

功能描述：车辆进入停车场时，停车厂家系统推送入场信息，平台创建停车订单。

数据流向：

```
[停车厂家] → HTTP推送入场通知
    → API网关 → 鉴权(IP白名单)
        → 停车适配器:
            1. 校验停车场编码
            2. 根据车牌查t_user_vehicle匹配用户
            3. 创建停车订单
            4. 推送微信模板消息
            5. 返回成功响应
```

异常场景处理：

| 异常场景 | 处理方式 | 用户感知 |
|---------|---------|---------|
| 厂家重复推送 | 幂等校验去重 | 无影响 |
| 车牌识别不清 | 厂家标记「无牌车辆」 | 用户手动输入车牌 |
| 平台服务不可用 | 厂家重试后记录离线日志 | 无法在线看入场信息 |
| 用户未绑定该车牌 | 仍创建订单 | 绑定后自动关联 |

**PK-F007 停车费用支付**

状态定义：

订单状态 t_order_parking.status：

| 值 | 状态名 | 含义 | 可流转到 |
|----|--------|------|---------|
| 1 | 停车中 | 车辆在场内 | 2、3 |
| 2 | 已完成 | 已支付并已出场 | - (终态) |
| 3 | 已取消 | 异常取消 | - (终态) |

支付状态 t_order_parking.pay_status：

| 值 | 状态名 | 含义 | 可流转到 |
|----|--------|------|---------|
| 0 | 未支付 | 未发起支付 | 1、2 |
| 1 | 已支付 | 支付成功 | 3 |
| 2 | 支付中 | 等待结果 | 1、4 |
| 3 | 已退款 | 退款完成 | - (终态) |
| 4 | 支付失败 | 支付失败 | 0 |

业务规则：

| 编号 | 规则描述 |
|------|---------|
| BR-020 | 支付前必须重新获取最新费用 |
| BR-021 | 费用差异>10%弹窗提示确认 |
| BR-022 | 优惠券锁定15分钟，超时释放 |
| BR-023 | 余额不足提示充值或切微信 |
| BR-024 | 微信支付超时5分钟自动关闭 |
| BR-025 | 积分发放：每消费1元积1分，会员加倍 |
| BR-026 | 已支付30分钟未出场推送提醒 |
| BR-027 | 同一订单不可重复支付 |
