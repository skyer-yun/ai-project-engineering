## 四、命名规范

### 4.1 包命名规范

com.{公司}.{项目}.controller / service / mapper / entity / dto / vo / config / enums / constant

### 4.2 类命名规范

{模块}Controller / {模块}Service / {模块}ServiceImpl / {模块}Mapper / {操作}{模块}DTO / {模块}VO / {模块}{类型}Enum

### 4.3 方法命名规范

get/list/page/save/update/delete/count/exists + {Entity}By{条件}

### 4.4 数据库命名规范

表名：{模块}_{实体}，主键id，外键{关联表}_id，状态字段{名称}_status，索引idx_{表名}_{字段}

### 4.5 API接口命名规范

GET/POST/PUT/DELETE /api/v1/{模块}

## 五、编码规范

### 5.1 Java编码规范

包含：类注释规范、方法注释规范、Controller规范、Service规范、异常处理规范（BusinessException + GlobalExceptionHandler）

### 5.2 前端编码规范

包含：组件规范（Vue SFC）、API封装规范、请求封装规范

## 六、数据库规范

### 6.1 表设计规范

所有业务表必须包含基础字段：id(BIGINT雪花ID)、create_by、create_time、update_by、update_time、deleted(逻辑删除)、remark

### 6.2 索引设计规范

主键索引、唯一索引、普通索引、联合索引、覆盖索引

### 6.3 SQL编写规范

禁止SELECT *，使用索引字段关联，禁止在索引列上使用函数

## 七、接口规范

统一响应格式：code + message + data + traceId

错误码：SUCCESS / PARAM_ERROR / UNAUTHORIZED / FORBIDDEN / NOT_FOUND / SYSTEM_ERROR / BIZ_ERROR等

## 八、日志规范

DEBUG/INFO/WARN/ERROR四级使用规范，关键节点日志清单

## 九、Git规范

分支命名：feature/{模块}-{描述} / bugfix/{模块}-{描述} / release/{版本号} / hotfix/{版本号}-{描述}

提交信息：`<type>(<scope>): <subject>` 格式（feat/fix/docs/style/refactor/test/chore）
