## 一、校验原则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| 不信任，要验证 | 所有AI输出必须经过校验，不能默认信任 |
| 分层校验 | 根据AI参与度分级，校验严格度不同 |
| 自动化优先 | 能自动校验的不依赖人工 |
| 可追溯 | 校验结果有记录，问题可追溯 |
| 持续优化 | 根据校验结果优化Prompt和流程 |

### 1.2 校验层级（4层架构）

1. **第一层：格式校验** - 自动化、快速、无人工参与
2. **第二层：规范校验** - 半自动化、规则引擎+人工确认
3. **第三层：内容校验** - 人工为主、专业知识判断
4. **第四层：安全校验** - 自动化扫描+人工审核

## 二、校验标准

### 2.1 代码类输出校验

第一层（自动）：语法正确(javac)、格式规范(CheckStyle)、引用完整(Maven)

第二层（半自动）：命名规范(SonarQube)、注释完整、日志规范、异常处理

第三层（人工）：逻辑正确(代码走读)、边界条件(测试)、性能合理、可维护性

第四层（自动+人工）：SQL注入(SonarQube)、XSS防护、敏感数据、权限控制

### 2.2 文档类输出校验

第一层：Markdown语法、章节完整、表格格式

第二层：术语统一(术语表比对)、编号规范、引用完整

第三层：内容准确(交叉比对)、逻辑清晰、数据准确、场景完整

### 2.3 设计类/测试类输出校验

设计类：品牌符合、Design Tokens一致、组件完整、交互合理

测试类：用例覆盖、数据合理、脚本可执行、断言正确

## 三、校验流程

### 3.1 标准校验流程

AI产出 → 第一层格式校验 → 第二层规范校验 → 第三层内容校验 → 第四层安全校验 → 提交使用

### 3.2 快速通道（L1级低风险）

自动格式+规范校验 → 人工抽检(10%) → 提交使用

### 3.3 严格通道（L3级及以上）

全四层校验 → 专家评审 → 签字确认 → 提交使用

## 四、校验工具链

| 工具 | 校验类型 | 集成方式 |
|------|---------|---------|
| SonarQube | 代码质量/安全 | CI/CD集成 |
| CheckStyle | 代码规范 | CI/CD集成 |
| Jacoco | 覆盖率 | CI/CD集成 |
| OWASP ZAP | 安全扫描 | 定时任务 |
| JMeter | 性能测试 | 按需执行 |

CI/CD校验流水线：编译检查 → 单元测试 → 代码规范扫描 → 安全扫描 → 覆盖率检查

## 五、校验记录

校验记录模板：产出编号、类型、AI参与度、四层校验结果、最终结论、审核人

校验统计目标：格式通过率>90%、规范通过率>80%、内容通过率>70%、安全通过率100%、平均审核时间<30分钟

## 六、回滚机制

### 6.1 回滚触发条件

| 级别 | 触发条件 | 影响范围 |
|------|---------|---------|
| P0 紧急 | 生产环境数据错误或安全漏洞 | 全部AI产出 |
| P1 严重 | 核心功能逻辑错误 | 当前任务AI产出 |
| P2 一般 | 非核心功能问题 | 当前文件/模块 |
| P3 轻微 | 格式/注释问题 | 当前文件 |

### 6.2 回滚流程

P0：立即停止所有AI任务 → 人工接管 → 回滚所有变更 → 问题分析 → 修复验证 → 逐步恢复

P1：停止当前任务 → 回滚变更 → 问题分析 → Prompt优化 → 重新生成

P2/P3：标记问题 → 人工修正 → 记录原因 → 优化Prompt

## 七、质量门禁

| 阶段 | 质量门禁 | 通过标准 |
|------|---------|---------|
| 需求阶段 | PRD评审 | 12项检查点通过 |
| 设计阶段 | 设计评审 | 架构评审+详细设计审核通过 |
| 编码阶段 | 代码审查 | 8项审查清单+规范扫描通过 |
| 测试阶段 | 测试通过 | S1/S2缺陷100%关闭+覆盖率达标 |
| 上线阶段 | 上线审批 | 全部测试通过+部署冒烟通过 |

## 八、持续优化

Prompt优化：格式错误频繁→增加格式示例 / 规范违反→增加约束 / 内容缺失→增加必填项 / 逻辑错误→增加业务规则

校验规则优化：反复出现的问题→新增自动校验规则 / 耗时过长→优化流程 / 误报率高→调整阈值

问题分析：分类统计 + 趋势分析 + 根因分析 + 预防措施
